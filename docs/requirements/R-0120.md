# R-0120 — Clear a forest without repeating its reward

1. Status: new
2. Updated: 2026-10-17
3. Related: P07; PION-003/PION-006; UC-020 (Hra), UC-016 cancellation variant. See the [pioneer rules](../gap-analysis.md#equipment-and-pioneers), [accepted work rules](../gap-analysis.md#exploration-work-and-transport) and [use cases](../use-cases.md#vybaveni-a-upravy-krajiny).
4. Dependencies: [R-0118](R-0118.md) equipment boundary; existing colony warehouse and terrain ownership.
5. Primary area: [A05](areas.md#a05).
6. Related areas: A07 lumber storage and changed field yields; A04 progress persistence; A03 action/result feedback.
7. Origin: documented PION-003 gap in the [rule catalogue](../gap-analysis.md#equipment-and-pioneers).

## 1. Summary

1. A pioneer should be able to remove forest, opening later land use and giving the player a predictable, single lumber result.
2. The 2026-10-17 catalogue at `f10e3f49` records no clearing action or tree-removal operation. This is a documented source assessment, not a new runtime check.
3. Scope: one clear-forest order, its tool/lumber transaction and lasting terrain-output change. Later plowing uses [R-0119](R-0119.md); road work uses [R-0121](R-0121.md).

## 2. Behavior

1. An eligible pioneer with at least 20 tools and positive movement can start clearing a forested square; the available control and refusal reason reflect the live terrain and unit state.
2. Before work starts, the player sees and confirms the 20-lumber outcome: the nearest owned colony within two squares receives it (ties by colony ID), excess beyond capacity is reported and discarded, or no recipient means no stored lumber. Only after confirmation does the order spend current movement. Ordinary work completes after four later owner updates, hardy work after two; completion removes forest permanently, spends exactly 20 tools once and applies the confirmed lumber rule.
3. Declining or canceling this start confirmation leaves movement, tools, terrain and progress unchanged. An untooled unit, already clear square or stale/invalid order also changes nothing. Explicit cancel after work starts discards progress without tools, lumber or terrain change, and without refunding spent movement. Re-clearing cannot award lumber twice.
4. Save and Continue preserve unfinished progress and the cleared state; production after completion uses the accepted bare-terrain yields, with no forest timber/fur output. Any later plow follows its own rule.

## 3. Implementation steps

1. Model action and map state own validation, timing and the single completion transaction; colony warehouse rules own receipt/capacity. Persistence records progress and forest removal; UI reports completion and any discarded lumber.
2. Not prepared for development; refine affected terrain-output callers and fixtures after selection.
3. Proposed checks: model forest/clear and 19/20-tool boundaries, nearest-colony/tie/capacity/no-recipient cases, ordinary/hardy timing, cancellation and save/Continue; add a named UC-020 `TC_...` player scenario at refinement.
4. Current result: captured only; gameplay has not changed.

## 4. Open questions

1. If the confirmed recipient colony disappears, changes owner or loses free storage before clearing completes, should completion request a new confirmation or use a defined fallback? Blocking before development: the accepted amount, nearest-colony rule and overflow policy stay fixed; the missing decision is how to handle a changed result after the multi-turn wait.
