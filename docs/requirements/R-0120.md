# R-0120 — Clear a forest without repeating its reward

1. Status: new
2. Updated: 2026-10-17
3. Related: P07; PION-003/PION-006; UC-020 (Hra), UC-016 cancellation variant. See the [pioneer rules](../gap-analysis.md#equipment-and-pioneers), [accepted work rules](../gap-analysis.md#exploration-work-and-transport) and [use cases](../use-cases.md#vybaveni-a-upravy-krajiny).
4. Dependencies: [R-0118](R-0118.md) equipment boundary; existing colony warehouse and terrain ownership.
5. Primary area: [A05](areas.md#a05).
6. Related areas: A07 lumber storage and changed field yields; A04 progress persistence; A03 action/result feedback.
7. Origin: documented PION-003 gap in the [rule catalogue](../gap-analysis.md#equipment-and-pioneers).

## 1. Summary

1. A pioneer should be able to remove forest, opening later land use and giving the player a predictable, single lumber result.
2. The 2026-10-17 catalogue at `f10e3f49` records no clearing action or tree-removal operation. This is a documented source assessment, not a new runtime check.
3. Scope: one clear-forest order, its tool/lumber transaction and lasting terrain-output change. Later plowing uses [R-0119](R-0119.md); road work uses [R-0121](R-0121.md).

## 2. Behavior

1. An eligible pioneer with at least 20 tools and positive movement can start clearing a forested square; the available control and refusal reason reflect the live terrain and unit state.
2. Before work starts, the player sees and confirms an expected 20-lumber result, not a guaranteed recipient. Only after confirmation does the order spend current movement. Ordinary work completes after four later owner updates, hardy work after two; completion removes forest permanently and spends exactly 20 tools once. Under the [2026-10-17 recipient decision](../gap-analysis.md#exploration-work-and-transport), completion chooses the nearest **current** owned colony within two squares (ties by colony ID), even if the previewed colony was lost or changed owner. It checks that colony's current warehouse capacity, stores what fits and discards any excess. With no eligible colony, it discards all 20 lumber. A capacity increase before completion can fit more; a later increase never restores discarded lumber. Completion does not pause for a second confirmation.
3. Declining or canceling this start confirmation leaves movement, tools, terrain and progress unchanged. An untooled unit, already clear square or stale/invalid order also changes nothing. Explicit cancel after work starts discards progress without tools, lumber or terrain change, and without refunding spent movement. Re-clearing cannot award lumber twice.
4. Save and Continue preserve unfinished progress and the cleared state; production after completion uses the accepted bare-terrain yields, with no forest timber/fur output. Any lumber discarded at completion, including all 20 when no colony qualifies, creates a notification for the next turn that persists across Continue without repeating disposal. Any later plow follows its own rule.

## 3. Implementation steps

1. Model action and map state own validation, timing and the single completion transaction. At completion, resolve the recipient from the current world and apply its current warehouse capacity, or discard all lumber if none qualifies; no saved recipient or second confirmation is needed. Persist progress, forest removal and the next-turn discarded-lumber notification so Continue cannot repeat disposal; UI presents the notification.
2. Not prepared for development; refine affected terrain-output callers and fixtures after selection.
3. Proposed checks: model forest/clear and 19/20-tool boundaries; previewed colony destroyed or changed owner, replacement by the nearest current owned colony with ID tie, and no eligible colony at completion; capacity shrinking or growing before completion, exact stored/discarded amounts and no restoration after later expansion; ordinary/hardy timing, cancellation and save/Continue with one next-turn discard notification and no duplicate disposal. Add a named UC-020 `TC_...` player scenario at refinement.
4. Current result: captured only; gameplay has not changed.
