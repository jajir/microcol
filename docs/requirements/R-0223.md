# R-0223 — Observe real players completing core game tasks

1. Status: new
2. Updated: 2026-10-20
3. Related: P28/P31; [player-observation method](../ux.md#overovani-s-hraci-a-zaznam-zjisteni), [test-plan estimate](../implementation-estimate.md#real-player-test-plan-and-completion-evidence).
4. Dependencies: representative playable paths [R-0217](done/R-0217.md)–[R-0220](R-0220.md), accessible controls [R-0222](R-0222.md), supported platform choices [R-0234](R-0234.md)/[R-0235](R-0235.md).
5. Primary area: [A03](areas.md#a03).
6. Related areas: A02 entry, A07 colony management, A08 diplomacy, A10 independence.
7. Origin: real-player evidence distinct from code inspection, automated UI tests and provisional UX hypotheses.

## 1. Summary

1. Observe whether new and experienced strategy players can find and complete selected core tasks and understand their outcomes.
2. This is a bounded study and finding-disposition outcome, not a claim that the current game is already usable or a mandate for an unspecified redesign.

## 2. Behavior

1. Before recruitment, choose tasks spanning first colony, production/trade, recovery from an unavailable action, a midgame choice and later independence; agree participant experience, supported platform/display coverage and a task success threshold. Include the [UX-001–005 hypotheses](../ux.md#pocatecni-seznam-k-overeni) as questions, not presumed failures.
2. For each session, record version, conditions, unprompted path, assistance, outcome and the player's explanation of what happened. Triage actual findings by severity, owner and reproduction; recheck important fixes. Keep code-known, app-tested and player-observed evidence visibly distinct.
3. Completion requires the agreed sample/tasks to have observations and every accepted finding a disposition. A small sample cannot establish universal accessibility or fun; further long-campaign balance evidence belongs to R-0230.

4. Consume the accepted 2026-10-20 rules from [R-0130](../gap-analysis.md#r-0130-refinement), [R-0155](../gap-analysis.md#r-0155-refinement); preserve this requirement’s own outcome and existing delivered behavior. These decisions do not establish this consumer’s implementation or acceptance.

## 3. Implementation steps

1. Prepare consent/session scripts and evidence format from the [UX method](../ux.md); run and analyze sessions, then link feature changes to their owners and repeat affected tasks. Do not count automation as a participant.
2. Current result: captured study only; no recruited-player outcome is claimed.
3. Align the existing checks and shared model/AI/UI integration with the linked 2026-10-20 decisions; retain unresolved questions only with their rule owners and run UI regression in CI under the current user instruction.

## 4. Open questions

1. What participant count, experience mix, accessibility/device coverage and success threshold will be accepted for this release round? The estimate gives scenarios, not an approved sample.
