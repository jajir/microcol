# R-0273 — Hand-drawn top-toolbar icons and colony selector

1. Status: new
2. Updated: 2026-10-25
3. Related: [graphics brief](../graphics.md#soucasne-zadani-vzhledu), [UX guidelines](../ux.md), [R-0270](done/R-0270.md).
4. Dependencies: existing game-wide toolbar actions, colony selection and bottom status messages; this requirement does not change their game rules.
5. Primary area: [A03 — screens and shared UI language](areas.md#a03).
6. Related areas: [A04](areas.md#a04) supplies the season for the proposed accent; [A10](areas.md#a10) retains Congress, independence and retirement availability and effects.
7. Origin: user request and attached game screenshot, 2026-10-25; ten downloadable visual alternatives requested before implementation.

## 1. Summary

1. Make the top toolbar feel like the same hand-drawn game as the map, while making every action understandable from its icon and permanent text label.
2. The supplied screenshot mixes icon-only controls, text-only Congress/Retire buttons and a platform-styled colony selector. It is a visual reference, not evidence of a newly verified game build.
3. Capture one coherent toolbar family and a visibly clickable styled colony dropdown. Ten [concept sheets](../graphics-top-menu-proposals.md) are available for selection; production artwork and gameplay implementation are not authorized by this design-only request.

## 2. Behavior

1. Every available toolbar action has one recognizable hand-drawn symbol and a permanent localized name. Existing action availability and meaning remain authoritative; leaving the game and ending it with a score remain separate actions.
2. Hovering a button or focusing it with the keyboard shows its explanation in the existing bottom status bar. Leaving the control restores the appropriate status message. The icon and short label remain visible without hover.
3. All icons share a fixed dark ink and one replaceable accent. The concept proposal uses olive green for summer and cool blue for winter, on the existing cream background. Production art must use the same geometry across seasons and two explicit color roles; the PNG concepts are not exact color masks or final font/size specifications.
4. The colony selector has an enclosed hand-drawn field, a colony symbol, a readable label and a separate chevron. Opening it shows named colonies and a non-color selection marker. Escape or clicking outside closes it without choosing a colony; an empty list clearly explains that no colony is available. Exact selected-label behavior will be refined with the chosen variant.
5. The existing Playpen Sans 14 regular typography and [visual brief](../graphics.md#soucasne-zadani-vzhledu) apply to implementation. A proposal sheet's enlarged headings, raster text or detail illustrations do not introduce a typography exception.

## 3. Implementation steps

1. Select one of the ten visual families, then refine its production dimensions, complete states and colony-label behavior. This requirement remains `new`; the visual exploration does not mark it ready for development.
2. Reuse the GUI owners `ButtonsGamePanel`, `ColoniesMenu`, shared button/status-message support and `gui.image`, following the [package map](../architecture.md). Preserve existing model operations and localization. No model-to-GUI dependency or save-format change is needed.
3. Redraw the selected art as editable SVG with fixed ink and replaceable accent, then follow the existing raster export/runtime pipeline. Do not use a complete concept-sheet PNG as a runtime button asset.
4. Before implementation acceptance, map the affected toolbar/colony journeys to named `TC_...` scenarios under the [functional contract](../functional-tests.md), including hover/focus, keyboard selection/cancel, empty colonies, localization and seasonal changes. Required model/JUnit and Docker/Xvfb smoke gates remain mandatory for that future implementation.
5. Current result: ten raster visual alternatives and their generation prompts prepared on 2026-10-25. This documentation-only scope is checked by documentation consistency tests and the strict MkDocs build. It does not verify runtime behavior, small-size legibility or publication.

## 4. Open questions

1. Which visual family should be selected for implementation? Blocking: yes for implementation, no for delivery of the ten concepts. The [catalogue](../graphics-top-menu-proposals.md) compares the alternatives; summer green and winter blue are the working interpretation used for the previews.
