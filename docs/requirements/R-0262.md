# R-0262 — Make the main game screen a clear hand-drawn interface with a taller bottom panel

1. Status: new
2. Updated: 2026-10-24
3. Related: P27/P28/P29; SUPPORT-002/003/004; UC-114/115 (Hra); [shared UX rules](../ux.md#spolecna-pravidla-pro-dalsi-zmeny) and [main-screen visual target](../graphics.md#hlavni-herni-obrazovka-a-spodni-panel).
4. Dependencies: [visual contract R-0260](done/R-0260.md), existing main-screen navigation and shared controls, and the specific map-grid treatment [R-0261](R-0261.md). Reuse current artwork; selected asset corrections remain with [R-0224](R-0224.md), without requiring its entire audit first.
5. Primary area: [A03](areas.md#a03), main game screen and shared visual language.
6. Related areas: A01 navigation, A05 map and unit actions, A04 date/turn display and A07 displayed economic information retain their existing behavior and model ownership.
7. Origin: user request on 2026-10-24 for the main game screen to actually resemble the supplied hand-drawn designs, make its active regions recognizable, and enlarge the bottom panel.

## 1. Summary

1. A player looking at the main map should see one coherent hand-drawn screen and immediately recognize where actions are available, what is selected and where information is shown.
2. Source inspection at `df0cd0a4` on 2026-10-24 finds an existing command area, map, right-hand information panel and bottom status bar containing contextual description, treasury and date. The shared visual contract is documented, but that alone is not acceptance of the screen's overall appearance.
3. This requirement owns the integrated appearance and layout of the main gameplay screen, including a visibly taller bottom panel. It does not redesign the separate main menu, colony or Europe screens, add commands or change their rules. The reference images guide the result; existing navigation and information remain functional.

## 2. Behavior

1. Opening or returning to the main gameplay screen shows a consistent ballpoint-on-paper appearance across the command area, map frame, side information and bottom panel. Use the agreed palette, approximately uniform pen stroke, flat fills without internal effects and default Playpen Sans Regular 14. Existing skins or fonts are not automatic exceptions to the agreed target.
2. Interactive controls are recognizable before hovering: shape, framing, icon or label makes the action area apparent. Hover, pressed state, keyboard focus, selection and disabled state remain distinct and consistent; color alone is insufficient. Actual pointer hit areas match visible controls. Informational regions are clearly grouped without falsely suggesting that every label is a button.
3. The bottom status panel is visibly taller than the current screen at the same window size and scale. Retain readable contextual information, treasury and date, with generous vertical padding and clear grouping/separators. Increase usable panel space rather than changing the default font size or weight. Longer descriptions and Czech/English text do not overlap, clip the other fields or hide controls.
4. Resizing the window and using the smallest supported layout retain an accessible command area, usable map, right panel and bottom panel without overlap. The taller panel participates in layout: no map squares or controls are concealed beneath it. Map selection and input coordinates still correspond to what the player sees.
5. Existing commands, shortcuts, tooltips, selection, scrolling, screen navigation and return/cancel paths keep their behavior. Current action availability remains accurate, unavailable actions retain explanations, and viewing or resizing the screen changes no game state. The explored-only dashed grid and solid unknown-area fill follow R-0261 without inventing another visibility policy.
6. Acceptance compares representative main-screen states against both supplied references and the written rules at actual display size. The examples guide composition and hand-drawn character; do not add a command or claim a gameplay feature merely because it appears in a mockup.
