# R-0142 — Edit or cancel a route without stranding carriers

1. Status: new
2. Updated: 2026-10-17
3. Related: P16/P06; ROUTE-004 and route-specific MOVE-008 cancellation; UC-030/016 (Hra). See the [route rule](../gap-analysis.md#automated-trade-routes), [accepted edit/cancel policy](../gap-analysis.md#exploration-work-and-transport) and [route use case](../use-cases.md#lode-naklad-a-obchodni-trasy).
4. Dependencies: route identity [R-0139](R-0139.md), stop instructions [R-0140](R-0140.md) and carrier assignment [R-0141](R-0141.md).
5. Primary area: [A06](areas.md#a06).

## 1. Summary

1. A player needs to change a running itinerary, cancel one carrier's route or delete a route while retaining control of every affected carrier.
2. The 2026-10-17 catalogue at `ffae3396` finds no route editor, assignment or cancellation. R-0139–R-0141 establish the prerequisite state.
3. This requirement owns route edit/delete timing, per-carrier cancel and repair of a paused lost stop; it does not recalculate past transactions.

## 2. Behavior

1. An edit to stops or configured cargo takes effect at the carrier's **next** stop, preserving its current location and voyage progress. Canceling an individual assignment returns only that carrier to manual orders immediately; other assigned carriers continue.
2. Deleting a route immediately returns all its assigned carriers to manual control, without moving them or resetting an Atlantic crossing. An inaccessible or lost stop pauses the affected carrier with a reason; the player may repair the route or cancel rather than spin or silently choose another port.
3. Canceling an edit changes nothing. Wrong owner, stale route or obsolete assignment rejects without partial edits, goods transfer or movement. Save/Continue retains pending edits or a paused reason without repeating a stop or resurrecting a deleted route.

## 3. Implementation steps

1. Model owns staged route changes and assignment removal against R-0139 IDs. Validate route, stop and carrier ownership before any mutation; UI offers edit, cancel, delete and pause-repair actions from current model state.
2. Not prepared for development. On selection, inspect the saved current-stop boundary and voyage progress so edit and delete cannot reset R-0141/R-0021 travel.
3. Proposed checks: edit en route/at stop, next-stop application, one-of-two carriers cancel, delete with two assignments and an in-transit ship, lost-stop repair, stale/cancel, save/Continue and named UC-030/016 player paths under the [functional contract](../functional-tests.md).
4. Current result: captured only; no gameplay change or runtime test is claimed.
