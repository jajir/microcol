# R-0155 — Explain native settlement alarm without color alone

1. Status: new
2. Updated: 2026-10-20
3. Related: P18/P27/P28; [NAT-006](../gap-analysis.md#native-nations-settlements-and-relations); [UC-061](../use-cases.md#domorode-narody) (Hra). See [accepted attitude thresholds](../gap-analysis.md#native-and-european-relations).
4. Dependencies: native settlement identity [R-0150](R-0150.md), T/L and rate [R-0153](R-0153.md), event changes [R-0154](R-0154.md).
5. Primary area: [A08](areas.md#a08).
6. Related areas: A03 map/details and accessible shared presentation; A04 persisted relation values; A02 selected European viewpoint.
7. Origin: NAT-006 display residual; no native GUI path is reported by the 2026-10-17 source catalogue at `8f3ce118`.

## 1. Summary

1. The player needs to distinguish current native attitude, whether alarm is rising, and a rival's provocation at a settlement.
2. Existing European map views do not establish that native settlement information route; this is a dated source finding, not UI acceptance.
3. This requirement owns the visible explanation of model relations, not their computation or their event causes.

## 2. Behavior

1. On a known settlement, show current attitude from `max(T,L)` as content, uneasy, angry or hostile at the accepted 25/50/75 thresholds. The color encodes current attitude, exclamation count encodes rate of alarm change, and background color marks another provoking European power when known.
2. The same three meanings are available in text/icon labels and keyboard-reachable details; color alone is insufficient. A rate of zero or decreasing alarm is distinguishable from increasing alarm without implying a new hostile state.
3. As R-0153/0154 alter relations, the map/details refresh from model-provided values. Save/Continue reproduces the same visible state; opening a detail does not advance alarm or reveal an undiscovered rival relationship.
4. UC-061 checks friendly, threshold-adjacent, hostile, changing-rate and rival-provocation examples under the human viewpoint, including a noncolor reading path.

5. Agreed 2026-10-20 ([shared rule](../gap-analysis.md#r-0155-refinement)): Show no exclamation mark for zero/decreasing alarm change, one for positive change up to 2 points per update, two for change above 2 through 5, and three above 5. Show a separate falling indication and the exact signed change in accessible text. This rate indication does not replace the agreed current-attitude thresholds.

## 3. Implementation steps

1. GUI reads model attitude, local rate and permitted rival indication from R-0153; the model remains authoritative for values and discovery permissions. Reuse shared UX/accessibility controls rather than independent color-coded rules.
2. On selection, define the rate-to-exclamation presentation against R-0153's model data and test at real map sizes. No event arithmetic or AI strategy belongs in rendering.
3. Proposed model/UI and UC-061 checks cover all thresholds, distinct channels, unknown rival, accessible text/focus, dynamic update and Continue. Follow the [functional contract](../functional-tests.md).
4. Current result: capture only; no gameplay change or runtime acceptance is claimed.
