# R-0013 — Leave or replace an active game safely

1. Status: Draft
2. Updated: 2026-10-13
3. Related: P28, P26; UC-113 and UC-115 (Hra). See the [rule catalogue](../gap-analysis.md),
   [use cases](../use-cases.md) and [work packages](../implementation-plan.md#seznam-pracovnich-baliku).
4. Dependencies: [R-0012](R-0012.md) navigation; existing save/load, with restoration safety in [R-0018](R-0018.md).
5. Primary area: [A01](areas.md#a01).
6. Related areas: A04 saving and recovery; A02 draft setup.

## 1. Summary

1. A player can return to the menu, start another game or quit without accidental loss of an active session.

2. Current menu/controller code dispatches start/load/exit actions; the new navigation foundation must define one consistent replacement policy instead of independent button decisions.

3. Implement the agreed leave/replace decision for an active free-play session. Do not score retirement or change game rules.

## 2. Behavior

Proposed acceptance for individual refinement; capture does not approve implementation.

1. Propose an active-session replacement offers Save and continue, Discard and continue, and Cancel. Clearly name the destination, such as starting a new game or exiting.

2. Cancel returns to the original screen and selection with the same units, treasury, turn and pending commands. Merely opening a menu does not advance a turn.

3. Save and continue proceeds only after successful saving. Cancelling file selection or a write failure keeps the active session available and offers recovery.

4. Confirming Discard replaces/closes the session only when the destination is ready. An invalid selected save preserves the previous playable session.

5. Opening Settings or returning from it preserves the live game. Loading the same game later restores the last successfully saved state, not a partially abandoned setup.

## 3. Implementation steps

1. Implement the shared lifecycle decision in `gui.dialog` and reuse `PersistingService`; keep game serialization in `model.campaign.po`. Route menu, window-close and applicable shortcuts through the same policy.

2. Integrate the R-0012 transitions, preserving screen/focus on cancellation. Use the R-0018 validated replacement path for loading.

3. Proposed `TC_free_play_leave_game_test`: save/success, discard, cancel, cancelled file chooser and failed write/load with a recognizable active colony. Verify state through page verification methods; run existing save/campaign regressions.
