# R-0018 — Restore a free-play save without losing the active game

1. Status: Draft
2. Updated: 2026-10-13
3. Related: P26; SUPPORT-001; UC-113/UC-115 (Hra). See the [rule catalogue](../gap-analysis.md),
   [use cases](../use-cases.md) and [work packages](../implementation-plan.md#seznam-pracovnich-baliku).
4. Dependencies: Existing save/load; [R-0002](R-0002.md) phase contract; [R-0014](R-0014.md) profile fields.
5. Primary area: [A04](areas.md#a04).
6. Related areas: A01 Continue/Load and replacement; all implemented state owners.

## 1. Summary

1. Complete the safe manual-save/restore boundary for the ordinary free-play loop, including invalid files and partially completed turns.

2. The catalogue identifies working `PersistingService`, `GameController` and human-turn autosave paths. The gap is not an absent save system; new phase/profile state and safe replacement need explicit acceptance.

3. Current-schema manual save/load and safe active-session replacement. Separate turn/decade autosave slots, historical save compatibility and cloud synchronization are outside this slice.

## 2. Behavior

Proposed acceptance for individual refinement; capture does not approve implementation.

1. Save a game containing a named colony, worked field, cargo/passenger and pending order. Load restores identities, quantities, locations, active player and the R-0002 phase without replaying production.

2. Parse and validate a selected save before replacing the live session. Missing required identity data, invalid references or malformed JSON produces a recoverable error with the original game still playable.

3. Cancelling either file chooser does not change the game or create a file. Opening a save never silently rewrites that player file.

4. Failed writing preserves the previous complete save at the destination. Success is reported only when a complete current-schema snapshot is safely stored.

5. Continue and explicit Load use the same validated restore path. After loading and advancing one phase/round, each due effect occurs exactly once.

## 3. Implementation steps

1. Inspect `gui.dialog.PersistingService`, `gui.event.model.GameController`, `model.campaign.po` and each selected state serializer. Define snapshot validation and replacement order around existing services.

2. Add missing current-state serialization and safe file replacement, update bundled fixtures directly, and integrate R-0013 lifecycle feedback. Do not add legacy migrations.

3. Proposed `TC_free_play_restore_test` uses an ordinary-start save plus corrupt/invalid copies; model/persistence tests inject write failure and phase round-trips. Verify previous save bytes and live state survive failures.
