## 1. Summary

1. Make participant identity and control explicit so opponents can be configured independently of display names and later AI behavior.

2. The catalogue records only the Dutch human/king in the fixed free-play start. The architecture also notes that `PlayerHuman` can represent computer-controlled colonizing players.

3. Persist and validate a minimal European participant roster, including each Crown association. Native society setup, intelligence sliders and arbitrary opponent counts are not implicitly accepted.

## 2. Behavior

Proposed acceptance for individual refinement; capture does not approve implementation.

1. Setup previews the participants and their nation/control roles. Propose one human nation plus one European rival for the first testable roster; no strategy quality is promised by adding that rival.

2. Nation identity, stable player identity, editable display name, human/computer control and Crown identity are separate data. Equal display names must not merge players or ownership.

3. Reject duplicate colonizing nations, missing Crown links and an unsupported human-player count before game creation, without partially creating units.

4. Initial units belong to the intended player. Turn scheduling uses the agreed national order from R-0002 rather than saved list order.

5. Save/load preserves identity, control and ownership. A rival receives only information available to it, and must later act through shared model operations.

## 3. Implementation steps

1. Extend the existing `Player`/`PlayerPo` and game creation contract only as needed; inventory all uses of names as identity before choosing representations.

2. Validate the reference roster and attach existing robot controllers by control role. Keep roster setup separate from the economic behavior proposed in R-0027.

3. Proposed `TC_free_play_participants_test` checks preview, two-player ownership and continuation. Model tests cover duplicate nation, invalid Crown association and equal display names with distinct identities.
