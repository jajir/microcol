# R-0113 — Skip the full game CI for documentation-only changes

1. Status: ready for development
2. Updated: 2026-10-15
3. Related: P31/P32 in the [implementation plan](../implementation-plan.md#seznam-pracovnich-baliku); CI and delivery, no gameplay UC.
4. Dependencies: existing [documentation publication](../publishing.md) and [development delivery](../development-builds.md).
5. Primary area: [A03](areas.md#a03), shared development support.
6. Related areas: none; preserve all game areas' existing verification gates for changes outside documentation.
7. Origin: user request on 2026-10-15 to avoid a complete CI build when only `docs/` changes.

## 1. Summary

1. Developers need documentation edits to be checked and published without spending resources rebuilding and retesting an unchanged game.
2. Source observation on 2026-10-15 at `f5371698`: the development-build, Java-compatibility and documentation workflows have no path filter for pushes to `main`. A documentation-only push therefore starts all three workflows.
3. Scope: skip automatic game compilation, Maven/model/UI tests, compatibility matrices, native packaging and development distribution publication when every changed path is under `docs/`. Keep documentation checks and Pages publication. Implementation is selected by the authorized R-0051–R-0113 run; acceptance remains pending.

## 2. Behavior

1. A push to `main` changes only files under `docs/`, including nested files, additions, deletions or moves within that directory → documentation checks and Pages deployment run; the complete game CI and game release publication do not run. The current development download remains unchanged.
2. At least one changed path is outside `docs/`, whether alone or mixed with documentation → retain the existing full verification and delivery behavior for that event. This includes workflow files, `mkdocs.yml`, documentation tooling and `AGENTS.md`; the exception is limited to the requested directory.
3. A file is moved across the `docs/` boundary → treat the change as including a path outside `docs/`. Inspect the entire push or pull-request change set, not just the last commit.
4. Pull requests retain documentation validation and apply the same documentation-only exception to their existing automatic game checks. Preserve the existing event scope; this requirement does not introduce game distribution publication from pull requests.
5. Explicit manual workflow dispatch remains available for full verification and builds. A skipped automatic game build must not leave required checks permanently pending or block a documentation-only merge. Failure of documentation validation still prevents Pages deployment.

## 3. Implementation steps

1. Refinement on 2026-10-15 at `b2b3ec14`: GitHub's branch-protection API reports main is unprotected (404), and the effective branch-rules API returns an empty list. No currently required check is omitted. Keep both game workflows triggered; a lightweight `changes` job determines whether their existing game jobs run or explicitly skip. Preserve existing job names, matrix entries and publication dependencies.
2. A shared Python-standard-library classifier reads the GitHub event and inspects the full Git change range with rename detection disabled and NUL-delimited paths. Push uses before/after commits; pull requests use the base/head merge-base comparison. Both paths of a boundary-crossing move therefore count. Checkout fetches full history. Empty, unavailable or invalid comparison data conservatively requests full game work; manual dispatch always does so. Expose a `game_required` boolean job output. Gate functional, launcher/native, compatibility and publication jobs, retaining their existing additional conditions.
3. The bounded implementation covers only the classifier, its tests and the two game workflows. The caller owns requirement/operating documentation, review and verification. No Java, game fixture or launcher change is needed. Pages keeps its existing validation and deployment path.
4. Caller checks: `python3 -m unittest discover -s scripts/ci -p 'test_*.py'`, including real temporary Git histories for nested docs, additions/deletions, within/boundary-crossing moves, mixed/code-only and multiple-commit pushes, diverged pull requests, manual dispatch and uncertain input. Inspect workflow wiring and run documented launcher/doc tests plus strict MkDocs. Publish this non-doc change and verify full CI/release; then make the documentation-only acceptance update and verify successful Pages, explicitly skipped game jobs and unchanged game manifest. Record actual run IDs in the delivery evidence.
5. Current result: implemented; local checks and the full implementation-push CI/release passed. The documentation-only live acceptance remains pending in [publication evidence](../publishing.md#documentation-only-ci-2026-10-15). Three local worker attempts delivered no usable patch; the caller completed the implementation after the final interruption, as recorded in [worker evidence](../ai/local-qwen.md#r-0113-ci-filtering-2026-10-15). The observed branch settings are dated evidence, not a promise that future protection cannot change.
