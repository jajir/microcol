2. Updated: 2026-10-13

4. Dependencies: [R-0012](R-0012.md); existing bundled free-play map. Participant expansion follows [R-0015](R-0015.md).
5. Primary area: [A02](areas.md#a02).
6. Related areas: A05 expedition; A04 calendar from R-0002; A08 participant identities.

## 1. Summary

1. Give the first ordinary free-play start an explicit, reproducible profile instead of treating the bundled scenario as the final setup specification.

2. The catalogue records a fixed map, player name without separate nationality, missing difficulty profile and an incomplete initial ship roster. Q-01/Q-02 own the unsettled numerical baseline.

3. One agreed reference profile plus editable player name, persisted with the game. Full map generation, all nation/difficulty combinations and their gameplay effects remain later work, not acceptance of this slice.

## 2. Behavior

Proposed acceptance for individual refinement; capture does not approve implementation.

1. Setup shows the map/profile identity, nation, difficulty interpretation and initial expedition before Start. Unsupported alternatives are not offered as if functional.

2. Propose the bundled map as the first reference map. Approve its explicit nation, ship, settlers, equipment and calendar through Q-02; do not silently label current values as manual facts.

3. Player name is Unicode with surrounding Unicode whitespace trimmed; internal accents, spaces and punctuation survive. Reject empty input with an actionable message; settle the name limit in chapter 4.

4. Start creates a fresh independent world exactly once. Cancel creates no game and preserves any existing session through R-0013 when that lifecycle is integrated.

5. After save/load, profile identity, player identity and expedition state agree with the created game. A second start from the same reference profile does not inherit changes from the first.

## 3. Implementation steps

1. Define the profile in `model`/`model.store` and the game envelope; adapt `gui` setup and `model.campaign` free-play creation. Keep campaign completion out of the profile contract.

2. Resolve Q-01/Q-02 for this single profile, update its bundled data directly and validate required identity fields. Do not add save migrations or pretend a profile label implements difficulty effects.

3. Proposed `TC_free_play_reference_profile_test`: fresh-profile start, Unicode name, invalid input, cancel, two independent games and round-trip. Model tests reject malformed profiles; UC-002 full 4×5 coverage stays open.
