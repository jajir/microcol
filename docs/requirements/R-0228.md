# R-0228 — Ship one meaningful event cue with a visual equivalent

1. Status: new
2. Updated: 2026-10-17
3. Related: P30; [audio cue catalogue contract](../audio.md#katalog-a-sablona-noveho-zvuku), [player feedback rules](../audio.md#zakladni-pravidla-pro-dalsi-praci).
4. Dependencies: event service [R-0226](canceled/R-0226.md), category settings [R-0227](R-0227.md), owning visual/game event (for example turn report [R-0204](done/R-0204.md)); no new model outcome belongs here.
5. Primary area: [A03](areas.md#a03).
6. Related areas: the selected event's owning gameplay area, A04 event timing.
7. Origin: one bounded first-cue integration; illustrative audio counts and extra music in the estimate are not an approved asset list.

## 1. Summary

1. One selected high-value game outcome receives a short cue at the moment it actually occurs, with the same information available visually.
2. The asset and trigger are recorded in the shared audio catalogue with their source and usage rights.

## 2. Behavior

1. Choose a specific event and distinguish its committed success/warning/failure from preview, rejected command, unrelated message and reopening. Play the cue once for the intended human, at the documented moment; repeated same-turn occurrences obey its explicit spacing/coalescing rule.
2. The equivalent text/icon/report remains understandable when muted. Audio level, overlap with music, restart, save/reopen and missing asset/device behave under R-0226/0227; a sound failure cannot change stocks, turns or battle outcome.
3. The catalogue names identifier, meaning, result trigger, timing, recipient, visual companion, source/license/credit, resource format, category, overlap policy and dated listening evidence. Do not infer a suite of mandatory sounds from this first cue.

## 3. Implementation steps

1. After event selection, trace the actual committed-result signal through model-to-GUI delivery and integrate one licensed/editable source and runtime asset. Run affected functional scenarios plus mute/duplicate/failure tests and listen on supported platforms.
2. Current result: captured bounded sound outcome; no cue selection, asset or audible result is claimed.

## 4. Open questions

1. Which existing visual outcome should receive the first cue, and what exact audible meaning/priority should it convey? The audio page lists examples, not an agreed first asset.
