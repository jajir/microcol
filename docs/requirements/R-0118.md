# R-0118 — Equip a colony pioneer only when enough tools are available

1. Status: new
2. Updated: 2026-10-17
3. Related: P07; PION-001; UC-017 (Hra). See the [pioneer rules](../gap-analysis.md#equipment-and-pioneers), [accepted work rules](../gap-analysis.md#exploration-work-and-transport) and [use case](../use-cases.md#vybaveni-a-upravy-krajiny).
4. Dependencies: existing colony equipment transaction; preserve the completed European pier contract [R-0020](done/R-0020.md).
5. Primary area: [A05](areas.md#a05).
6. Related areas: A07 colony warehouse; A03 equipment choice and rejection feedback.
7. Origin: documented PION-001 gap in the [rule catalogue](../gap-analysis.md#equipment-and-pioneers); new capture, not a reopening of R-0020.

## 1. Summary

1. A player needs a clear minimum-tools boundary when equipping a colonist as a pioneer in a colony.
2. Source inspection on 2026-10-17 at `f10e3f49`: colony equipment currently accepts any positive tool stock and caps the issued amount at 100. This is a source observation, not a player test.
3. Scope: colony-side pioneer equipment and its model/UI boundary. European pier equipment, later tool use and the hardy pioneer's acquisition remain with [R-0020](done/R-0020.md), [R-0119](R-0119.md)–[R-0122](R-0122.md) and [R-0074](R-0074.md), respectively.

## 2. Behavior

1. In an owned colony, the current player chooses the existing tool-equipment action for an eligible colonist; the displayed choice reflects the model's actual availability.
2. With 20/99/100/101 tools available, the colonist receives 20/99/100/100 tools, and the warehouse loses exactly that amount. Existing unit identity and specialty remain.
3. With 0/1/19 tools, or if the unit, owner or stock changes before confirmation, the action is rejected with a usable reason and no equipment or warehouse change. Cancel leaves both unchanged.
4. Save and Continue retain the equipped amount, including a partial 20–99-tool load. Existing mutually exclusive equipment and warehouse-capacity rules continue to apply.

## 3. Implementation steps

1. The colony model's shared equipment query and command own the 20-tool minimum and exact transfer; colony UI uses that query and handles a changed-state rejection. Reuse the existing save fields and the [R-0020](done/R-0020.md) pier transaction separately.
2. Not prepared for development; refine affected callers, fixture quantities and control feedback after selection.
3. Proposed checks: model boundaries 0/1/19/20/99/100/101 and atomic stale-state rejection; extend the named UC-017 player path with a `TC_...` scenario at refinement, including Continue. No new runtime verification is claimed.
4. Current result: captured only; gameplay has not changed.
