## 1. Summary

1. A long ordinary game remains playable through late turns, repeated saves and reports on supported platforms.
2. This requirement owns measurement and triage of whole-game stability, memory and responsiveness, not a guessed performance target or a rewrite of completed features.

## 2. Behavior

1. Run reproducible early/mid/late positions through multiple complete turns, AI decisions, UI navigation, Save/Continue and exit/restart. Record version, OS/runtime, map size, unit/colony count, memory, turn and interaction timings, crashes and irrecoverable hangs.
2. Compare results with an agreed baseline/budget; no known release-blocking crash, progression block or save loss remains. Route a measured defect to the smallest owner and remeasure after repair, preserving the same scenario.
3. Successful short UI scripts or package builds do not substitute for sustained play. Maintain a repeatable dataset and actual measurements rather than deriving acceptance from application constants.

## 3. Implementation steps

1. Define the supported scenario/platform sample and budgets before running; collect profiles/logs only as needed to localize failures, then run affected functional checks after any fix.
2. Current result: captured acceptance plan; no long-game stability or timing result is asserted.

## 4. Open questions

1. What supported map/load profile and turn, interaction, memory and crash thresholds constitute first-release acceptance? No numeric performance target is approved in the source docs.
