2. Updated: 2026-10-17

## 1. Summary

1. The first-release package uses a recorded, compatible runtime and dependency set whose actual native behavior is verified.
2. This requirement owns release baseline selection and focused integration fixes; existing CI and Mac ARM/Intel development artifacts are credited.

## 2. Behavior

1. Record JDK, JavaFX, modules, libraries, bundled native components and build tool versions for each supported package. Reproducible candidate builds launch and exercise graphics, audio, save paths and representative gameplay without relying on a developer machine's installed runtime.
2. Compare upstream changes and known incompatibilities before updating the baseline; update only necessary dependencies and rerun affected tests. A package that builds but fails at native toolkit startup is not accepted.
3. Version/manifest in the app and diagnostics identify the same candidate as the published artifact. Platform-specific proof remains R-0234/0235; no new Java architecture or a separate develop branch is required.

## 3. Implementation steps

1. Audit current resolved dependencies and bundled runtime, pin the approved release candidate and run launcher/package integration plus affected unit/UI tests. Record exact versions and platform evidence in existing delivery docs.
2. Current result: captured release gate only; the old estimate's toolchain observations need a dated recheck.

## 4. Open questions

1. None; choose the compatible release toolchain during refinement. Platform minima belong to R-0234/R-0235.
