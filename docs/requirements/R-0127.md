# R-0127 — Show and apply special-resource overlays

1. Status: new
2. Updated: 2026-10-17
3. Related: P04/P11; MAP-005; UC-008 (Hra). See the [map rule](../gap-analysis.md#map-terrain-and-exploration), [accepted resource bonuses and calculation order](../gap-analysis.md#economy-production-and-education) and [use case](../use-cases.md).
4. Dependencies: terrain identity [R-0123](R-0123.md) and baseline output [R-0124](R-0124.md); [R-0122](R-0122.md) consumes explicit silver-deposit identity. Finite reserve/depletion belongs to [R-0128](R-0128.md).
5. Primary area: [A05](areas.md#a05).
6. Related areas: A02 generated-map placement under [R-0065](R-0065.md); A07 field yield and production; A04 saved overlay; A03 visible tile/preview information.
7. Origin: MAP-005 gap and accepted overlay policy in the [rule catalogue](../gap-analysis.md#map-terrain-and-exploration).

## 1. Summary

1. A player should recognize a special resource on a tile and see its agreed effect in both yield preview and actual work.
2. The 2026-10-17 catalogue source assessment at `f902be8a` finds no special-resource overlay in stored tiles or the terrain-output calculation. This is source inspection, not runtime acceptance.
3. This requirement owns resource identity, display, save/Continue and output additions. It does not own finite reserve consumption [R-0128](R-0128.md), road construction [R-0121](R-0121.md) or road bonuses [R-0122](R-0122.md).

## 2. Behavior

1. A map tile can show and retain the documented silver, ore, mixed mineral, trapping, game, oasis, prime crop, prime timber, prime food and fishery overlay. The player sees the overlay and its matching field yield when that tile is known; loading preserves it without duplicating output.
2. Apply an explicitly printed aid-card resource bonus where present. Otherwise add 2 to the named output: silver; ore; both ore and silver for mixed minerals; fur for trapping; lumber for prime timber; the named crop for prime crop; food for game, oasis and prime food; fish for fishery. Place the overlay before job modifiers in the [accepted production order](../gap-analysis.md#economy-production-and-education). Only an explicit overlay can introduce its named output on a zero-baseline tile.
3. A tile without an overlay receives no overlay addition. Preview and next production update agree; selecting another commodity does not claim the resource's bonus. A silver-deposit tile remains explicitly identifiable for the mountain road bonus in [R-0122](R-0122.md), without inferring it from a nonzero yield.
4. Save and Continue retain overlay kind and resulting yield; merely opening a tile or restoring a save does not mine or replenish it. Finite ore/silver/mixed reserves and last-extraction limits are separately accepted with [R-0128](R-0128.md), so UC-008 output can be accepted without claiming UC-009 depletion.

## 3. Implementation steps

1. Keep overlay identity in model/map state and current-schema persistence. Use one model field-output calculation for preview and production, extending the R-0124 baseline in the agreed order. UI renders the model's known resource without revealing an unseen tile.
2. Not prepared for development. On selection, compare all printed card modifiers with the accepted +2 fallback, inspect saved map and scenario data, and identify the distinct reserve-state owner before enabling depletion. Preserve R-0122's silver-deposit dependency explicitly.
3. Proposed checks: every overlay kind and named output, printed bonus versus +2 fallback, zero-baseline introduction only by matching overlay, no-overlay guard, preview/real production agreement, known-versus-unseen display and save/Continue. Add a named UC-008 player path at refinement under the [functional contract](../functional-tests.md).
4. Current result: captured only; no gameplay change or runtime test is claimed.
