# R-0134 — Reserve the correct ship holds for artillery and treasure

1. Status: new
2. Updated: 2026-10-20
3. Related: P08; CARGO-004; UC-024 (Hra). See the [cargo rule](../gap-analysis.md#transport-ships-and-atlantic-travel) and [boarding use case](../use-cases.md#lode-naklad-a-obchodni-trasy).
4. Dependencies: [R-0095](done/R-0095.md) owns and has implemented the artillery role and its one-hold transport slice; [R-0175](R-0175.md) owns the treasure-train identity, creation, value and claim from native conquest [R-0174](done/R-0174.md).
5. Primary area: [A06](areas.md#a06).
6. Related areas: A05 unit/cargo identity; A08 treasure source; A09 artillery role; A04 saved multi-hold reservation.
7. Origin: remaining treasure capacity under CARGO-004; preserve R-0095's delivered artillery hold behavior.

## 1. Summary

1. A player transporting artillery or a treasure train needs hold use that matches the unit's real size and releases capacity when it leaves.
2. The 2026-10-17 catalogue at `ffae3396` predates R-0095's artillery one-hold implementation. The remaining gap is the six-hold treasure reservation and its integration with the R-0175 treasure role, not a second artillery implementation.
3. Scope: one shared cargo-capacity rule for these roles, with six distinct holds for treasure and one for artillery. Native treasure generation and Cortes' reward stay with [R-0174](done/R-0174.md)/[R-0175](R-0175.md).

## 2. Behavior

1. A legal artillery unit occupies one free ship hold, retaining the delivered R-0095 behavior. A treasure train, once available, may board only a ship with six free holds; fewer than six rejects without moving it or displacing other cargo.
2. A boarded treasure reserves all six holds as one unit. Unloading or destruction releases all six exactly once, without cloning the train or freeing only part of its reservation. A six-hold ship can carry exactly one such train and no other cargo simultaneously.
3. Wrong owner, stale capacity or cancel leaves unit, ship, goods and passengers unchanged. Save/Continue retains the unit and its full reservation. This requirement does not cause native conquest to create a treasure train or settle its value.

4. Consume the accepted 2026-10-20 rules from [R-0175](../gap-analysis.md#r-0175-refinement); preserve this requirement’s own outcome and existing delivered behavior. These decisions do not establish this consumer’s implementation or acceptance.

## 3. Implementation steps

1. Reuse the model's ship capacity and passenger validation, retaining R-0095 one-hold artillery. Add a multi-hold reservation representation only when a real treasure-train role is supplied by R-0175; reject partial reservations before mutation. UI presents only legal boarding choices.
2. Not prepared for development. R-0175's treasure role/creation contract is an explicit prerequisite before readiness; align its persisted identity without creating a second reward system here.
3. Proposed checks: artillery one hold regression; treasure 5/6 free-hold boundary, occupied-hold rejection, unload/destruction release, stale/cancel, save/Continue and named UC-024 player path under the [functional contract](../functional-tests.md).
4. Current result: captured only; no gameplay change or runtime test is claimed.
5. Align the existing checks and shared model/AI/UI integration with the linked 2026-10-20 decisions; retain unresolved questions only with their rule owners and run UI regression in CI under the current user instruction.
