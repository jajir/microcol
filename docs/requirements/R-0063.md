## 1. Summary

1. The player needs the nation chosen during setup to determine their actual participant and remain the same after Continue.

2. Current situation: R-0014 deliberately uses a mock nation selector while the reference scenarios remain fixed. A selected label alone does not change participant identity.

3. Scope: the outcome and examples below. This is captured work awaiting individual refinement; it does not reopen the delivered origin scope or close a whole UC.

## 2. Behavior

Proposed acceptance for refinement; inherited resolved decisions remain agreed.

1. Select England, France, Spain or Netherlands in setup → Start assigns the human to that nation with the correct identity, ownership and presentation.

2. Back returns to the menu without replacing the active game or saved continuation. Start validates the selected map/profile before replacement.

3. Player-entered name follows the existing Unicode/64-code-point contract and is distinct from the immutable nation identity.

4. Save and Continue retain nation and player name. National advantages are separate game rules; a working selector must not claim they are all implemented.

## 3. Implementation steps

1. Preparation awaits selection. Inspect setup/scenario assembly, model profile validation and persistence; reuse existing setup controls under the [package responsibility map](../architecture.md). Keep rule validation before mutation and use current-schema fixtures.
