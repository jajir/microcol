## 1. Summary

1. Agree a small screen/state map before adding isolated menu commands. The reader should be able to locate every ordinary free-play entry and return path.

2. [ButtonsPanelPresenter](../../microcol-game/src/main/java/org/microcol/gui/screen/menu/ButtonsPanelPresenter.java) starts free play directly, gates it on campaign completion and loads the autosave for Continue. [Screen](../../microcol-game/src/main/java/org/microcol/gui/screen/Screen.java) lists existing screens, but this is not an agreed final navigation design.

3. Own the navigation contract and transition table, not gameplay rules, graphical redesign or implementation of every destination. R-0001 owns removing the campaign gate; [R-0013](R-0013.md) owns safe replacement of an active game.

## 2. Behavior

Proposed acceptance for individual refinement; capture does not approve implementation.

1. Propose main-menu destinations New free game, Continue, Load, Campaign, Settings and Exit. New free game opens setup; Start is a separate action after setup validation. Campaign progress never authorizes ordinary free play.

2. Prepare a transition table with source state, command, enabled condition, destination, Back/Cancel result and retained state. Cover no save, available save, active game, unfinished setup and failed load.

3. Propose Continue resumes the active in-memory game when one exists; otherwise it loads the latest valid recovery point. Load selects another save. Disabled Continue explains the absence of a recoverable game.

4. In-game menu exposes Resume, Save, Load, Settings, Main menu and Exit. Retirement is a distinct A10 outcome and must not be an alias for leaving the application.

5. Review every path with mouse and keyboard, including Escape, focus return and a cancelled setup. Document unavailable destinations explicitly; do not create controls that silently do nothing.
