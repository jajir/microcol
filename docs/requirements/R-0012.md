2. Updated: 2026-10-13

6. Related areas: A02 setup destinations; A03 shared controls; A04 continuation; A10 retirement semantics.

## 1. Summary

1. Decision agreed with the user on 2026-10-13: retain the existing main menu and its ‘New free play game’ entry. A new menu architecture is unnecessary for this slice.

2. The campaign gate is removed, satisfying the same entry change tracked by R-0001. Existing Load/Continue and return-to-menu paths are retained.

3. Keep the automatic save/continue workflow; do not introduce Save/Discard prompts or a parallel in-memory Resume design. Verify the actual save trigger under R-0018 rather than assuming it fires on menu entry.

## 2. Behavior

1. New free play game is available regardless of campaign progress. A fresh profile can use it; the campaign remains a separate optional entry.

2. Retain existing menu labels and layout. R-0014 subsequently inserts the agreed mock setup screen with working Start and Back before creating the game.

3. Load selects an existing game. Continue restores the recovery save through the existing load path. Returning to the main menu is intended to save current progress automatically; R-0018 records the observed boundary and any gap.

4. Retain existing Settings, campaign and Exit behavior. Retirement/scoring is not added by this navigation change.

## 3. Implementation steps

1. Implemented and verified on 2026-10-13. The complete Docker regression passed; see the [shared acceptance record](../functional-tests.md#free-play-implementation-2026-10-13) for commands, counts and delivery evidence. Earlier audit observations describe the baseline.

2. Deliver the small campaign-gate change through R-0001, retaining the existing menu/controller and its callbacks.

3. TC12 verifies the campaign-finished start; TC21/TC_05 and TC24 verify the always-enabled fresh-profile entry and working setup.

4. Verify screen journeys and continuation with R-0016/R-0018. Keep the source of truth for mock setup in R-0014.

## 4. Open questions

1. Resolved 2026-10-13 by the user: keep existing Continue/load behavior and automatic saving associated with returning to the main menu. Do not redesign Continue as in-memory Resume. R-0018 must distinguish intended timing from tested timing.

2. Resolved 2026-10-13 by the user: the existing menu is sufficient; enable its free-play entry without campaign completion. No new menu tree or retirement command is required.
