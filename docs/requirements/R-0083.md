## 1. Summary

1. The player needs a visible price and an explicit choice to spend treasury gold on the current project.

2. Migration observation (2026-10-14): The queue supports choosing and progressing projects; it has no accepted rush-purchase quote/transaction.

3. Scope: the outcome and examples below. Selected and refined on 2026-10-16; it does not reopen the delivered origin scope or close a whole UC.

## 2. Behavior

Agreed acceptance refined on 2026-10-16.

1. Open rush purchase for a valid current project → show exactly what will be completed and the full gold/resource consequence.

2. Confirm with sufficient funds and unchanged project → charge once and complete according to the agreed purchased-material policy.

3. Cancel, changed queue/prerequisite or insufficient funds → preserve treasury, progress, tools and buildings.

4. Continue after purchase → retain one completion, one charge and correct remaining queue order.

5. Accepted behavior (2026-10-15; [economy, production and education](../gap-analysis.md#economy-production-and-education)): Quote missing hammers plus tax-inclusive missing tools, with no partial payment on cancel or stale state; home Europe must be available.

## 3. Implementation steps

1. `ColonyBuildingQueue` owns an immutable rush quote and atomic confirmation. Price is twice missing hammers plus the existing tax-inclusive Europe purchase quote for missing tools. Consume existing shared hammers/tools only up to project costs; missing goods go directly into this completion, never warehouse storage. Preserve surplus and the rest of the queue.

2. Bind the quote to this queue, head identity, order, owner, relevant stocks, treasury and market quote; compare fresh state and completion gates before mutation. Repeated/stale/foreign confirmation rejects unchanged. Home-Europe access, current turn/colony validity, arithmetic and unit-creation capacity remain authoritative. Population is a start-only gate. A zero-cost fully supplied project may complete once through the same explicit confirmation.

3. The construction picker opens a separate explicit confirmation showing the project, materials used/bought, total gold and remaining treasury. Cancel/Escape changes nothing; insufficient gold disables confirmation; stale state requires a new quote. `TC_55_F46_rush_construction_test` checks cancel, purchase, insufficient gold, stale resources and Continue. Model tests add exact rounding, mixed queue/unit completion, surplus, blocked prerequisites/Europe, repeated confirmation and full-state rejection snapshots. Follow the [functional contract](../functional-tests.md).

4. Implemented and locally verified on 2026-10-16: 1586 model tests and 13 selected Docker player/support tests passed, zero failures/errors/skips. Formatter, package/Javadoc and strict documentation checks passed. Full CI/publication are pending; see [execution evidence](../functional-tests.md#r-0083-rush-completion-2026-10-16). R-0109's shared pool is the sole construction-progress source. No new market or rebellion mechanics are introduced here.
