# R-0432 — Readable save filenames and ten circular autosave slots

1. Status: waiting for refinement
2. Updated: 2026-11-08
3. Related: SUPPORT-001; UC-113 (Hra); [save policy](../save-load-navigation.md).
4. Dependencies: [R-0388](done/R-0388.md) existing turn history; [R-0382](done/R-0382.md) archive metadata; [R-0298](done/R-0298.md) save management.
5. Primary area: [A04](areas.md#a04).
6. Related areas: A01 Continue destination; A03 save-name input, list and error feedback.
7. Origin: User request and Finder screenshot, 2026-11-08; analysis before implementation. Latest decision replaces five newest-first ranked files with ten circular slots.

## 1. Summary

1. Players need short recognizable files, one shared directory without playthrough subdirectories, automatic protection every turn and independent manually named saves.
2. Source inspection at `596540bc` on 2026-11-08: `SavedGames` uses playthrough UUID directories, random UUID manual filenames and increasing ten-digit turn filenames, retaining five snapshots per game. `GameModelDao` stores readable names inside metadata independently of filenames. Root recovery copies and quick saves are additional files. See the [dated source inspection](../save-load-navigation.md#soucasne-automaticke-zapisy-kontrola-zdroju-8-listopadu-2026).
3. Scope: refine the replacement save policy. No gameplay implementation, migration or changes to the user's existing saves are authorized by this analysis.

## 2. Behavior

1. Agreed latest decision, 2026-11-08: automatically save each turn into ten shared circular slots numbered 000–009. Write 000, 001, through 009, then replace 000, 001 and so on without confirmation. Number 000 no longer means newest. This supersedes the earlier five-slot newest-first decision.
2. All slots share one save directory without per-game subdirectories. Manual saves remain independent, available whenever the player can safely save, with user-chosen names. Default manual names use the played nationality and game year, not the player's name. Custom names take precedence; existing Unicode trimming and 64-code-point text limits apply.
3. Proposed: retain the existing safe boundary at the start of a fully prepared human turn after AI/world processing, before player actions. The initial prepared new-game state counts; merely loading an old save, looking at files or repeating the same callback does not write or advance the slot. Autosave preference remains effective.
4. Proposed: persist successful-write order independently of game year and wall-clock changes. Restart resumes at the next slot; switching games does not reset the ring. All games share the ten-slot budget, so another game gradually replaces previous autosaves. The browser and Continue use the actual latest successful save, not the lowest filename.
5. Proposed: replace only the chosen managed autosave after a complete safe write; write failure retains its previous valid contents, the next-slot position and Continue. Never rotate or overwrite manual files. Reserve autosave names from manual allocation. Manual filename collisions require explicit overwrite confirmation; cancellation leaves files and gameplay unchanged. Unsupported filename characters need clear feedback.
6. Proposed simplification: remove separate latest-turn and decade recovery writes; latest-turn recovery uses the most recent circular slot. The user-triggered quick-save command needs a decision; do not silently repurpose it. Existing files are not automatically deleted or renamed by reading or listing them.
7. The user's literal requested example is `autosave-000.akripis` in `./akropia/saves/`. Extension and path interpretation remain open below; do not silently normalize them to the existing `.akropia` extension and home-directory path.

Review metadata, atomic replacement, Continue/baseline path reuse, managed-kind recognition, browser sorting, quick save/load, recovery menu, import/export and file chooser extensions together. Remove per-game directory allocation for new saves.

Extend `TC_43_F34_recovery_points_test`, `TC_42_F34_load_recovery_test` and `TC_191_F224_session_menu_test`; select saved-game browser scenarios during implementation refinement. Preserve stable scenario IDs and existing gameplay assertions.

## 4. Open questions

4. Manual filenames: accept explicit confirmation for an existing target and visible rejection of unsupported/reserved names? Autosave replacement is already agreed.
5. Accept removal of separate latest-turn/decade copies, and what should the existing user-triggered quick-save command do? Recommendation: no extra automatic recovery files; decide quick save explicitly.
6. Is `.akripis` an intentional new extension, or should `.akropia` remain?
7. Does `./akropia/saves/` intentionally mean relative to the working directory, or is the existing `~/.akropia/saves/` intended? Recommend the home-directory path so launching from another directory does not change save location.
