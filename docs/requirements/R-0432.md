## 1. Summary

1. Players need short, recognizable filenames when inspecting or copying their saved games outside the game. Requested examples are `autosave-001.akropia` through `autosave-005.akropia` and `duch-1600.akropia`; an explicitly entered save name must be reflected in the filename.
2. Source inspection at `f29bf15e` on 2026-11-08: `SavedGames` creates `saves/<playthrough UUID>/`; manual targets use a new UUID, quick save uses `quick.akropia`, and turn snapshots use `turn-` plus a ten-digit increasing write sequence. Five snapshots are already retained per playthrough. These UUIDs identify games/files; they are not content hashes. The screenshot is consistent with this structure, but does not identify which games the two directories contain.
3. `GameModelDao` already stores a readable name in archive metadata: the supplied name, or player name plus game year/season. `PersistingService` chooses the random manual target separately, so the display name does not determine the filename. Independent root recovery slots explain `latest-turn.akropia` and `previous-decade.akropia`; they are outside the five-file history.
4. Scope is naming and its safe integration with existing save management. No gameplay implementation or modification of the user's existing saves is authorized by this analysis. The user rejected per-game directories on 2026-11-08; the remaining scope question concerns extra recovery and quick-save files.

## 2. Behavior

1. Requested: retain the latest five successful automatic turn saves with short `autosave-NNN.akropia` names, in one shared save directory, without playthrough subdirectories (user decision, 2026-11-08). The five-slot history is therefore shared across games; starting another game gradually replaces the previous game’s autosaves. Preserve existing save timing, failure reporting, manual/quick-save independence and read-only loading under the linked save policy.
2. Agreed on 2026-11-08: `autosave-001.akropia` always denotes the newest successful snapshot and `autosave-005.akropia` the oldest. With fewer than five saves, use only the needed names. Loading an earlier turn does not rotate them; the next successful new-turn save becomes 001 regardless of game year. Existing managed autosave names are replaced without an overwrite prompt, after safe completion of the new snapshot.
3. Requested: manual saves use a readable default such as `duch-1600.akropia`; user input such as `Před útokem` produces `Před útokem.akropia`. Agreed on 2026-11-08: the default uses the nationality played by the user and the game year, not the player name or a separate game title. A custom save name takes precedence. All new saves share one directory without per-game subdirectories; proposed location is the existing `~/.akropia/saves/`.
4. Proposed: retain Unicode letters, accents, punctuation and internal spaces wherever portable filesystem rules permit them, with existing Unicode trimming and 64-code-point input validation. Reject path separators, traversal and unsupported filename characters with clear feedback rather than silently changing the supplied name. Handle an already supplied `.akropia` suffix once. Reserve managed quick/autosave names so manual saves cannot enter automatic cleanup.
5. Unresolved for manual saves only: a new save whose filename already exists could receive a short suffix, for example `duch-1600-2.akropia`; only the existing explicit overwrite action with confirmation may replace a manual save. Include case-insensitive and Unicode-normalized collisions. Cancellation leaves files and the active game unchanged.
6. Preserve complete recovery states on write failure or interruption. Continue and the save browser must still identify the intended state after any renaming. Merely listing or loading an archive must never rename, rewrite or rotate it. Existing files are not silently migrated or deleted.

Rank rotation must not let a stale path select a different snapshot or let interruption destroy previous saves.

## 4. Open questions

4. Manual-save name collisions and unsupported/reserved names: the user approved replacement for autosaves only. Proposed manual policy is a numeric suffix for a new save, explicit confirmation for overwrite, and visible rejection of unsupported/reserved names.
5. Should the extra `latest-turn.akropia`, `previous-decade.akropia` recovery copies and user-triggered `quick.akropia` remain? The user expects only five autosaves and manually named saves and requested a summary of existing automatic writes before deciding. Proposed simplification is to reuse the newest autosave for latest-turn recovery and remove the separate decade checkpoint if accepted; quick-save behavior needs a separate decision. Do not treat this proposal as implemented or decided.
