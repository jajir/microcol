# R-0062 — Produce one automatic base cross per colony

1. Status: ready for development
2. Updated: 2026-10-16
3. Related: P11; PROD-008; UC-040 (Hra), base component. See the [rules](../gap-analysis.md), [use cases](../use-cases.md) and [work packages](../implementation-plan.md#seznam-pracovnich-baliku).
4. Dependencies: Existing chapel/church/cathedral production and colony update path.
5. Primary area: [A07](areas.md#a07).
6. Related areas: A04 single update; A03 cross preview. A06 national immigration is separate R-0076.
7. Origin: [R-0010](canceled/R-0010.md). Unfinished original outcome under the [migration](migration-2026-10-14.md).

## 1. Summary

1. The player needs an unstaffed colony to contribute its automatic cross, with displayed and actual production matching.

2. Migration observation (2026-10-14): Religious production has a declared base of one, but the current calculation only adds worker contributions; existing checks expect zero without staff. Periodic immigration does not prove cross production.

3. Selected and refined on 2026-10-16 under the continuing implementation authorization. This requirement owns the automatic base calculation; religious tier/expert improvements remain R-0110 and national collection remains R-0076. It does not close the whole UC.

## 2. Behavior

Agreed acceptance after refinement on 2026-10-16.

1. Basic chapel without a preacher → preview one base cross and produce it once at the colony update.

2. Add or remove a worker → add/remove that worker’s contribution while retaining one base cross.

3. Upgrade the religious building → the colony receives the current building's unattended contribution once, not once for each old/new building. R-0110 owns the increased tier values and other religious bonuses; this prerequisite activates the currently declared base without claiming those increases delivered.

4. Two colonies each contribute once. Reopening screens and saving/loading add no production; unrelated town-hall bell output remains unchanged.

5. Accepted behavior (2026-10-15; [economy, production and education](../gap-analysis.md#economy-production-and-education)): The unstaffed initial colony produces one cross; church/cathedral totals replace that baseline.

## 3. Implementation steps

1. Inspection at `f15adba0` on 2026-10-16 found that `Construction.getProduction()` sums slots without the declared base. `Colony.getGoodsStats()` and `Construction.countTurnProduction()` already share that calculation. Add the declared base once for cross-producing buildings in the model. Do not activate the unrelated town-hall base as a side effect.

2. Preserve slot output, existing worker assignment validation and the single mutable building used by upgrades. No new stored field or screen-specific production formula is needed. Tier values remain with R-0110; existing save/load and national-turn boundaries must not replay production. Add missing unstaffed chapels directly to the bundled buildArmy/thrive scenarios and F07 fixture; new colonies already include a chapel.

3. Verify `Construction_CHURCH_Test` and new `ColonyCrossProductionTest`: empty/staffed/removed workers, chapel upgrades, two colonies, repeated preview, committed production, save/load and unchanged bells. Extend existing `TC_07_F07_producing_gooods_test` with visible unattended preview, repeated opening and per-turn stock checks; retain `TC_02_F02_founding_colony_test`. Run these in Docker with `PageVerificationContractTest`, followed by the required full regression/publication checks under the [functional contract](../functional-tests.md).

4. Current result: implemented with passing model and selected Docker checks; [dated evidence](../functional-tests.md#r-0062-automatic-cross-production-2026-10-16) records the results. Full regression and publication remain pending, so this record stays ready for development.
