## 2. Behavior

Proposed acceptance for refinement; inherited resolved decisions remain agreed.

1. A project has enough hammers but is one tool short → do not finish it; show an actionable missing-tools report identifying colony, project and shortage.

2. Opening the colony from that report shows the same retained progress and waiting reason.

3. Supply the last required tool → complete once on the agreed phase and consume exactly the required tools.

4. Accepted frequency (user decision, 2026-10-17): produce one missing-tools report each owner turn while the project is still waiting for tools. Repeated views, dismissal and Continue do not create another report for the same update or duplicate completion. The next owner turn reports the current shortage again; reminders stop when the project no longer waits for tools.

5. Accepted behavior (2026-10-15; [recovery and presentation](../gap-analysis.md#recovery-and-presentation)): Keep the missing-tools outcome visible through the shared report controls with the per-turn frequency accepted on 2026-10-17.

6. Shared update boundary (2026-10-15): apply this requirement within [national turn processing](../gap-analysis.md#national-turn-processing). Resume the saved completed boundary without repeating production, arrivals or action replenishment; future pending choices must preserve earlier completed updates.
