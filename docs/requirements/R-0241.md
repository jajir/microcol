# R-0241 — Review, launch and support the Steam release

1. Status: new
2. Updated: 2026-10-17
3. Related: P32; [Steam store/review plan](../implementation-estimate.md#missing-publishing-and-delivery-work), [release dependencies](../implementation-estimate.md#store-requirements-fees-and-calendar-dependencies), [post-release upkeep](../implementation-estimate.md#post-release-maintenance).
4. Dependencies: store checklist [R-0237](R-0237.md), media [R-0238](R-0238.md), depot/client checks [R-0239](R-0239.md)/[R-0240](R-0240.md), stable release record [R-0236](R-0236.md), player support guide [R-0232](R-0232.md).
5. Primary area: [A01](areas.md#a01).
6. Related areas: A03 player-facing information; A04 diagnostic/save support; P31 regressions.
7. Origin: bounded publisher operations and initial support readiness, not a new game feature or perpetual unlimited maintenance mandate.

## 1. Summary

1. Approved store and build reviews lead to a deliberate publisher launch with a working support route and a recoverable build record.
2. This requirement distinguishes preparation, external review, actual release action and post-launch triage.

## 2. Behavior

1. Submit the completed store page and build through the publisher account, resolve review findings, rehearse final checks, then perform and verify the authorized launch action. Confirm public store availability, correct package access/download and exact live build/version; a target date or uploaded depot is not publication.
2. Provide support links, concise FAQ, diagnostic request guidance and issue triage/patch ownership. Record early incidents and the approved rollback/patch route using R-0236/0240. Keep continuing maintenance cadence separately scoped after the first release.
3. Respect current account-side waiting/review requirements at execution time; the dated estimate is planning context, not a standing assertion about today's platform rules.

## 3. Implementation steps

1. Maintain one release checklist with responsible publisher, actual partner-review state, links/evidence and go/no-go result. Recheck live platform policies before submission, record final action and run a customer-style download smoke test.
2. Current result: captured operational release outcome only. No store review, launch, public build or support channel is claimed complete.

## 4. Open questions

1. Who holds the final launch/go-no-go responsibility, and what support staffing and coverage period will operate after release? Account permissions belong to R-0237 and the published channel to R-0232.
