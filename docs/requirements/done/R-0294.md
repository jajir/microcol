## 1. Summary

1. The coastline already looks softly drawn, but the flat colours of adjoining land terrains expose the square grid. Give their boundaries a similarly hand-drawn appearance.
2. Preserve the readable terrain palette and meaningful trees, relief, resources, colonies and units. Do not add textures, gradients, new inland outlines or another setting.
3. This changes rendering only. The terrain of each logical square, movement costs, yields and saved map remain the same.

## 2. Behavior

1. Opening a new or existing game automatically shows gently curved, irregular boundaries between different known land colours. Equal colours join without visible seams; narrow strips, isolated squares and three-way joins remain continuous without gaps or overlaps.
2. Each square's centre keeps its own terrain colour, so selection, names and gameplay continue to identify the same square. Existing coastline silhouettes and their ink remain intact, with neighbouring land colours meeting the coast naturally.
3. Shapes remain stable when panning and after Save/Continue. Opening a saved game does not rewrite it. Exploration may update newly revealed joins; unexplored terrain must not contribute a hidden colour.
4. Players use the existing map navigation, selection, save and exit controls. Fog, optional grid, terrain decorations, resource overlays and water animation remain readable and functional. There is no new confirmation, cancel step or sound.

## 3. Implementation steps

1. Keep geometry in existing `gui.image`, integrated through `MapManager` and `PaintService`. Derive shared cubic edges from the saved map seed and global coordinates; reverse the exact same edge for the neighbouring region. Limit vertex offsets to 8% per axis and control points to an 18% band around the original edge; pin water, unknown and map-edge joins.
2. Rasterize local known-land regions with the existing flat palette and apply the existing coast alpha/ink mask. Cache final images by location and explored neighbourhood identity; release temporary geometry. Keep standalone synthetic terrain previews valid. No model, AI or save-schema change is required.
3. Cover tiling, narrow/isolated patches, seed stability, cache invalidation, hidden terrain and coast alpha in `TerrainBoundaryImagesTest` and `TerrainCoastColourTest`. Add `TC_80_F72_terrain_identity_test.TC_05_hand_drawn_boundaries_survive_pan_and_continue` through dedicated page verifications; retain existing composition, fog and resource assertions.
4. Apply the shared Java formatter, inspect a real Docker/Xvfb map capture, run affected TC80/TC26/TC91 scenarios and the page source contract, then the mandatory model/JUnit and fixed smoke gate. Run documentation checks and strict MkDocs. [Execution evidence](../../functional-tests.md#r-0294-terrain-boundaries-2026-10-26) records actual results separately from remote regression and publication.

5. Implementation and required local acceptance are complete; see the linked execution evidence. Full regression and publication remain independently unverified.
