# R-0350 — World minimap in the right sidebar

1. Status: done
2. Updated: 2026-10-30
3. Related: [UC-114/119 and the UI catalogue](../../use-cases.md), [visual brief](../../graphics.md#soucasne-zadani-vzhledu), [UX guidelines](../../ux.md).
4. Dependencies: existing map navigation and [R-0070 explored terrain and current visibility](R-0070.md).
5. Primary area: [A03](../areas.md#a03).
6. Related areas: [A05](../areas.md#a05), for the player's permitted knowledge of the world.
7. Origin: user request on 2026-10-30 for seven visual proposals based on an attached main-game screenshot; the user selected the attached strongly inked, reduced world overview and requested implementation on the same day.

## 1. Summary

1. Give the player a world overview and a direct way to move the detailed map to a chosen location.
2. The supplied screenshot has player and terrain information at the top of the right sidebar and no minimap. It is the visual reference, not evidence of the current executable revision.
3. Capture the requested behavior and prepare visual alternatives. The [first gallery](../../graphics.md#minimapa-sedm-navrhu-30-rijna-2026) contains seven styles; the follow-up request on 2026-10-30 adds [seven more reduced scales](../../graphics.md#minimapa-sedm-meritek-30-rijna-2026). The selected direction keeps strong hand-drawn strokes and a small full-world overview; the actual reduction follows the world dimensions, not an illustrative fixed multiplier.

## 2. Behavior

1. The minimap sits at the top of the right sidebar, above the existing player and terrain information. It always represents the full playable world's extent, with terrain indicated by color and land boundaries by strong hand-drawn lines.
2. Clicking a location on the minimap moves the detailed map to that location. A closed rectangle shows which part of the world the detailed map currently displays and follows changes to that view.
3. Unexplored areas remain concealed. The world outline describes the playable bounds; it does not reveal unknown coastlines, terrain or objects. Rendering follows the player's existing knowledge rules in R-0070.
4. Agreed boundary behavior: clamp the detailed view at world edges, preserve the world's aspect ratio, and make navigation change only the view, without issuing a unit order or discovering terrain. Existing information below the minimap must remain usable in small windows.

## 3. Implementation steps

1. Reuse `VisibleAreaService` and the game animation loop for a 220 × 180 logical-pixel overview above the existing sidebar information. Fit the full world without distortion; letterbox unused space. Draw terrain colors, irregular ink boundaries and an opaque unknown mask from the human player's explored terrain. Do not draw units or settlements.
2. Clicking centers the detailed view, clamped to world edges. A cream rectangle with a dark outline follows ordinary scrolling, centering, resizing and loading another map. Center worlds smaller than the detailed view. Arrow keys pan while the minimap has focus; Tab leaves it without issuing a unit order. Keep a localized permanent hint and accessible help.
3. Keep coordinate conversion and drawing in the existing game UI packages; reuse model visibility queries under the [architecture contract](../../architecture.md#prozkoumany-teren-a-soucasny-dohled-r-0070). Refresh changed explored terrain, including discovery and terrain edits, without exposing hidden geography.
4. Acceptance: geometry JUnit tests for coordinate mapping and small worlds; `TC_196_F228_world_minimap_test` for full-world fit, click/keyboard navigation, viewport synchronization, unknown terrain, unchanged gameplay state, discovery, resizing and localization. Preserve UC-114/119 and R-0070 coverage. Run model/JUnit, targeted Docker/Xvfb with the relevant existing layout/visibility scenarios, then smoke; review captured visuals, documentation consistency and strict MkDocs. Actual results belong in the functional evidence page.
5. The two proposal galleries remain design history. The selected image is a visual reference, not evidence of runtime geometry or world size.

6. Implementation and required local acceptance are complete on 2026-10-30; see the [functional evidence](../../functional-tests.md#r-0350-world-minimap-2026-10-30) and [runtime screenshots](../../graphics.md#minimapa-vybrany-vzhled-30-rijna-2026). Publication requires separate verification.
