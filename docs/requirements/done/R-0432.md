## 1. Summary

1. Players need short recognizable files, one shared directory without playthrough subdirectories, automatic protection every turn and independent manually named saves.
2. Source inspection at `596540bc` on 2026-11-08: `SavedGames` uses playthrough UUID directories, random UUID manual filenames and increasing ten-digit turn filenames, retaining five snapshots per game. `GameModelDao` stores readable names inside metadata independently of filenames. Root recovery copies and quick saves are additional files. See the [dated source inspection](../../save-load-navigation.md#soucasne-automaticke-zapisy-kontrola-zdroju-8-listopadu-2026).
3. Scope: implement the accepted replacement save policy. Preserve existing files without migration or deletion.

## 2. Behavior

1. Agreed latest decision, 2026-11-08: automatically save each turn into ten shared circular slots numbered 000–009. Write 000, 001, through 009, then replace 000, 001 and so on without confirmation. Number 000 no longer means newest. This supersedes the earlier five-slot newest-first decision.
2. All slots share one save directory without per-game subdirectories. Manual saves remain independent, available whenever the player can safely save, with user-chosen names. Default manual names use the played nationality and game year, not the player's name. Custom names take precedence; existing Unicode trimming and 64-code-point text limits apply.
3. Accepted on 2026-11-08: retain the existing safe boundary at the start of a fully prepared human turn after AI/world processing, before player actions. The initial prepared new-game state counts; merely loading an old save, looking at files or repeating the same callback does not write or advance the slot. Autosave preference remains effective.
4. Accepted on 2026-11-08: persist successful-write order independently of game year and wall-clock changes. Restart resumes at the next slot; switching games does not reset the ring. All games share the ten-slot budget, so another game gradually replaces previous autosaves. The browser and Continue use the actual latest successful save, not the lowest filename.
5. Accepted on 2026-11-08: replace only the chosen managed autosave after a complete safe write; write failure retains its previous valid contents, the next-slot position and Continue. Never rotate or overwrite manual files. Reserve autosave names from manual allocation. Manual filename collisions require explicit overwrite confirmation; cancellation leaves files and gameplay unchanged. Unsupported filename characters need clear feedback.
6. Accepted simplification: remove separate latest-turn and decade recovery writes; latest-turn recovery uses the most recent circular slot. Retain the existing user-triggered quick-save command as one shared `quick.akropia` outside the ring; this is an implementation choice preserving the explicit player action. Existing files are not automatically deleted or renamed by reading or listing them.
7. The user confirmed `.akropia` and accepted the proposed home-directory location `~/.akropia/saves/`. Managed names are `autosave-000.akropia` through `autosave-009.akropia`.
