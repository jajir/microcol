2. Updated: 2026-10-23
3. Related: P27; [SUPPORT-003](../../gap-analysis.md#supporting-persistence-and-information); [UC-114 labor row](../../use-cases.md#povinne-matice-a-obsah-prehledu) (Hra).

5. Primary area: [A03](../areas.md#a03).
6. Related areas: A05 unit identities; A07 workforce; A04 current viewpoint.
7. Origin: field-level labor advisor residual; R-0016 delivered opening/leaving reports, not these complete counts and drilldown.

## 1. Summary

1. The labor advisor lets the player count each owned colonist type and find selected people without searching the map.
2. Existing screens/navigation are credited; this requirement owns the labor fields and location action only.

## 2. Behavior

1. Show current counts for every owned colonist type, including legitimate specialist, veteran and native-convert identities without double-counting a worker also represented by equipment or cargo. Selecting a type reveals each member's real colony/job, map, ship or accessible Europe location.
2. Reassignment, loss, capture and Save/Continue refresh counts/locations. Do not reveal hidden foreign labor; a missing/stale unit location returns safely. Mouse/keyboard opening and leaving retains R-0016 behavior and spends no move.
3. UC-114 checks per-type totals against a mixed fixture, a selected location in each placement, viewpoint isolation and update after transfer.

4. Consume the accepted 2026-10-20 rules from [R-0149](../../gap-analysis.md#r-0149-refinement); preserve this requirement’s own outcome and existing delivered behavior. These decisions do not establish this consumer’s implementation or acceptance.

## 3. Implementation steps

1. Reuse the model’s unit ownership, specialty and placement queries to provide current human-viewpoint labor entries. Count each living owned person once by stable unit ID; preserve civilian specialty when equipped or veteran and expose veteran/equipment information without a second population count. Include native converts and stationed workers; exclude ships, braves, foreign and Crown-seized people.
2. Extend the existing statistics/advisor navigation with a localized EN/CS labor report: per-type totals, selectable members and explicit colony/job, map, carrier/voyage, accessible Europe or native-assignment location descriptions. Reuse existing screen/map selection events for available destinations. Revalidate selected unit ownership and placement before navigating; inaccessible transit/seized/removed targets must not reveal hidden state or crash. Opening, selecting and leaving spends no movement.
3. Rebuild from current state when opening the report or selecting a type/member; retain no independent labor ledger. Cover transfer/reassignment, death/capture and Save/Continue. Model tests cover identity deduplication, all placement families, equipment/veteran coexistence and viewpoint isolation. TC166 covers a mixed workforce, location choices, keyboard/close path and a changed placement after Continue, using existing fixtures and page verification methods.
4. Main reviews model/UI boundaries, applies the shared formatter and runs all JUnit plus relevant Docker/Xvfb scenarios. Complete local acceptance follows at the batch boundary. Targeted model/UI verification passed on 2026-10-23; see the dated [execution evidence](../../functional-tests.md#r-0198-labor-advisor-written-not-verified-2026-10-23). Complete batch acceptance remains pending.

8. Complete local acceptance passed on 2026-10-23: 3,964 model/JUnit and 637 UI/support tests, zero failures/errors/skips. See [seventh-batch acceptance](../../functional-tests.md#seventh-batch-full-acceptance-2026-10-23). This requirement is done; publication was not verified.
