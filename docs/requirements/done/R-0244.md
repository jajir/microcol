## 1. Summary

1. Reduce repeated cloud context in normal Codex and supported Claude Code work through a local compression proxy.
2. Keep model selection, reasoning, subscription authentication, required tests, review and publication intact. The pilot is evidence for one task, not a guaranteed saving for every session.

## 2. Behavior

1. New supported client sessions use a loopback-only Headroom service with the existing provider credentials and selected model. The host restarts the service after a crash and starts it at login.
2. Use cache mode and retain access to original evidence; disable shared memory, output shaping, the traffic-learning service and telemetry uploads. Do not route the local Ollama worker or external tools that have not been configured and verified.
3. Preserve raw files, diffs and test reports as acceptance evidence. A successful compressed response does not establish acceptance. Keep an explicit direct-provider bypass and reversible configuration; never silently replay an interrupted implementation.
4. Verify both clients with real requests and tool outputs, including their reported model and proxy routing. Distinguish configured desktop routing from a verified running desktop task. Record limitations, startup/restart behavior and rollback steps.

## 3. Implementation steps

1. Pin an isolated host installation, reuse the downloaded compression model, and use Headroom's supported native service installer. Configure Claude's existing settings and Codex's native provider base-URL setting without rewriting thread history or model preferences.
2. Back up affected settings, verify loopback binding and disabled optional features, test actual Codex/Claude traffic and service recovery, and document the current commands in one operating page.
3. Run documentation checks and strict MkDocs, review the host configuration and source diff, then publish documentation through the existing CI filtering contract. This changes developer tooling, not game code or test expectations.

4. Implemented and locally accepted on 2026-10-18. The [operating evidence](../../ai/headroom.md#rollout-verification-2026-10-18) records actual client/tool requests, service recovery, direct bypass, retained preferences and documentation checks.
