## 1. Summary

1. Make unknown-map question marks look like the surrounding hand-drawn map artwork.
2. At source revision `0a85fe547218dd4e23107ef91acbe30e3486fdf7`, the mark was a small, light-brown Playpen Sans 14 glyph. The supplied screenshot showed weaker visual weight than the map contours.
3. The user selected A from the [comparison](../../graphics-assets/question-marks-2026-10-26/comparison.png): a compact rounded hook and small irregular dot.

## 2. Behavior

1. Unknown squares use the fixed [variant A drawing](../../graphics-assets/question-marks-2026-10-26/variant-a.svg), with rounded 1.6-pixel strokes in the terrain contour color `#292824`. Its approximately 21-pixel ink height sits inside a 45-pixel map square. This replaces a text glyph with artwork and does not change the Playpen Sans 14 typography rule.
2. Retain the existing approximately 4% frequency, saved-seed placement, fixed map position and permanent disappearance after exploration. Shape, position and tilt do not animate or change during repainting, panning, resizing or Continue.
3. The decoration appears automatically and has no action or cancellation path. It remains legible without revealing hidden terrain or adding a control.
4. B and C remain documented alternatives and are not mixed into the map.

## 3. Implementation steps

1. Reuse unknown-mark drawing in `gui.util.PaintService` and stable selection in `gui.image.ImageRandomProvider`. Draw the exact selected SVG curve with existing JavaFX canvas operations and the shared terrain marker ink. No runtime atlas, font weight, dependency, save field or package responsibility is added.
2. Preserve `TC_26_F18_fog_of_war_test.TC_10_unknown_question_marks_remain_fixed_until_explored` and its player journey; update the independent rendered-pixel reference to A and capture actual game evidence. Retain density, fog/privacy and hidden-resource checks.
3. Run TerrainDecorationTest, all TC26 and TC91 scenarios, PageVerificationContractTest, the shared formatter, all model/JUnit checks and the fixed Docker/Xvfb smoke gate with its current 360-second budget. Validate documentation consistency and strict MkDocs.
4. Variant A is implemented and locally accepted on 2026-10-26: all 20 targeted checks and all 4,775 mandatory model/JUnit plus smoke checks passed. Actual results are in the [functional evidence](../../functional-tests.md#r-0296-hand-drawn-question-marks-2026-10-26); the earlier design-only checks remain in the [documentation evidence](../../publishing.md#r-0296-question-mark-proposals-2026-10-26).
