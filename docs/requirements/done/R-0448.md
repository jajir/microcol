# R-0448 — Explain rejected colony worker drops

Status: done

## 1. Summary
1. Requested on 2026-11-10: a worker returning to its original position after a refused drag needs an explanation during the gesture and after release.
2. Primary area: [A03](../areas.md#a03). Dependencies: existing colony work eligibility and movement rules; shared modal confirmation controls. No gameplay rule changes.
3. Follow the [architecture](../../architecture.md), [UX guidelines](../../ux.md) and [functional test contract](../../functional-tests.md#r-0448-rejected-colony-worker-drops-2026-11-10).

## 2. Behavior
1. While dragging a worker over an unavailable surrounding field, the status bar states that the worker cannot move there and explains the known reason.
2. Releasing over that field shows one modal explanation with an OK button after the native drag ends. The worker, job, movement and stocks remain unchanged.
3. Canceling the drag does not open a rejection modal. Legal assignments and native-land questions retain their current behavior. Eligibility is rechecked at release.
4. Tundra is not categorically forbidden: it produces food. A field without food production cannot receive the initial food job; other rejection reasons include occupied fields, missing docks and unavailable workers or movement.

## 3. Implementation steps
1. Keep authoritative eligibility in the model. Let the colony field UI receive refused releases without applying a model mutation; defer its shared message dialog until native drag completion.
2. Reuse English/Czech localization and existing status feedback. Cover unsupported terrain, occupied fields, stale state, cancellation and subsequent legal drag in TC_39; retain the map-edge rejection checks in TC_34 and native-land checks in TC_114.
3. Apply the shared Java formatter. Run model/JUnit, targeted Docker/Xvfb UI scenarios, fixed smoke/support, documentation consistency and strict MkDocs. Record actual results in [functional test evidence](../../functional-tests.md#r-0448-rejected-colony-worker-drops-2026-11-10).
