## 1. Summary

1. Developers need the game and its packaged dependencies to exclude versions affected by the repository's current Dependabot alerts.
2. On base `f902716f1889f4f832dc1c5e4a40fcf5c2b448a2`, the authenticated GitHub API returned nine open alerts: Log4j Core #1, #7, #11, #16–20 and Gson #8. All refer to `microcol-game/pom.xml`.
3. Scope is the affected runtime libraries and the matching logging binding. Unrelated dependency upgrades and gameplay changes are outside this request.

## 2. Behavior

1. Building the game resolves patched Log4j Core/API/binding together and patched Gson, and packages those versions into the game module.
2. Existing logging, startup, settings and game save/load behavior remain usable. Invalid saves retain the existing rejection contract; no save migration is introduced.
3. All nine captured alerts must be covered by the resolved versions. A failed, incomplete or skipped required local check blocks completion; updating version text alone is insufficient.
4. Local acceptance and pushing sources do not establish remote alert closure, full-regression success or distribution publication.

## 3. Implementation steps

1. Update the two Log4j dependencies together using one version property in the game POM, from 2.0.1 to 2.25.5. This also covers the additional Log4j API serialization fix in the [Apache security advisory](https://logging.apache.org/security.html). Update Gson from 2.8.2 to 2.8.9, the patched version for alert #8.
2. Reuse existing logging configuration, Gson adapters and packaging. Preserve Log4j's runtime service declarations in the combined module descriptor, because shading removes the library descriptors. Mark both combined JARs as multi-release so the bundled versioned classes work with JDK 17 linking. Inspect the resolved Maven dependency tree and assembled game/module archives for the selected versions; exercise logging and Unicode JSON round trips on both classpath and module path, including the JDK 17 linked runtime. No package responsibilities or build output names change.
3. Run all model/JUnit and support tests with the fixed Docker/Xvfb smoke gate, including `TC_12_F11_start_free_game`, the settings path in `TC_84_F75_framed_settings_test` and save/continue in `TC_21_F15_free_play_screen_navigation_test`; run documentation consistency checks and strict MkDocs.
4. Implementation and required local acceptance are complete. The [dated evidence](../../functional-tests.md#r-0299-dependabot-library-updates-2026-10-26) records packaging failures and their repairs, successful JDK 17 runtime checks, formatting, documentation validation and all 4,775 mandatory checks passing. Remote regression, alert closure and publication remain independently unverified.
