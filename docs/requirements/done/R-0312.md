# R-0312 — Developer shortcut on every screen without a status indicator

1. Status: done
2. Updated: 2026-10-27
3. Related: UC-006, UC-114 and UC-119 in the [UC catalogue](../../use-cases.md); follows [R-0311](R-0311.md).
4. Primary area: [A03](../areas.md#a03), screens and shared UI language.
5. Dependencies: A01 entry/menu navigation and existing Settings persistence; A05 map hover remains unchanged.
6. Origin: the user requested removal of the DEV status indication and F3 support on every game screen, explicitly including the welcome page, on 2026-10-27.

## 1. Summary

1. Make the developer-mode shortcut consistent throughout the application. A player should not need to enter the map or Settings before switching it.
2. Keep the status bar focused on game information. The Settings checkbox remains the visible indication of the saved preference.

## 2. Behavior

1. Bare F3 switches the same persisted preference on the welcome page, Settings, every other game screen and application-owned dialogs. It also works while a text field is focused, without editing its text or closing the dialog. Operating-system file pickers retain their own keyboard handling.
2. One physical press switches once, on release. Holding F3 or reopening a screen must not multiply the action. Modified F3 combinations remain untouched. Switching never issues a unit order, cancels a prepared move or changes game state.
3. Remove both the persistent DEV label and the temporary enabled/disabled notice from every status bar. Do not replace them with another notification. Settings continues to show the effective value immediately.
4. Preserve the default-off state, saved preference, normal descriptions, labelled coordinates, stationary-pointer refresh and map visibility rules agreed in R-0311.

## 3. Implementation steps

1. Follow the [package map](../../architecture.md): move the existing shortcut filter from individual screens to the main window and shared dialog construction. Reuse `ViewUtil`, `MainStageBuilder`, `AbstractMessageWindow` and `DeveloperModeShortcut`; keep all behavior in GUI packages.
2. Remove the status label, timer, mode dependency and unused translations from status-bar owners. Retain the shared `DeveloperMode` preference and hover listeners.
3. Extend TC84 for the welcome/menu and other screens, direct-created and injected dialogs, focused text input and repeated screen entry. Replace indicator assertions with explicit absence checks. Preserve existing map, Settings, persistence and unit-command checks. Run all model/JUnit, targeted Docker/Xvfb, fixed smoke, shared Java formatting and documentation acceptance under the [functional contract](../../functional-tests.md).
4. Implemented and accepted locally on 2026-10-27 after model/JUnit, targeted UI, fixed smoke, source review and documentation checks. Exact selections, failed attempts and passing results belong to the [dated evidence](../../functional-tests.md#r-0312-global-developer-shortcut-2026-10-27). The transient JavaFX pulse error from the first smoke was not reproduced and is not claimed as repaired. Native macOS keyboard behavior and remote publication were not checked.
