## 1. Summary

1. Developers need a mandatory local check that supports rapid collaboration without waiting for the hour-long UI regression after every change.
2. The former policy required full local regression. The existing runner already freezes sources, isolates Docker tests and validates complete reports.
3. Change verification cadence and select existing smoke scenarios; preserve all existing gameplay assertions, full regression and publication gates.

## 2. Behavior

1. Before every commit, including documentation-only commits, all fast model/JUnit tests, support checks and ten representative UI scenarios must pass locally. Failure, missing reports, skips or timeout prevents committing.
2. The complete gate must finish within five minutes. Report actual source identity, selection, counts, duration and evidence; do not infer performance from an old run.
3. Every push to main starts complete regression in GitHub Actions. Ordinary work does not wait for, inspect or repair that regression; only the user's explicit instruction starts repair, including overnight work. A remote failure does not block the next locally checked task.
4. Publication still requires successful checks for the exact published revision. A smoke pass is not full-regression or publication evidence. No automatic monitor or repair schedule is introduced.

## 3. Implementation steps

1. Add `--smoke` to the existing isolated verifier and a manifest of ten existing methods; discover all model/support tests, preserve strict XML validation and enforce the 300-second budget. No Java or game behavior changes.
2. Align AGENTS.md, publishing, functional-test, completion and module documentation; make the existing functional CI job run for every main push while retaining publication dependencies.
3. Test selection, incomplete/failing reports and the budget in the verifier unit suite; run the actual Docker gate through the completion runner, documentation checks and strict MkDocs.
4. Implemented and locally accepted: all 4,720 model tests, ten selected UI scenarios and nine support checks passed in 280.289 seconds, with zero failures/errors/skips; runner and documentation checks passed.
