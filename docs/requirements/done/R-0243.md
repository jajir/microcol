## 1. Summary

1. The main agent should resume when a worker, Docker test or CI run finishes, without repeated cloud-model calls just to check progress.
2. On 2026-10-18, both installed Codex CLIs successfully queued unique messages into the exact idle desktop test task. This proves delivery with the app running, not delivery across app shutdown or host sleep.
3. Own one small host-side completion runner and its use in the three existing workflows. Preserve all model/runtime limits, test selections, review, repair and publication gates. No additional service or dependency is required.

## 2. Behavior

1. The caller supplies the exact receiving task UUID, working directory, bounded timeout and worker job, Docker arguments or CI run identity. Dispatch returns a unique evidence directory; local waiting does not request model inference.
2. Success, command failure, startup failure, cancellation or deadline produces a saved result and one bounded Codex queue attempt. The message identifies the run, outcome and evidence; it never declares acceptance or publication solely from command completion.
3. A Docker deadline stops only its uniquely named container and retains available reports. A worker retains its own cleanup and cumulative budgets. A CI watcher observes an exact run and commit; a watcher deadline does not cancel remote CI or imply CI failed.
4. Invalid inputs fail before dispatch. A failed notification is visible in saved evidence and must not silently change the command outcome or trigger automatic duplicate delivery. App closure, host sleep and forced supervisor termination remain explicit limits.
