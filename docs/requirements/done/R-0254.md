## 1. Summary

1. Finish routine work without the additional remote CI wait after complete successful local verification.
2. Previously the completion workflow required remote deployment and distribution checks after every push.
3. This changes agent workflow guidance, not executable CI, game behavior or the evidence from the failed four-container experiment.

## 2. Behavior

1. A game change with complete successful local model and Docker UI results, required local checks and review can be committed, pushed and reported complete without waiting for CI.
2. Missing, failing, errored, skipped or timed-out local checks still block acceptance. Targeted selection alone is insufficient for final game acceptance.
3. Documentation-only work runs its documented local checks and strict MkDocs. It does not trigger a mandatory local game regression.
4. Remote workflows may run automatically, but agents do not watch or repair them unless explicitly asked for CI work or verified publication. Unverified publication is reported as unverified, never as a new downloadable build.

2. Preserve configured CI jobs and release gates; no Java, fixture, test assertion or Docker execution change.
3. Verify documentation, completion-runner and worker-launcher checks without inference, strict MkDocs, links and the scoped diff. No full UI run is required for this guidance-only change.
4. Current result: implemented and locally verified: 19 completion-runner, 21 worker-launcher and 9 documentation checks passed, plus strict MkDocs. No executable behavior changed. Publication verification is explicitly not required by this policy.
