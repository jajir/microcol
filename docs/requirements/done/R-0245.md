## 1. Summary

1. Make the implementation choice predictable: use Codex unless the user requests Claude Code or the configured local model.
2. Keep all three options documented without changing installed runtimes, model preferences, tests or review requirements.

## 2. Behavior

1. A new request without an execution choice uses Codex. A request selecting Claude or the local model uses that option within its stated scope; later requests still default to Codex unless the user changes the general policy.
2. A selected alternative remains selected during its task. Its failure or unavailability is reported; it does not silently trigger a switch to another option or a new installation.
3. All routes preserve requirements, required checks, caller review, repair limits, completion callbacks and publication. Local medium/high profiles and their budgets apply only when local work is selected.

## 3. Implementation steps

1. Own the current choice and examples in the existing AI operating page. Align AGENTS.md, the local-worker skill, requirement instructions and the implementation handoff; retain dated experiment history with an explicit supersession note.
2. Link the policy from the documentation index, backlog and Headroom page. Distinguish execution choice from proxy routing, model settings and parallel delegation.
3. Check the no-choice/Codex, explicit Claude, explicit local and later-request cases in the written rules. Run the documented portable checks and strict MkDocs; review rendered pages and links, then commit and verify the existing publication workflow.

4. Implemented and locally accepted on 2026-10-18. [Dated evidence](../../ai/local-qwen.md#codex-default-policy-verification-2026-10-18) records the policy-case review, 49 passing checks and strict documentation build. CI and publication remain independently verified.
