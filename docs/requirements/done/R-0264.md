# R-0264 — Exempt documentation-only commits from local game tests

1. Status: done
2. Updated: 2026-10-24
3. Related: P31/P32; [local acceptance policy](../../publishing.md#local-acceptance-policy); workflow-only agreement, no gameplay UC change.
4. Dependencies: existing documentation consistency checks, strict MkDocs and the game-test gate.
5. Primary area: [A03](../areas.md#a03), supporting developer workflow.
6. Related areas: all areas use the same commit-scope distinction; gameplay ownership is unchanged.
7. Origin: explicit user instruction on 2026-10-24 to stop running unit and smoke tests before commits containing only documentation or requirements.

## 1. Summary

1. Documentation changes should complete without waiting for game tests that exercise unchanged executable content.
2. The earlier policy required model/JUnit and Docker/Xvfb smoke before every commit. This agreement replaces that requirement only for documentation-only commits.
3. Update the shared instructions and current workflow documentation. Test runners, smoke selection, remote CI and publication gates are outside this change.

## 2. Behavior

1. A commit containing only documentation, requirement analyses, documentation illustrations or textual project instructions requires documentation consistency checks, strict MkDocs and review. It requires neither model/JUnit tests nor the Docker/Xvfb smoke gate.
2. Determine scope from the actual proposed commit, not only file extensions or unrelated uncommitted work. Changes to executable code, tests, runtime assets/data or build/runtime/CI configuration retain the existing game gate, including mixed commits.
3. Tooling tests run when their tooling changes, not merely its documentation. After applicable checks and review, the authorized commit/push workflow continues. Remote regression and publication remain governed by their existing rules; historical results are not rewritten.

## 3. Implementation steps

1. Reconcile `AGENTS.md`, the authoritative publishing policy, the functional-test introduction, completion-runner instructions and active documentation-capture requirements. Keep one policy owner and link to it.
2. Review the actual staged scope, run `scripts/docs` test discovery and strict MkDocs, and preserve unrelated working-tree changes. No runtime implementation or additional test mechanism is needed.
3. Current result: the documentation-only exception and its boundaries are recorded consistently. Acceptance is recorded in [documentation evidence](../../publishing.md#documentation-only-acceptance-2026-10-24); no remote publication result is claimed.
