# R-0316 — One paper button style with an icon for every action

1. Status: done
2. Updated: 2026-10-27
3. Primary area: [A03](../areas.md#a03), shared controls and visual language.
4. Related: UC-006, UC-114/115/119; [visual contract](../../graphics.md#soucasne-zadani-vzhledu), [UX](../../ux.md).
5. Dependencies: A01 menu/settings/session navigation; A02 new-game and campaign choices; A04 saving and loading; A05 unit/editor actions; A06 Europe, transport and trade; A07 colony actions; A08 diplomatic decisions; A09 military orders; A10 Congress and independence. Existing actions and validation remain with their current owners.
6. Origin: the user explicitly requested all buttons to use the main game menu's appearance, a single shared implementation, and a matching icon for each button; obsolete visual tests must follow the new agreement.

## 1. Summary

1. Players currently see paper buttons in the game menu and wooden buttons in dialogs, Congress, reports and other screens. Shared layout R-0307 did not replace the old default skin.
2. Use the existing main toolbar as the visual reference for all application-owned action buttons, including ordinary actions, toggle/navigation buttons, icon-only actions and drop-down buttons.
3. Every action button has an appropriate icon. Reuse matching existing artwork and draw missing symbols in the same ink, olive accent and geometry. Native operating-system file-picker controls are outside the application's styling ownership.

## 2. Behavior

1. Main/opening menus, dialogs, Congress, statistics, colony, Europe, trade, settings, campaign, free play and editor use one paper background, hand-drawn frame, Regular 14 typography and shared interaction states.
2. Each button shows a meaningful action or object icon, including buttons created dynamically. Preserve existing labels, tooltips, accessible names, keyboard activation, focus, selection and disabled behavior. No localized-text guessing determines an icon.
3. Buttons and content remain reachable at smaller supported windows; labels and icons must not overlap or be clipped. Actions, cancel paths, quantities, costs, saves and turn progression stay unchanged.
4. Existing checkbox/radio selection indicators remain form-control indicators; the shared design of those controls follows the existing Settings controls. Buttons used to select ships retain their ship icon inside the shared frame.

## 3. Implementation steps

1. Inventory application-owned button creation, factories, CSS overrides and tests. GUI utilities own common presentation; individual screens select the action icon and keep their existing handlers. No game-rule or model dependency changes.
2. Make the existing paper CSS the shared default, remove the wooden skin path and local button-face overrides, and centralize icon-bearing button creation. Preserve current toolbar/menu artwork and export missing icons from a shared SVG atlas.
3. Update stable TC83 visual checks and affected page objects, add coverage of shared icon/style behavior in dialogs, Congress, reports and dynamic controls, and retain existing gameplay assertions. Run all model/JUnit, selected Docker/Xvfb journeys, fixed smoke/support, shared Java formatter, documentation checks and strict MkDocs before commit/push.
4. Current result: all 197 production button creation sites use the shared factory and explicit icons. Common CSS and the SVG atlas replace the wooden path. Acceptance includes dragging with the new ship icon, Escape from the colony toolbar, and actual scrolling before test gestures in the framed screens. Verification is recorded in the [functional evidence](../../functional-tests.md#r-0316-shared-paper-buttons-and-action-icons-2026-10-27); local acceptance passed on 2026-10-27. Remote regression and distribution publication were not checked in this task.

## 4. Open questions

1. None. The user has selected the reference and authorized matching missing icons and test updates.
