## 1. Summary

1. A player needs a road order that produces a saved, visible improvement and shortens valid travel.
2. The 2026-10-17 catalogue at `f10e3f49` records a road capability flag but no executable road order or persisted road state. This is a documented source assessment, not a runtime test.
3. Scope: build one road, persist it, charge once and apply its accepted one-third movement effect through shared MOVE-003 cost, path and range calculations from [R-0125](R-0125.md). That shared terrain-cost contract must be implemented before this requirement can become ready or done. This requirement does not own the full terrain-cost overhaul or road production bonuses [R-0122](R-0122.md).

## 2. Behavior

1. Under the [2026-10-17 terrain decision](../../gap-analysis.md#exploration-work-and-transport), the current player can order an eligible pioneer with at least 20 tools and positive movement to build a road on any terrain except sea, including a coastal colony tile, if no road exists. Sea tiles reject the order; UI explains invalid or stale choices.
2. Start spends current movement; ordinary work completes after two later owner updates, hardy work after one. Completion records one road and spends exactly 20 tools once. A connected road segment costs one-third movement in either direction under the [accepted movement rule](../../gap-analysis.md#exploration-work-and-transport); execution, path and displayed range must agree for acceptance.
3. Missing tools, an existing road, an ineligible unit or a stale order rejects without mutation. Explicit cancel discards unfinished work without charge or road and does not refund movement. Repeating the order cannot create another road or tool charge.
4. Save and Continue preserve unfinished work and the completed road without repeating completion or moving a unit during loading.

## 3. Implementation steps

1. Model/map own admission and persisted road state. Add a road set to `WorldMap`/`WorldMapPo`, valid only on non-sea tiles, and expose it through terrain/map queries for rendering. Forests, plowed fields and colony tiles remain legal road targets under the existing any-non-sea rule. Road production bonuses remain R-0122.
2. Reuse the plow/clear lifecycle for a build-road order: eligible live current-owner pioneer with at least 20 tools, no other order and positive exact movement; ordinary countdown two owner updates, hardy countdown one, first progress next update. Add authoritative problem/cancel operations, action serialization, tool completion guard and stale-target handling. Cancel or stale completion cannot create a road or charge tools; completed roads and progress survive Continue.
3. Extend the R-0125 shared entry-cost boundary to accept origin and destination. A land step gets the one-third discount only when both endpoints have a road; disconnected endpoints retain ordinary terrain cost. Use it in actual movement, route search, path affordability, range and step preview. Ships keep their existing water/port cost. River integration remains R-0126.
4. Audit movement/selection consumers of floor-valued `getActionPoints`: move controls, M-key, unit cycling, map selection and AI must use exact positive thirds so a unit can spend its final third. Work/fortify admission follows the already accepted positive-movement rule. Do not change whole-point costs for boarding, combat or other unrelated actions.
5. Add visible road rendering and dedicated build/cancel controls using existing event/controller patterns and both supported languages. Show prerequisites and expected work outcome, consume current movement on direct start, display active progress, allow explicit cancellation, and explain rejection without partial effects. Reuse current visual/audio/UX guidelines; do not reuse the misleading clear-forest icon for roads.
6. Reserve `TC_88_F79_road_construction_test` for UC-021/UC-016 and `TC_89_F80_road_travel_test` for UC-012. Add model boundaries for every non-sea terrain, sea/lake rejection, 19/20 tools, ordinary/hardy timing, cancellation, stale/repeated/concurrent completion and persistence. Player paths cover build/cancel/Continue and connected/disconnected road travel in both directions, exact fractional remaining movement, route/range feedback and final-third availability. Keep the functional source-contract and stable scenario IDs.
7. Main owns review, shared formatting and actual targeted Docker/model verification before acceptance. Preparation on 2026-10-19 found no missing user decision; implementation and acceptance are pending.
