# R-0274 — Selected hand-drawn terrain and resource icons

1. Status: done
2. Updated: 2026-10-25
3. Primary area: [A03](../areas.md#a03), shared visual language.
4. Related: [UC-114/119](../../use-cases.md), [R-0269](R-0269.md), [visual brief](../../graphics.md#soucasne-zadani-vzhledu).
5. Dependencies: existing terrain, resource and fog rules; shared map/reference image providers.
6. Related areas: A05 terrain/resource identity; no rule changes.
7. Origin: user selected red-marked T01–T14 from proposal 10, B01–B03 from proposal 09 and B04–B12 from proposal 08 on 2026-10-25, explicitly requesting in-game integration.

## 1. Summary

1. Replace placeholder terrain artwork and geometric resource markers with the 26 selected hand-drawn symbols, readable in 45-pixel map squares.
2. The current reference shares terrain images and resource painting with the map, but several terrain types reuse one picture and resources use generic shapes.
3. Deliver the selected motifs across existing consumers. Preserve map background colours so coast/fog transitions stay continuous; preserve forests, fields, roads, rivers, units and gameplay rules.

## 2. Behavior

1. Loading a game displays the selected terrain symbol for each known square; old random decorative whales or alternate terrain pictures cannot replace the selected symbol.
2. A known resource shows its selected pictorial icon in the upper-right area, with a strong outline and transparent surroundings. The terrain, roads and units remain distinguishable; unexplored squares reveal no icon.
3. Terrain previews and the illustrated Colonizopedia use the same images as the map. All 14 terrain kinds and 12 bonuses have their own image; English/Czech names and rule values remain unchanged.
4. Loading, saving, resource depletion, production and exploration retain existing rules. There is no additional user action or cancel path for this visual replacement.

## 3. Implementation steps

1. Trace the selected contours into a compact editable SVG atlas and export its runtime PNG with librsvg. Register it in `gui.image`; reuse the existing image cache and tile loader.
2. Use the selected terrain images consistently and replace geometric resource painting with the shared transparent icon. Retain existing coastline backgrounds and unrelated overlays.
3. Update existing TC_100_F91 reference checks and TC_91_F82/TC_88_F79 resource checks to inspect real selected artwork instead of legacy marker colours. Check the atlas identities/transparency and review Docker screenshots at tile size.
4. Apply the shared Java formatter. Run affected scenarios, source contract, all fast model/JUnit tests and the fixed Docker/Xvfb smoke gate; run documentation checks and strict MkDocs. Record actual results in the functional evidence before marking done.
5. Local acceptance and visual review are recorded in [the verification evidence](../../functional-tests.md#r-0274-selected-terrain-artwork-2026-10-25); publication remains independently verified.
