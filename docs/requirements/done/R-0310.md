## 1. Summary

1. A player starting Free game → Original world should be able to move the initially focused galleon immediately.
2. Confirmed on 2026-10-27 at `afc916327ea4e7f6a4b5d02bce4c1c66044e6ece`: `M` followed by a destination click and mouse dragging both leave the galleon at its starting tile. Both control scenarios pass after clicking an adjacent empty tile and then the ship; see the linked evidence.
3. On 2026-10-27 the user selected the repair and regression-test integration after the earlier reproduction-only request. The [repair evidence](../../functional-tests.md#r-0310-initial-free-play-movement-repair-2026-10-27) records successful local acceptance.

## 2. Behavior

1. Start a fresh Original world from the real Free game menu using default setup. Initial focus is on the galleon at `(45, 15)`.
2. Without reselecting a tile or unit, press `M` and click adjacent sea tile `(44, 15)`. The same galleon arrives there and leaves its original tile empty.
3. In a separate fresh game, drag the initially focused galleon from `(45, 15)` to `(44, 15)`. Movement succeeds without an earlier click elsewhere.
4. Control scenarios repeat each action after clicking empty tile `(45, 14)` and then the ship. Preserve the world, destination and command.
5. No turn advance, model mutation, loaded replacement world or direct selection injection may prepare these scenarios. Save compatibility and other maps are outside this reproduction.

6. The focused tile selects a human-owned unit even if a computer player acts first. Selection does not advance the turn or authorize movement during the computer turn. An empty focused tile leaves no unit selected; preserve an existing valid choice on the same tile.

The initial tile is focused while France's AI turn is active, so the current-player query selects no Dutch unit. Add an explicit-owner query in `Model` that reuses `UnitStorage` selection priorities; the UI requests the human player's unit. Preserve the existing current-player query, movement rules and valid selection. No new turn listener or timing dependency is needed.
2. Integrate the isolated `TC_193_F15_initial_ship_movement_test`: `TC_01` covers `M`, `TC_02` covers dragging, and `TC_03`/`TC_04` retain the reselection controls. Reuse the existing fixture, `@Start` and menu/page objects; expose the existing `GamePage.dragToLocation` action without removing its callers' verification. Add focused JUnit coverage for selection during the computer turn and empty-tile behavior. Keep the related toolbar and failed-turn page helpers aligned with the current frame and game-menu navigation, preserving their existing gameplay assertions.
3. Apply the shared formatter, run all model/JUnit tests, then TC193, affected national-turn/unit-order scenarios and `PageVerificationContractTest` in Docker/Xvfb, followed by the fixed smoke/support selection. Keep the previously failed reproductions as historical evidence; require successful movement in the integrated tests.
