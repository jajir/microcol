## 1. Summary

1. A player working silver, ore or mixed mineral land needs a finite deposit that can run out without changing the underlying terrain.
2. The 2026-10-17 catalogue source assessment at `f902be8a` reports no saved reserve or harvesting transition. It is not a runtime acceptance result.
3. This requirement owns depletion of an already represented deposit. [R-0127](R-0127.md) owns overlay identity and its initial yield; this requirement does not reimplement every resource bonus or ordinary field production.

## 2. Behavior

1. An explicitly identified silver deposit begins with 100 bonus units; a pure ore deposit begins with 200 and a mixed deposit with independent 200-silver and 200-ore reserves, under the [accepted provisional policy](../../gap-analysis.md#economy-production-and-education). Each actual mining update can extract no more bonus output than remains, and consumes only the bonus actually produced.
2. When one resource reserve reaches zero, only that resource’s mineral bonus ends, but the underlying terrain and any ordinary baseline output remain. A non-mining worker or an update with no mineral bonus output does not consume reserve. A last extraction smaller than the usual bonus stops at the remaining amount rather than producing a full bonus and going negative.
3. The field preview and actual production agree about an exhausted deposit. Invalid or stale production state cannot spend reserve without producing the corresponding mineral output. Inspecting the tile, changing jobs, saving or loading does not replenish it.
4. Save and Continue preserve the exact remaining reserve across multiple updates, including zero, without repeating an extraction. Whole UC-009 requires silver, ore and mixed examples; the earlier UC-008 overlay check alone does not establish depletion.

5. Agreed 2026-10-20 ([shared rule](../../gap-analysis.md#r-0128-refinement)): A pure silver deposit retains 100 bonus units and a pure ore deposit 200. A mixed deposit instead has two independent reserves: 200 silver and 200 ore. Extracting one resource never consumes the other: after all 200 silver bonus units are mined, all untouched 200 ore bonus units remain. Cap each actual bonus extraction by its own remaining reserve, retain baseline terrain production and persist both counts independently. No ore-first allocation of a shared reserve applies.

## 3. Implementation steps

1. Selected and refined on 2026-10-20. Keep reserve state beside resource identity in the existing `WorldMap`/`WorldMapPo` owners; use independent silver and ore quantities, validated against the overlay and map location. Initialize full reserves only when creating a deposit. Persist remaining quantities explicitly; reject missing/invalid required mineral data when loading, update bundled mineral maps/fixtures directly, and do not add save migrations or refill reserves during inspection/save/load.
2. `Colony.startTurn()` commits the current production snapshot; `ColonyField.countTurnProduction()` is not called by that path. Integrate extraction with the actual post-famine field production snapshot, using the same political snapshot as credited output and consuming each field's mineral bonus exactly once. Preview, job switching and production statistics remain read-only. Validate the extraction plan before applying it and preserve unchanged state on expected rejection.
3. Derive the mineral contribution from the shared job calculation with and without that mineral bonus, preserving the ordinary terrain and other applicable effects. Cap the final extra goods after profession/political modifiers by the matching remaining reserve, including the last partial unit; an expert must not multiply a final partial reserve into extra goods. Do not deduct the other mineral or consume non-mining/zero output. Keep explicit overlay identity and non-mineral production intact when a reserve is exhausted; the overlay remains the owner of mineral identity and ordinary road eligibility.
4. Reuse current terrain/field/job previews and player controls; they must show the same depleted/partial output as the actual turn. Implement named UC-009 scenarios in `TC_102_F93_mineral_depletion_test` with the existing fixture, `@Start`, page-object and explicit verification conventions. Prepare near-boundary deposits before loading, then mine through legal player turns and use disk Save/Continue; do not manipulate running state to force depletion. Pure silver, pure ore and both independent mixed reserves need player coverage.
5. Model coverage includes full initial reserves (100/200/200+200), independent mixed depletion, last partial extraction with ordinary and specialist workers, zero/non-mining output, exhausted baseline, read-only previews/job changes, post-famine actual production, positive/zero Save/Continue continuity and rejection of invalid/missing/negative/inconsistent stored reserve data. Preserve all existing resource, road, production, education and save fixtures/tests. Run the agreed complete model selection plus relevant UI scenarios after each change; full batch acceptance remains pending.
