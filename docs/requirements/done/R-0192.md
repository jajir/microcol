# R-0192 — Apply every revolution loss condition before victory

1. Status: done
2. Updated: 2026-10-23
3. Related: P24; [GOV-020/021/022](../../gap-analysis.md#government-taxation-and-independence), GOV-019 precedence; [UC-085](../../use-cases.md#politika-a-valka-za-nezavislost) (Hra).
4. Dependencies: rebellion set [R-0191](R-0191.md), colony capture/destruction [R-0096](R-0096.md), affiliation/support residents [R-0100](R-0100.md), real Crown ownership [R-0186](R-0186.md).
5. Primary area: [A10](../areas.md#a10).
6. Related areas: A07 colony resident count; A09 occupation/capture; A04 terminal result once.
7. Origin: accepted four-way rebellion defeat residual; ordinary free-play zero-colony evaluator is not its replacement.

## 1. Summary

1. A rebellion can be lost by territory or population control even while a few rebel units still fight.
2. This requirement owns loss evaluation and ordering, preserving R-0191's separate victory condition.

## 2. Behavior

1. After declaration, lose when (a) no rebellion-set colony survives, (b) all surviving members are Crown-held, (c) all surviving coastal members are Crown-held **or none survives**, or (d) Crown-held members contain at least 90% of all current internal residents in the surviving set. A zero population denominator is a loss.
2. Count actual residents on both sides, not declaration-time population or outside troops. Ninety of 100 Crown-held residents loses; 89 does not on that condition alone. On any completed action/update, evaluate these conditions **before** R-0191 victory and before R-0190 attempts delivery to a port that no longer exists.
3. Persist and report one reason/result, not multiple losses or a later victory. Save/Continue does not repeat the end event. UC-085 checks each condition independently, inland-only survival, 89/90 boundary, zero denominator, capture/recovery and same-action precedence.

## 3. Implementation steps

1. Model uses R-0191 rebellion-set membership, real colony ownership and internal resident counts to produce one loss result before checking victory. Avoid a fixed 15-turn grace period or global zero-colony shortcut for a declared revolution.
2. Proposed model/UC-085 checks cover all four conditions, precise population denominator, ordering and reload under the [functional contract](../../functional-tests.md).
3. Selected and refined 2026-10-23. Establish the shared stable colony-membership state required by R-0191 in this change: snapshot at declaration, add later rebel acquisitions/foundings, retain membership through occupation and remove destroyed members. Persist the state and one terminal reason; R-0191 will consume it without a duplicate tracker.
4. Integrate evaluation at completed gameplay action/update boundaries and before R-0190 delivery; do not end the game halfway through a capture or other atomic action. Reuse the existing game-over result and event flow, preserve campaign behavior unrelated to a declared rebellion, and prevent duplicate end events after load. Count only current internal residents of surviving members. Use exact integer comparisons for the 90 percent boundary.
5. Add TC157 for an actual player-visible loss and Continue behavior, with model checks for each condition, 89/90 percent, zero residents, acquisition/capture/destruction membership, and loss before a pending intervention. Main runs all JUnit plus selected Docker/Xvfb scenarios and complete local batch acceptance. Victory remains R-0191; final combined precedence acceptance follows its implementation.

6. Implementation and targeted checks recorded in [functional evidence](../../functional-tests.md#r-0192-targeted-rebellion-loss-verification-2026-10-23). Full batch acceptance and combined victory precedence remain pending.
