## 1. Summary

1. A player should recognize a special resource on a tile and see its agreed effect in both yield preview and actual work.
2. The 2026-10-17 catalogue source assessment at `f902be8a` finds no special-resource overlay in stored tiles or the terrain-output calculation. This is source inspection, not runtime acceptance.
3. This requirement owns resource identity, display, save/Continue and output additions. It does not own finite reserve consumption [R-0128](R-0128.md), road construction [R-0121](R-0121.md) or road bonuses [R-0122](R-0122.md).

## 2. Behavior

1. Under the [2026-10-19 placement decision](../../gap-analysis.md#economy-production-and-education), land overlays are valid on any land terrain and fishery only on ocean/lake (not the high-seas lane). A map tile can show and retain the documented silver, ore, mixed mineral, trapping, game, oasis, prime crop, prime timber, prime food and fishery overlay. The player sees the overlay and its matching field yield when that tile is known; loading preserves it without duplicating output.
2. Apply an explicitly printed aid-card resource bonus where present. Otherwise add 2 to the named output: silver; ore; both ore and silver for mixed minerals; fur for trapping; lumber for prime timber; the named crop for prime crop; food for game, oasis and prime food; fish for fishery. Place the overlay before job modifiers in the [accepted production order](../../gap-analysis.md#economy-production-and-education). Only an explicit overlay can introduce its named output on a zero-baseline tile.
3. A tile without an overlay receives no overlay addition. Preview and next production update agree; selecting another commodity does not claim the resource's bonus. A silver-deposit tile remains explicitly identifiable for the mountain road bonus in [R-0122](R-0122.md), without inferring it from a nonzero yield.
4. Save and Continue retain overlay kind and resulting yield; merely opening a tile or restoring a save does not mine or replenish it. Finite ore/silver/mixed reserves and last-extraction limits are separately accepted with [R-0128](R-0128.md), so UC-008 output can be accepted without claiming UC-009 depletion.

## 3. Implementation steps

1. Add one resource-overlay identity per tile in the existing model/map/store owners, with explicit NONE, SILVER, ORE, MIXED_MINERALS, TRAPPING, GAME, OASIS, PRIME_COTTON, PRIME_TOBACCO, PRIME_SUGAR, PRIME_TIMBER, PRIME_FOOD and FISHERY identities. Map food/fish to existing CORN; mixed minerals adds to both ORE and SILVER. Keep identity explicit for R-0122/R-0128; do not infer a deposit from yield or decide mixed-deposit road eligibility here.
2. Each matching resource adds 2 before existing flat plow/river and later profession/percentage modifiers; nonmatching outputs are unchanged. Only this matching overlay can introduce output on a zero baseline. The local aid-card 4 production chart is baseline terrain data, not an overlay multiplier; preparation inspected PDF pages 132–135 and resource descriptions 24–25 without finding a numeric override. Preserve the accepted printed-bonus precedence if contrary evidence is found, rather than silently changing the rule.
3. Persist an optional complete resource row block following existing map improvements. Validate known codes, bounds and the agreed land versus ocean/lake boundary before exposing map state. Absence means no overlay; malformed present rows reject. No migration, depletion, generation or editor controls. Load preserves identity without extraction, replenishment or goods production.
4. Terrain.getTerrainProduction must incorporate the overlay before its current modifier pipeline, so existing field preview and actual colony production use one result. Review food-field selection and AI planning consumers; do not add independent UI/AI yield rules. Render a readable kind-specific marker on known tiles and provide the named resource in existing tile inspection in both languages; unknown tiles must not leak identity.
5. Add model coverage for all twelve kinds and both outputs of mixed minerals, matching zero-base introduction, nonmatching/no-overlay guards, plow/river composition, explicit silver identity, invalid codes/terrain, and save/load. Add TC_91_F82_resource_overlays_test (UC-008): authored known/unknown markers and inspection, prime-sugar preview versus actual next-turn stock, stable identity and unchanged stock through Continue. Reuse existing field-job/production/fog page helpers and current-schema fixtures; assertions only in dedicated page verification methods. Do not replace an occupied colony field's terrain or move a test unit onto a ship unintentionally.
6. Follow architecture, graphics/UX and functional contracts and the shared Java formatter profile. Main owns refinement, review, actual targeted model/Docker tests and documentation. R-0065 owns generated placement; R-0128 owns finite reserves. Accepted on the isolated batch branch on 2026-10-19; see [verification](../../functional-tests.md#r-0127-resource-overlays-2026-10-19).
