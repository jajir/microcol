# R-0438 — Common alignment axis in Settings

1. Status: done
2. Updated: 2026-11-09
3. Related: UC-119 (Regrese), SUPPORT-001; [UX rules](../../ux.md).
4. Dependencies: existing Settings controls, localization and menu/game hosts.
5. Primary area: [A03](../areas.md#a03).
6. Related areas: A01 menu navigation; A04 existing preference persistence.
7. Origin: User selected visual proposal A and requested implementation on 2026-11-09.

## 1. Summary

1. Make Settings easy to scan by placing every caption to the left of one common axis and every input to its right, matching accepted proposal A.
2. Keep the existing hand-drawn controls, settings, ordering and return paths.

## 2. Behavior

1. Opening Settings from the menu or a running game shows right-aligned captions in an equally wide column; radio buttons, checkboxes and equal-length sliders begin after the same gap. The guide line itself is not drawn.
2. Long English and Czech captions wrap before the axis without clipping or overlapping another row. A small window scrolls the content while the title and return action stay available.
3. Clicking a checkbox caption still toggles that setting. Tab, Space, arrows, slider dragging, language changes and immediate preference persistence keep their existing behavior. Back and Escape keep their existing destinations; no new Apply or Cancel action is added.
4. Keyboard shortcuts use the input column; developer settings retain their heading and description. No new game rule or illustration is introduced.

## 3. Implementation steps

1. Keep ownership in `gui.screen.setting`; share a small row helper and scoped Settings CSS. Preserve controls and event bindings; keep checkbox accessible names and associate the separate caption with its control.
2. Extend `FramedSettingsPage` geometry checks and TC_84/F75 scenarios for English/Czech, both hosts, small windows, caption clicking and retained input behavior. Preserve existing assertions and stable scenario IDs.
3. Apply the shared Java formatter; run all model/JUnit tests, targeted TC_84 and page source contract in Docker/Xvfb, fixed smoke/support, documentation consistency and strict MkDocs. Record actual results in [functional evidence](../../functional-tests.md#r-0438-settings-common-axis-2026-11-09).

4. Implemented and locally accepted on 2026-11-09: 5,116 model/JUnit tests, 18 targeted UI/source-contract tests and 21 fixed smoke/support tests passed without failures, errors or skips. Automated English/Czech screenshots in both hosts were reviewed; see the linked functional evidence.
