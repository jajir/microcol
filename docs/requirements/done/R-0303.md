## 1. Summary

1. Run model/JUnit tests once before targeted UI and a separate seven-minute smoke phase.
2. Before this change the smoke command repeated all model/JUnit tests alongside support tests and ten fixed UI scenarios. Reuse the existing verifier to separate these phases.
3. Keep this change limited to the existing entry points, their tests and the authoritative instructions. Remote regression is outside ordinary task completion.

## 2. Behavior

1. For a behavior change, run and debug all model/JUnit tests, verify targeted UI scenarios, run smoke, then review and integrate into `main`. The model phase includes every existing model test, including ConnectorTest; smoke contains only the existing support tests and ten fixed UI scenarios. Both selections require complete validated reports; neither phase alone establishes acceptance. Tooling-only changes use their tooling tests before the gate; documentation-only changes retain the existing exemption.
2. Both direct and callback smoke entry points allow 420 seconds after acquiring the local lock, including recovery, preparation, tests, reports and cleanup. Waiting for the lock is separate and can extend wall-clock waiting.
3. A complete passing run at 361 or 420 seconds is eligible for acceptance; a run at 421 seconds fails. Missing, failed or skipped required tests still block integration.
4. The callback watchdog allows 480 seconds for execution and cleanup, without extending acceptance. Unchanged tested source and selection may reuse passing earlier-phase results. Historical outcomes and limits remain unchanged.

## 3. Implementation steps

1. Add mutually exclusive `--model` and `--smoke` selections to the existing verifier; keep default full verification unchanged. Use the existing inventory, explicit Maven selectors and report validation for both modes. Update the shell smoke budget, verifier deadline/help/manifest and callback cap together. No new runner or dependency.
2. Test that model-only execution includes ConnectorTest and starts no UI group, while smoke selects support and named UI methods with no model test. Reject combined mode flags. Update the existing simulated-clock boundary test and entry-point agreement test. Run both affected Python test suites and the shell syntax check.
3. Align `AGENTS.md`, publishing, functional-test and callback instructions. Run documentation consistency checks, strict MkDocs and both Docker/Xvfb phases on the isolated source. Tooling-only scope needs no targeted gameplay scenario.
4. Implementation, review and required local acceptance are complete on the integrated source. All 4,764 model/JUnit tests and 21 separate UI/support checks passed without failures, errors or skips. Remote regression and publication remain independently unverified. See [execution evidence](../../functional-tests.md#r-0303-separate-model-and-smoke-phases-2026-10-26).
