1. Status: done
2. Updated: 2026-10-25
3. Related: P27/P28 in the [implementation plan](../../implementation-plan.md), [shared UX guidelines](../../ux.md), [visual brief](../../graphics.md#soucasne-zadani-vzhledu); presentation follow-up for UC-015/017/018/025/038/066 in the [use-case catalogue](../../use-cases.md), with existing gameplay acceptance retained.
4. Dependencies: existing context-menu actions and keyboard handlers; the unit-action placement proposed by R-0270 is separate work.
5. Primary area: [A03](../areas.md#a03), consistent shared controls and readable action shortcuts.
6. Related areas: A05 owns unit orders and equipment, A06 European-port actions, A07 colony work and production. Their rules and available actions remain authoritative.
7. Origin: user request on 2026-10-25 to replace the system-looking context menu with a drawn game menu and show shortcuts as highlighted keys instead of parenthesized label text.

## 1. Summary

1. A player opening a context menu should see the same paper-and-ballpoint visual language as the game, recognize each action immediately and discover its existing keyboard shortcut.
2. Source inspection on 2026-10-25 at `fb6ee004765c15253691fb26ba456dc447b2784e` found JavaFX context menus for colony fields, workers/buildings, colonists outside a colony and units on the European pier. Shared CSS includes white menu rows and blue focus; several toolbar translations embed shortcuts in parentheses. These observations are not a runtime visual test.
3. This requirement owns shared menu presentation and honest shortcut display. Moving toolbar commands into a unit menu belongs to R-0270. Adding new shortcuts, changing game rules, save data or unrelated toolbar tooltips is outside this change.

## 2. Behavior

1. Opening an existing context menu by mouse or its supported keyboard route displays a compact paper-colored menu with drawn outlines, the shared palette and Playpen Sans 14 at normal weight. Preserve the action order, localized names and existing prerequisites.
2. Each action occupies one readable row. Its name is on the left; when a shortcut actually works for that action in the current screen, show it separately on the right as a clearly outlined key or key combination. Do not repeat it in parentheses in the action name. Actions without a shortcut have no invented key or placeholder.
3. The key outline/background provides emphasis without bolding or changing the agreed font. Keep action text, keyboard focus and temporarily unavailable actions legible; unavailable actions remain governed by the [shared UX rule](../../ux.md#kdy-akci-skryt-a-kdy-vysvetlit-jeji-nedostupnost).
4. Preserve mouse selection, keyboard navigation, activation and Escape/outside-click dismissal. Opening, moving focus or closing the menu does not perform an action. Invoking an action preserves its existing confirmation, cancellation, model validation and outcome feedback.
5. A displayed shortcut must invoke the same action on the same object and obey the same availability conditions as clicking that row. A shortcut belonging only to the map screen must not appear as usable in Europe or a colony. Preserve working keyboard shortcuts and do not introduce duplicate dispatch.
6. Check Czech and English labels, long action names, disabled rows and menus near window edges at 1000×700 and 1280×850. Text and shortcut must not overlap or be clipped. The future menu in R-0270 should reuse this presentation when selected for development.
