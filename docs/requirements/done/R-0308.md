# R-0308 — Opening-menu buttons fit their contents

1. Status: done
2. Updated: 2026-10-27
3. Related: UC-115/119, [opening-menu appearance](../../graphics.md#opening-menu-r-0297).
4. Dependencies: [R-0297](R-0297.md) supplies the shared toolbar style, icons, actions and compact labels.
5. Primary area: [A03](../areas.md#a03), screens and shared UI language.
6. Related areas: A02 supplies existing new-game actions; A04 supplies Continue and recovery. No action or rule changes.
7. Origin: after comparing the opening menu with the map toolbar, the user requested content-sized opening-menu buttons and direct publication to main on 2026-10-27.

## 1. Summary

1. Opening-menu buttons should end shortly after their icon and translated label instead of sharing a fixed 300-pixel width.
2. At `afc91632`, the opening menu stretches every button to its fixed-width column. The shared font, padding and frame already match the map toolbar.
3. Change only opening-menu sizing. Preserve its single column, shared left edge, button height, order, artwork and actions.

## 2. Behavior

1. Opening the menu gives each button the width required by its icon, full label and existing padding. Short names have shorter buttons; long names have longer buttons.
2. Switching between English and Czech recalculates widths. Enlarging the window does not stretch short buttons to match long ones.
3. If the available column becomes too narrow for a complete label, that label hides without wrapping or ellipsis. Its icon, tooltip and accessible name remain available; widening restores the full label and content-sized width.
4. Existing enabled/disabled states, focus feedback, keyboard activation, navigation, Continue and exit behavior remain unchanged. Resizing or changing language does not alter game state.

## 3. Implementation steps

1. Keep ownership in `gui.screen.menu.ButtonsPanelView` and scoped `GameMenu.css`. Remove the fixed column width and cap each button at its measured content width.
2. Measure the full label even while it is hidden, and compare it with available column width rather than the button's temporarily reduced width. This avoids remaining stuck in icon-only mode after narrowing.
3. Update `WelcomePage.verifyOpeningControls` and existing `TC_83_F74_wooden_buttons_test.TC_01_menu_navigation_uses_wooden_buttons` to verify actual label-fit widths, common left edge/height, EN/CZ navigation and narrow-to-wide restoration. Preserve existing frame, palette, accessibility and keyboard checks.
4. Apply shared Java formatting, run all model/JUnit checks, targeted TC83/01, TC12 and page-contract checks in Docker/Xvfb, then the fixed smoke/support selection. Run documentation consistency checks and strict MkDocs. Isolate acceptance from unrelated working-tree changes; record actual results in the existing functional evidence page before completion.

5. Local acceptance and reviewed screenshots are recorded in the [functional evidence](../../functional-tests.md#r-0308-opening-menu-content-width-2026-10-27). Remote publication is verified separately.
