## 1. Summary

1. Decorative motion should make the lake surface feel alive without drawing another lake inside it. Its shoreline and meaningful map symbols must remain readable.
2. Deliver fourteen comparable proposals using the user's actual map crop, including units, fish and grid. Isolated artwork does not provide enough context for this choice.
3. On 2026-10-27 the user selected **K3 — Tři drobné kruhy** and explicitly authorized its implementation on lakes. Refinement is complete; the existing proposal remains the visual reference.

## 2. Behavior

1. Use the selected [K3 proposal](../../graphics-assets/lake-animations-2026-10-27/k3.gif): three small concentric ripples appear in succession, expand and fade completely during a six-second cycle. Black lines replace the filled miniature-lake silhouette; the shoreline stays fixed.
2. Preserve the existing sparse 5% selection and location/seed offsets. Reconsider selection only at the lake cycle boundary, so a selected animation finishes naturally. Fish and other meaningful attributes retain priority over decoration. Static terrain/help previews show the three visible rings instead of an empty frame or a miniature lake.
3. Preserve lake identity, coast shape, terrain colour, hidden-map behavior, navigation, Continue and gameplay outcomes. Motion remains cosmetic, quiet and understandable without sound. The player needs no new control or prerequisite and can continue using the existing animation-speed setting.
4. Ocean and High Seas keep their existing frames, timing, selection and direction marker. The other thirteen proposals remain archived alternatives.

## 3. Implementation steps

1. Source inspection at `121b08aa` identifies the cause: `ImageRandomProvider` gives lakes intermittent water decoration, but its animated frame branch covers only `OCEAN` and `HIGH_SEA`. Lakes fall back to `drawing-LAKE` in `terrain-symbols.svg`, a filled lake silhouette reused in the transparent decoration row. `PaintService` draws that silhouette over the lake background before coast overlays.
2. Append 120 transparent 45 px lake frames to the existing terrain atlas; reuse the six-second clock and saved-seed phase calculation. K3 uses centre (25, 19), ring start offsets 0/0.9/1.8 seconds, expansion duration 3.8 seconds, vertical radius 55% of horizontal radius and 1.6 px black strokes. Preserve the proposal's radius, fade and relative-opacity curves. Frame 50 supplies the static three-ring preview.
3. Follow the [package map](../../architecture.md): `gui.image` owns frame lookup and selection. Existing `MapManager` attribute guards and `PaintService` painter ordering keep coast/resource priority; they need no new responsibility. Export the SVG to the existing PNG. No model, AI, save-schema or package changes are needed.
4. Extend `SelectedTerrainArtworkTest`, `TerrainDecorationTest` and the existing `TC_80_F72_terrain_identity_test.TC_04_sparse_terrain_and_living_water_survive_pan_and_continue` journey through dedicated page verification methods. Cover three transparent rings, frame progression, rest/loop boundaries, coasts, resource priority, static rendering, hidden terrain and Continue. Apply shared Java formatting and all local acceptance phases required by the [functional contract](../../functional-tests.md).
