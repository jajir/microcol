# R-0301 — Keep generated rivers off coasts, hills and mountains

1. Status: done
2. Updated: 2026-10-26
3. Related: P02, SETUP-001 and UC-001 (Nastavení); [use cases](../../use-cases.md).

7. Origin: the user's new-game screenshot and explicit correction of river generation on 2026-10-26.

## 1. Summary

1. A player starting a generated world must see rivers on inland lowland terrain, never across hills, mountains or coastal squares.
2. The previous generator deliberately started on hills/mountains and ended beside water. This requirement replaces that placement rule; the river artwork is not the cause.
3. Scope is newly generated worlds. Loading an existing save or an authored scenario does not regenerate or alter its map.

## 2. Behavior

1. Starting a generated new world through the existing setup applies the placement rule to every river square, including its first and last square.
2. Hills and mountains cannot carry a river. Every river square has no water neighbour in any of the eight directions, so at least one dry square separates it from the sea, including at the end of the course.
3. A source lies on eligible flat land beside uplands. Rivers retain connected, nonbranching paths without loops, a large main course of 8–16 squares and small courses of 3–7 squares. They end beside the dry coastal buffer.
4. Seed reproducibility, climate/land-share choices, legal starting positions, river resources and save/Continue remain intact. If a candidate cannot fit a valid main river, the existing bounded generation retry/error path applies; no forbidden terrain is used as a fallback.

## 3. Implementation steps

1. Keep ownership in `model.generation.GeneratedWorldRivers`; filter sources and every next square against terrain and all eight water neighbours, and stop before the coastal buffer. Reuse the existing generation order and retry budget.
2. Update `GeneratedWorldTest` to check all nine climate/land-share combinations over fixed seeds, preserving topology, length, reproducibility and save checks. Add `GeneratedWorldRiversTest` for coast-only and upland-only rejection.
3. Extend `TC_122_F113_generated_world_test` through dedicated `FreePlaySetupPage.verifyGeneratedRiversAvoidCoastAndUplands` checks after starting and continuing a generated world. Keep its existing player steps and assertions.
4. Update the [shared generated-world rule](../../gap-analysis.md#r-0065-refinement), apply the shared formatter and run the targeted checks, mandatory model/smoke gate and documentation checks. Record actual results in [functional evidence](../../functional-tests.md#r-0301-generated-river-placement-2026-10-26); implementation and required local acceptance are complete.
