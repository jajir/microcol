## 1. Summary

1. Give the developer evidence of unclear interactions and obstacles through an autonomous AI playthrough, without requiring the developer to play the whole game.
2. Existing UI tests use Docker/Xvfb and prepared scenarios. This request adds an independent Maven project and runtime, with its own exploratory evidence and no dependency on TestFX, page objects or JUnit game scenarios.
3. The first deliverable is a working Codex-in-Docker session, desktop control, durable evidence and one documented 40-turn playthrough. It does not establish whole-game completion or human usability.

## 2. Behavior

1. The operator starts a separate UX session against an identified game build. Codex runs inside the same Linux container as the game and sees screenshots of the real X11 desktop.
2. The experienced strategy player uses generic mouse and keyboard tools, visible text and in-game help. It records its goal, expectation, observed result and the visible source of an inference. An unsupported guess is explicitly labeled.
3. Every desktop action preserves its input and resulting screenshot; errors, cancellation and time limits preserve previous evidence. The operator receives a final report or an explicit incomplete/error outcome, never an automatic usability pass.
4. A fresh isolated player profile protects existing saves. Sources, developer documentation, model state and regression instructions are absent from the runtime. Credentials are supplied at runtime and excluded from the image and evidence.
5. The task, refined by the user on 28 October 2026, is to enter a normal new game and play 40 complete human turns in that same game, making normal strategic decisions. Record the initial position and a screenshot-backed assessment after every completed turn; the initial position is not a completed turn. Save progress through the UI and deliver the result directory. Forty end-turn clicks alone do not prove 40 completed turns. Failure to reach a goal is a recorded observation, not permission to change the game or fabricate success.

## 3. Implementation steps

1. Add `microcol-ux-test` as an explicitly built Maven project. Reuse the UI environment image with a distinct entrypoint, packaged game, Codex CLI and standard X11 input/capture tools exposed through the official Python MCP SDK.
2. Keep lifecycle, player prompt, desktop tools and evidence in the new project. Reuse the completion supervisor for bounded Docker work, retaining exact originating task identity and independent result directories.
3. Verify input rejection and evidence persistence with portable tooling tests; verify actual X11 screenshots, focus, drag, Unicode text and MCP image transport in a dedicated self-check. Run and review the real 40-turn Codex playthrough. Check the consecutive per-turn notes and screenshots against the actual game progress; incomplete play is not acceptance. Run all required model/JUnit and fixed smoke gates plus documentation checks before integration.
4. Implementation and local acceptance are complete. The 40-turn save and screenshot ledger were independently reviewed; tooling, model/JUnit, live X11/MCP/JavaFX, fixed smoke and documentation gates passed. See the [operating instructions and dated evidence](../../ux-playtesting.md) for exact revisions, selections, results and limits. Publication remains independently verified.
