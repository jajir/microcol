2. Updated: 2026-10-17

## 1. Summary

1. A player needs plowing to improve only a suitable clear field and consume the documented tools exactly once.
2. Source inspection on 2026-10-17 at `f10e3f49`: the plow action completes after a countdown, but its admission does not check tools or forest and its completion does not deduct tools. The existing hardy pioneer has a two-update plow countdown. These are source observations, not acceptance results.
3. Scope: valid plow start, progress, cancellation, one completed field effect and one 20-tool charge. Clearing and road work belong to [R-0120](R-0120.md) and [R-0121](../R-0121.md); the shared terrain-output matrix remains in the rule catalogue.

## 2. Behavior

1. The current player selects a pioneer with at least 20 tools and positive movement on a suitable, clear, unplowed square, then starts plowing. The control explains why an invalid location or tool load is unavailable.
2. The start spends current movement; ordinary work completes after four later owner updates, hardy-pioneer work after two. On completion the field improves, its eligible positive crop outputs follow the [accepted plow bonus](../../gap-analysis.md#economy-production-and-education), and exactly 20 tools are consumed once.
3. A non-pioneer, 0–19 tools, forest, unsuitable or already plowed square rejects without progress or state change. Explicit cancel before completion discards progress, preserves terrain and tools and does not refund spent movement; a repeated completion cannot charge again.
4. If the target becomes invalid before completion (including another pioneer completing the same field), the work ends without a second field effect or tool charge; it must not block the turn.
5. Save and Continue retain the current countdown and completed terrain, without advancing work merely by loading. A completed improvement affects the following colony update under [R-0052](R-0052.md).

## 3. Implementation steps

1. The model validates the work preconditions and owns the action lifecycle, tool charge and terrain effect; UI reads model availability. Preserve the existing plow save shape where possible and align yield previews with actual production.
2. Guard direct `setActionType(plowField)` as well as shared availability. Reuse `TerrainType.isCanHaveField`, reject forest/existing fields, and implement explicit cancellation without refunding movement. Keep completion and its 20-tool charge together; retain the existing countdown save representation.
3. Replace the old field-production modifier with the agreed +1 for already-positive corn, sugar, cotton and tobacco outputs. Preserve other terrain, forest and resource rules and the colony-before-unit update sequence.
4. Cover model admission at 0/19/20/40/100 tools, ordinary/hardy timing, stale and repeated completion, cancellation, disk roundtrip, crop bonus and following-update production. Extend `TC_15_F05_plow_field_test` and `TC_18_F01_plow_field_test` with named rejection, cancellation, completion and Continue scenarios; prepare scoped fixtures without changing shared F01/F05 behavior. Keep existing action/turn tests valid by equipping their pioneers.
