## 1. Summary

1. When startup, local I/O or an unexpected operation fails, a player gets a usable next step and a local diagnostic record that supports reproduction.
2. Existing save rejection and turn-preparation recovery stay with R-0067/R-0052; this requirement owns shared release diagnostic capture and exposure.

## 2. Behavior

1. A failure report identifies game/build version, platform/runtime, time, operation and safe error context in a bounded persistent local log. The player can locate that log and learn whether retry, Continue, backup restore or reporting is appropriate; ordinary saved games remain unchanged merely by opening them.
2. Missing/unwritable log location or a logging failure does not overwrite a valid save or hide the original error. Sensitive local paths and player-entered content are handled deliberately in any shareable summary.
3. Test startup and selected recoverable save/resource failures, log rotation/retention and reportability on packaged runtimes. Current source logging and existing expected-error dialogs are credited; only observed residual gaps are repaired.

## 3. Implementation steps

1. Keep diagnostic logs outside the saved-game root; on macOS use
   ~/Library/Logs/MicroCol. Use the platform's application-log/state directory
   on other supported systems. Bound the complete retained log set to three
   files of at most 5 MB each, including the active file. Follow the
   [accepted diagnostic policy](../../gap-analysis.md#local-diagnostic-logs).
2. Reuse Log4j/SLF4J and existing recovery dialogs. Record bounded safe
   operation/error identity, build, platform/runtime and time. Never persist
   save JSON or player text into diagnostic reports; path/context handling must
   not leak these indirectly through exception messages or ordinary model logs.
   Keep original console fallback if the file sink cannot start or write.
3. Cover caught startup/load/save/exit/turn failures and the EventBus error
   boundary without changing game rules or atomic persistence. Normalize expected
   unwritable-save-root failures to the existing recovery path. Show where to find
   logs in existing localized failure guidance. Avoid new telemetry/export UI.
4. Add focused log bounds/redaction/failure tests and recovery tests. TC99/F90
   exercises an unwritable save root using a file instead of chmod, confirms Exit
   failure keeps the game playable, and checks useful safe diagnostics. Follow
   architecture, functional test contract and shared Java formatter. Preserve
   existing TC42 load recovery and existing success paths.
5. Verify the changed diagnostics in packaged runtime as well as source tests;
   existing startup-only release evidence does not prove the new behavior.
   Record exact tested build/platform and any remaining packaging limitations.
   Targeted acceptance is complete; no full R-0233 baseline is claimed.

6. Accepted in the isolated batch on 2026-10-19; see [diagnostic evidence](../../diagnostics.md#evidence). Publication and full batch regression remain pending.
