# R-0355 — Drag navigation on the world minimap

1. Status: done
2. Updated: 2026-10-30
3. Related: [UC-114/119](../../use-cases.md), [minimap UX](../../ux.md#minimapa-sveta-2026-10-30).
4. Dependencies: [R-0350 world minimap](R-0350.md), existing camera clamping and model-owned exploration.
5. Primary area: [A03](../areas.md#a03).
6. Related areas: [A05](../areas.md#a05), preserving the player's permitted map knowledge.
7. Origin: the user tried dragging the implemented minimap, observed no response and requested drag navigation on 2026-10-30. This is a direct player observation, not a general usability study.

## 1. Summary

1. Let the player move the detailed map continuously by holding the left mouse button and dragging across the minimap.
2. Preserve the existing click navigation, keyboard access, hand-drawn appearance and concealed unexplored terrain.

## 2. Behavior

1. Pressing the left button inside the playable minimap centers the view as before. While held, the view follows the pointer and the viewport rectangle updates immediately.
2. A drag begun inside the map continues beyond its bounds, with the view clamped at world edges. Releasing the button ends navigation even outside the minimap; later pointer movement alone does nothing.
3. Right-button gestures and drags begun in the unused paper margin do not navigate. Navigation does not issue unit orders, change the turn or reveal terrain.
4. The permanent English/Czech hint and accessible help describe clicking, dragging and arrow keys. They remain readable in a small window.

## 3. Implementation steps

1. Extend the existing `WorldMinimap` primary-button gesture through drag and release events, reusing `MinimapProjection` and `ScrollingManager.centerOn`. Keep gameplay and drawing unchanged; no new package, artwork or setting is needed.
2. Add `TC_196_F228_world_minimap_test#TC_03_drag_tracks_pointer_until_release_without_changing_gameplay`, using native pointer steps and named page verification methods. Check intermediate positions before release, world-edge clamping, release outside, ignored gestures and unchanged serialized gameplay. Existing TC196 scenarios retain click, keyboard, discovery and EN/CZ checks with the updated hint.
3. Apply the shared formatter, run model/JUnit, targeted TC196/TC188/TC192 and `PageVerificationContractTest`, then fixed smoke/support. Check documentation consistency, strict MkDocs and runtime EN/CZ captures. Record actual results in [functional evidence](../../functional-tests.md).

4. Implementation and required local game acceptance are complete on 2026-10-30; the [functional evidence](../../functional-tests.md#r-0355-minimap-drag-2026-10-30) records the checked source, results and reviewed English/Czech captures. Publication requires separate verification.
