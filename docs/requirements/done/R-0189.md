2. Updated: 2026-10-23
3. Related: P24; target part of [GOV-016](../../gap-analysis.md#government-taxation-and-independence); [UC-083](../../use-cases.md#politika-a-valka-za-nezavislost) (Hra); [accepted intervention target](../../gap-analysis.md#revolution-and-intervention).

## 1. Summary

1. Rebels should see and work toward one fixed post-declaration liberty-bell target for foreign help.
2. This requirement owns target timing and progress, not the later physical troops/ships.

## 2. Behavior

1. On the **first rebel owner update after declaration**, announce target `ceil(500×k)` bells once and begin counting **new** bells from that update. Pre-declaration/earlier bells do not count. Keep the target fixed if difficulty or display context changes afterward.
2. At the first update when cumulative eligible bells reach the target, mark intervention earned exactly once and pass one durable event to R-0190. Progress/earned state survives Save/Continue; further bells do not earn another delivery.
3. UC-083 checks announcement timing, target rounding, below/at boundary, saved midway and no second event after delivery.

4. Consume the accepted 2026-10-20 rules from [R-0196](../../gap-analysis.md#r-0196-refinement); preserve this requirement’s own outcome and existing delivered behavior. These decisions do not establish this consumer’s implementation or acceptance.

## 3. Implementation steps

1. Model stores the fixed target, post-declaration bell count and earned flag; consume actual production from R-0100 rather than a displayed historical total. GUI reports target/progress without advancing it.
2. Proposed model/UC-083 checks cover declaration/update boundary, exact target, repeated update, restart and event handoff under the [functional contract](../../functional-tests.md).
3. Selected and refined 2026-10-23. Integrate initialization before the first post-declaration owner production update; count actual newly produced bells once, including that update. Persist target, eligible progress and earned state; reject inconsistent saved state. Reuse the shared difficulty coefficient and production path. Expose durable earned state for R-0190 without creating its units here.
4. Add model boundary tests for first-update timing, rounding, multiple colonies, overflow validation, fixed target, reload, and exactly-once earning. Add TC155 for the actual announcement, progress, earned feedback and Save/Continue; preserve English scenario steps and page verification methods. Main agent runs all JUnit plus selected Docker/Xvfb UI scenarios, then complete local batch acceptance. No remote CI verification is requested.
5. Keep bells reaching the target distinct from subsequent post-intervention score bells under R-0196. The pending delivery is durable state for R-0190; reloading must not resend a UI announcement or lose the earned outcome.

6. Targeted implementation and results are recorded in [intervention target evidence](../../functional-tests.md#r-0189-targeted-intervention-target-verification-2026-10-23). Full batch acceptance remains pending.

6. Complete local acceptance on 2026-10-23 is recorded in [sixth-batch evidence](../../functional-tests.md#sixth-batch-full-local-acceptance-2026-10-23).
