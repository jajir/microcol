## 1. Summary

1. The developer needs to know what is taking time and whether tests are running.
2. The quoted chat message conflates a failed startup attempt, Docker health and test execution. Existing runner logs already distinguish operations and elapsed time.
3. Scope: persistent agent reporting instructions using existing evidence; no runner or game changes and no claim to repair the original Docker issue.

## 2. Behavior

1. A delayed job is reported with its last evidenced phase, concrete operation, elapsed time and limit when available, and evidence location.
2. If Docker admission fails before the test command starts, the update explicitly states that no tests started; a retry identifies the new startup attempt and its evidenced phase.
3. Lock waiting, preparation, compilation, tests and cleanup are distinguished. Missing evidence is reported as unknown, not filled with an assumed cause or duration.
4. Successful probes and retries do not imply a permanent repair. Repeated failures require comparison of retained evidence before causal claims.
