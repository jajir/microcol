## 1. Summary

1. Players can see the finished result breakdown and a persistent top-ten ranking across games.
2. This requirement owns cross-game record/ranking/display, not score arithmetic or the choice to retire.

## 2. Behavior

1. Store at most ten scored game results ordered by higher final score first, then earlier completion record. Keep one entry per game-result identity; finishing, reloading or opening the list again does not duplicate it.
2. Automatically scored victory, loss and date-end results, plus a confirmed scored Retire, enter the same ranking path. Always show the just-finished result and its component breakdown even if it does not enter the top ten. A qualifying result survives app restart with score, difficulty and identifying nation/player data. An Exit or canceled Retire records nothing; later unscored play cannot replace the frozen result.
3. UC-112 checks 11+ results, score/tie ordering, boundary admission, nonqualifying breakdown, restart and duplicate prevention.

## 3. Implementation steps

1. Consume the immutable GameResult identity and component snapshot created by R-0193. Keep a bounded persistent top ten separate from game saves, using existing application storage and safe-write conventions. Store difficulty and nation/player display identity with the result; do not recalculate an earlier record from the live game.
2. Insert once by result identity, sort by descending final score and then original completion-record order, and trim to ten. Reopening or replaying a recorded identity must not change its tie order. A nonqualifying result still has its own displayed breakdown. A storage failure must not silently discard an existing ranking or prevent access to the completed result.
3. Integrate automatic scored victory, loss and 1800 outcomes through the shared result path. Show the just-completed result and ranking even when it is not admitted. Add discoverable access from the existing menu/navigation with EN/CS labels. Opening a save alone must not rewrite that save; unscored continuation cannot replace its frozen entry. Provide the shared recording path for later R-0194 Retire integration without adding Retire here.
4. Unit tests cover at least eleven results, all tie/admission boundaries, stable identities, reload/restart, invalid storage and write failure. Add TC163 for actual ranking access, completed-result display, duplicate prevention and persistence through reopening; assertions stay in dedicated page verification methods.
5. Main reviews/formats Java, runs all JUnit plus selected Docker/Xvfb UI scenarios, and completes full two-worker acceptance at the batch boundary.
