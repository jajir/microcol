# R-0342 — Center game-view bar contents within 1440 logical pixels

1. Status: done
2. Updated: 2026-10-29
3. Related: [UC-114, UC-115 and UC-119](../../use-cases.md).
4. Dependencies: the shared in-game frame from [R-0307](R-0307.md) and shared bar styling from [R-0337](R-0337.md).
5. Primary area: [A03](../areas.md#a03).
6. Related areas: A01 navigation, A06 Europe and A07 colony reuse the same frame; their game rules do not change.
7. Origin: the user selected a maximum of 1440 logical pixels on 2026-10-29 after comparing full-width and centered bar layouts. Capture and refinement are complete in this request.

## 1. Summary

1. Players on wide monitors need related controls and status information to remain within a comfortable central area.
2. Source inspection on 2026-10-29, based on main `67ac93f9`, found expanding toolbar and status contents; R-0337 centralizes their styling.
3. Apply one shared width limit to upper and lower bars on the map and all in-game pages. Keep the map and bar backgrounds full width.

## 2. Behavior

1. Resizing a running game automatically adjusts both bars. The player does not need a setting or an additional action.
2. Above the limit, the inner areas of both bars are centered and remain 1440 logical pixels wide. Backgrounds and horizontal frame edges still reach both window sides.
3. Below the limit, both bars fit the available width with a shared minimum horizontal padding of 16 logical pixels. The exact threshold is a window content width of 1472; at 1470, each inner area is 1438 pixels wide. Buttons retain normal size, existing icon fallback, labels, keyboard access and actions.
4. Returning from a wide window to a smaller window works without a new minimum-width restriction. Navigation, turn, balance and game state remain unchanged; resizing has no confirmation, cancellation or persistence requirement.

## 3. Implementation steps

1. Separate each full-width bar frame from its existing content using JavaFX StackPane. Keep the single width rule in GameScreenBars.css and reuse GameScreenHeader (shared by the map and InGamePage) and StatusBarView.
2. Adapt map content placement and the existing toolbar minimum-size calculation so centered margins never become a minimum window width. No model, AI, scenario or save schema changes are needed.
3. Extend TC_192_F225_in_game_layout_test with named wide-window, threshold and shrink-back scenarios and dedicated page-object verification methods. Preserve existing frame, navigation and gameplay assertions. Run all model/JUnit checks, targeted Docker/Xvfb UI scenarios, fixed smoke, the shared Java formatter, documentation consistency checks and strict MkDocs.
4. Current result: implementation and local acceptance are complete (4783 model/JUnit tests, 51 targeted UI checks and 21 smoke/support checks, with zero failures, errors or skips). Integration and publication are tracked separately. The [functional-test evidence](../../functional-tests.md#r-0342-bar-content-width-2026-10-29) records actual selections and results.
