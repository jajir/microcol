## 1. Summary
1. Developers need local Docker test requests from different tasks and worktrees to wait for one another instead of competing for resources.
2. The fixed smoke gate has a 300-second budget. R-0291 passed in 294.876 seconds; earlier failures and observed overlap are retained in [its evidence](../../functional-tests.md#r-0291-map-outline-weight-2026-10-26). Serialization alone does not guarantee this budget.
3. Use one operating-system lock and existing runners. No persistent FIFO scheduler, service, database, test reduction or timeout increase.

## 2. Behavior
1. Local smoke, full verification, targeted Docker tests and Docker runner checks share one lock across worktrees for this user and Docker host. A waiting request reports that it is waiting; ordering is not guaranteed.
2. Only waiting is excluded from the execution watchdog and unchanged smoke acceptance budget. Budgets start when the lock is acquired and include crash recovery, source preparation, verification and final cleanup. Existing source capture, test selection, reports and completion callbacks remain mandatory.
3. Cancellation while waiting starts no test and leaves the current holder alone. A dead holder releases the OS lock. Before starting another command, recover its recorded process group and remove only owned test containers; if recovery cannot be confirmed, fail without starting new tests.
4. A live hung run remains subject to its existing timeout. Raw Docker commands bypassing the supported entry points are outside this cooperative lock. Lock files may remain after release and must not be deleted to unlock a running job.

## 3. Implementation steps
1. Add a small shared Python lock helper beside the UI scripts. Integrate completion supervision and the existing shell entry points; label owned containers and retain existing cleanup. Record command identity before allowing it to execute so recovery cannot race command startup.
2. Keep lock descriptors out of child processes. Keep managed verifier Docker clients in the recorded process group so crash recovery stops clients before containers. Record wait time separately from execution time.
3. Verify mutual exclusion across working directories, cancellation, SIGKILL recovery, surviving children/containers, cleanup refusal and watchdog accounting with process tests. Run tooling checks, the mandatory model/JUnit plus fixed smoke gate, documentation consistency and strict MkDocs.
4. Implemented and accepted locally on 2026-10-26; see the [operating contract](../../ai/completion-callbacks.md#local-docker-test-lock) and [dated verification evidence](../../ai/completion-callbacks.md#r-0292-local-lock-evidence-2026-10-26). Publication remains independently verified.
