## 1. Summary

1. Show whether the latest tested main revision has a problem without opening logs, and make the evidence one click away.
2. Full UI regression currently runs for every main push, including documentation. Move it and verified game distribution work to one conditional nightly run or an explicit manual run. Keep existing push model compatibility and documentation checks.
3. Report both model/JUnit and full UI/support from the same full regression snapshot; do not confuse a smoke subset or repeated compatibility-matrix executions with these counts.

## 2. Behavior

1. At 02:17 UTC daily, run the full suite if relevant changes occurred since the last attempted full regression. Documentation-only differences and unchanged failed revisions do not automatically repeat the expensive suite. Missing history causes a conservative run. Manual execution on main always runs it.
2. Keep one full run active and the newest waiting request. Keep the existing 90-minute functional-job budget. Publish game builds only after the full regression and platform gates pass for their exact source revision; documentation keeps its independent publication.
3. Display two clickable count badges at the top of the repository README. The report names the tested commit, UTC start time, group counts, failing/skipped cases and links to job logs and downloadable XML/screenshots. The fast model workflow has a separate status badge.
4. Failed tests and errors remain visible in red. Partial, cancelled, skipped or unavailable evidence never becomes a green zero; known counts may be shown as partial. A newer main revision is amber even when the previous run passed. A skipped no-change night retains the last actual result. Pages/image caching may delay updates and the exact run remains authoritative.
5. Keep summaries for 90 days and detailed artifacts for 14 days. Do not commit generated results to main, add a storage branch or publish the legacy Maven site. A failed test run must still be eligible for report publication.

## 3. Implementation steps

1. Reuse the existing full verifier with one UI worker in dev-builds, add conditional schedule selection and retain manual execution. Delay native packaging until full tests pass. Keep the existing exact-revision publication guard.
2. Add a small Python Actions/summary adapter that reuses the verifier's inventory and report validation. Generate escaped Markdown and vector badges from artifacts through the existing Pages workflow, refreshed on test start/completion and documentation pushes.
3. Cover schedule deduplication, full change ranges, failed/missing/malformed/skipped reports, distinct model/UI totals, newer-main marking, skipped-run selection and escaped failure messages in CI tooling tests. Run all model/JUnit tests, fixed smoke, documentation checks and strict MkDocs. No changed player path requires a new TC scenario.
4. Implementation and required local acceptance are complete. [Verification evidence](../../functional-tests.md#r-0364-nightly-regression-and-public-test-counts-2026-10-30) records actual checks. Remote publication remains separately verified; no historical failures are rewritten.
