## 1. Summary

1. A colony report shows what it has, what it produces/consumes and what will grow or run short next.
2. Existing construction and shortage operations remain their owners; this requirement owns their report representation.

## 2. Behavior

1. For each owned colony show current population, stocks, actual production and consumption, active construction with retained progress, and an expected next-update growth or shortage based on current assignments/resources. Identify waiting tools with the same colony/project/quantity as R-0086, without creating another reminder.
2. Reassignment, trade, food loss and Save/Continue refresh the snapshot. Opening/closing the report spends no resources or turn; foreign colony private stock remains hidden.
3. UC-114 checks two unequal colonies, full/short input, food around zero, construction waiting/completed and post-update values against the model.
4. Consume the accepted 2026-10-20 rules from [R-0128](../../gap-analysis.md#r-0128-refinement), [R-0146](../../gap-analysis.md#r-0146-refinement); preserve this requirement’s own outcome and existing delivered behavior. These decisions do not establish this consumer’s implementation or acceptance.
5. Under food shortage a random resident is lost before output and project are recomputed, so the report shows the current stock and the shortage warning but `?` in place of output, use, spending, change and next stock; a completing warehouse or custom house likewise hides spending, change and next. Losing the last resident is reported as a lost colony.
6. Projection semantics: the figures are read from the current state, not forecast from a simulated update. Food has no warehouse limit, so no cap applies before exports.

## 3. Implementation steps

1. Build a current-owner snapshot from the existing colony production, food, warehouse and construction owners. Show each colony’s population, stored goods, actual production/consumption and expected next-update change under current assignments. Reuse shared model predictions; do not duplicate update arithmetic in GUI or simulate by mutating the live game. Clearly distinguish projections from stored values.
2. Include current project, retained construction progress and waiting tools with the same project and missing quantity as R-0086. Expose expected growth/food shortage and constrained inputs with the existing rules; reporting never emits another reminder or consumes resources. Validate model-local owner identity and exclude foreign colonies.
3. Extend existing statistics with a localized EN/CS colony report and owned-colony drilldown. Rebuild on opening and revalidate model/colony ownership before opening a selected colony; stale/captured/replaced-game targets return safe feedback. Use a scrollable layout, readable stocks/change labels and existing keyboard/close navigation.
4. Model tests cover two unequal colonies, sufficient/short inputs, food boundaries, project waiting/completion, report purity and agreement with actual next updates. TC168 covers visible stocks/output, a real reassignment or trade changing the report, legal drilldown and Save/Continue. Preserve existing rule tests and source-contract page verification conventions. Capture report screenshots for visual review.
