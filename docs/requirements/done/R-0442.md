# R-0442 — Consistent settings page background and developer label

1. Status: done
2. Updated: 2026-11-10
3. Related: UC-119 SUPPORT-001; [UX rules](../../ux.md).
4. Dependencies: [settings controls](R-0441.md), existing fullscreen frame and shortcut editor.
5. Primary area: [A03](../areas.md#a03).
6. Related areas: none; presentation only.
7. Origin: user screenshots and implementation request, 2026-11-10.

## 1. Summary

1. Settings and Keyboard shortcuts should use the same light paper as their header and footer.
2. Source inspection at `83a3720d` found darker content backgrounds and a shortcut hint appended to Developer mode.
3. Remove the shortcut hint from the manual setting; keep actual bindings visible in Keyboard shortcuts.

## 2. Behavior

1. Open Settings from a running game: its content and scrolling viewport match the header/footer background, including after resizing and returning from Keyboard shortcuts.
2. Open Keyboard shortcuts: its introduction and scrolling rows use the same light background. Save, Cancel and shortcut capture retain their existing behavior.
3. In both menu and game Settings, the localized Developer mode checkbox label contains no shortcut hint. Changing the binding does not append one; the checkbox and configured shortcut still toggle the same state.
4. Settings remain immediate and persistent; navigation, language switching and shortcut-editor cancellation do not change their contracts.

## 3. Implementation steps

1. Scope the existing paper color to the settings frame and shortcut editor in `InGamePage.css`. Keep ownership in `gui.screen.setting`; remove the now-unused shortcut-label listener.
2. Extend `TC_84_F75_framed_settings_test.TC_15_common_axis_keeps_wrapped_captions_and_game_settings_usable` with background checks and retain the existing developer/remapping scenarios with updated expected labels.
3. Apply the shared Java formatter; run all model/JUnit tests, targeted TC_84 Docker tests, the fixed smoke selection, documentation consistency and strict MkDocs.
4. Current result: implemented and locally accepted; 5,117 model/JUnit, 15 targeted UI and 21 smoke/support tests passed without failures/errors/skips. [Acceptance evidence](../../functional-tests.md#r-0442-settings-paper-and-developer-label-2026-11-10).
