## 1. Summary

1. Modal windows should look drawn by hand, with the quiet, slightly uneven single contour selected by the user. Their outline has the same 2px ink weight as current buttons.
2. Source inspection at `d318a050` found that application dialogs share `AbstractMessageWindow` and currently use undecorated rectangular stages.
3. This change owns only the outer frame and its filled silhouette. Keep existing dialog content, button artwork, icons, labels, sizing, states and handlers. Native operating-system file pickers remain system-owned.

## 2. Behavior

1. Opening an application modal displays the selected gently curved, asymmetric outline around its existing content. Paper fills the enclosed area. The underlying window remains visible outside the outline, including the corners; there is no rectangular backing plate.
2. Small confirmations, dynamically sized choices, large Congress/help windows and nested save confirmations share this appearance. Resizing or reopening keeps the contour complete, its line weight constant and controls readable.
3. The owner stays blocked while its modal is open. Existing mouse, Enter, Space, Escape, cancel and confirm behavior remain unchanged, including rejection and model effects. Viewing or canceling a dialog does not mutate game state.
4. Buttons retain the implemented R-0316 appearance rather than the simplified design-preview buttons. No save schema, rules, navigation or new sound changes are part of this requirement.

## 3. Implementation steps

1. Keep ownership in `gui.util`: wrap existing dialog content in one shaped paper frame, clip the complete surface to the same contour, draw the ink above opaque child panels, and use a transparent scene/stage. Keep existing content padding and all button styles; reserve a size-dependent outer gutter so inward curves cannot overlap controls.
2. Reuse the approved SVG path as the shared frame shape. Scale its geometry with layout while drawing the border at a fixed 2px width. All existing callers continue through `AbstractMessageWindow.init`.
3. Add geometry checks in `ModalFrameTest`. Extend TC83/F74 to exercise the real common modal base, transparency, resizing and unchanged button interactions; verify actual Congress/help and nested save dialogs in TC192/F225 and TC191/F224. Retain colony-name and typography checks. Add native screen-pixel checks under Xvfb/Openbox with simple compositing; run the affected UI-tooling tests. Run all model/JUnit tests, selected Docker/Xvfb journeys and the fixed smoke/support phase, plus Java formatting, documentation consistency and strict MkDocs.
4. Current result: implemented and locally accepted on 2026-10-27. Model/JUnit, targeted UI and smoke/support reports have no failures, errors or skips; visual review confirms the unchanged controls remain inside the outline. Detailed execution evidence belongs in [functional tests](../../functional-tests.md). Remote regression and publication are not verified by this acceptance.
