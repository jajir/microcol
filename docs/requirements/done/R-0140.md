## 1. Summary

1. A route stop needs explicit lists of goods to unload and load, executed in the documented order without loss or duplication.
2. The 2026-10-17 source catalogue at `ffae3396` finds no stop cargo instructions or recurring transfer. Existing manual cargo transactions remain useful foundations.
3. This requirement owns stop instructions and one legal stop's goods processing; [R-0141](R-0141.md) owns reaching and repeating stops.

## 2. Behavior

1. Each stop stores up to six commodity types to unload and up to six to load. On a legal arrival, unload configured goods first, then load configured goods, each up to actual destination capacity, carrier capacity and available stock. Europe stops use the current validated buy/sell quote and account for treasury changes exactly once.
2. A full hold, empty source or absent configured good is an explicit no-op for that transfer, never a loss or infinite retry. A failed European quote or stale ownership leaves that transfer and its money/stock unchanged; the player receives a reason.
3. Save and Continue retain the stop instructions and whether the current stop has already processed its transfers; loading or inspecting it does not repeat a sale, purchase, unload or load. Editing stop rules while a carrier is en route follows [R-0142](R-0142.md)'s next-stop boundary.

4. Agreed 2026-10-20 ([shared rule](../../gap-analysis.md#r-0140-refinement)): Unload before loading, and process each configured goods list in the player-visible top-to-bottom order. Allow the player to reorder entries and label this order as priority when hold space, warehouse capacity or money is insufficient.

## 3. Implementation steps

1. Extend the existing route stop representation with required ordered unload/load goods IDs, zero through six distinct goods in each list. Reuse one itinerary store; validate duplicates, unknown IDs and limits on create/restore. Preserve player-visible order as priority and expose reorder controls in the existing editor.
2. Model processes a legal carrier at the selected route stop, validating ownership, actual location, transport kind, route identity and unprocessed visit before mutation. Reuse shared cargo/warehouse transfer and European trade operations, unload before load and process each list top-to-bottom. Transfer only actual available amounts up to existing capacities and funds; never invent stock or overflow holds.
3. Persist the minimal carrier/visit processing boundary needed to prevent replay of the same visit after Save/Continue, while permitting a later distinct visit. R-0141 will drive travel and repeat visits through this same operation. Merely opening, previewing or restoring state performs no transfer. Rejected stale ownership or trade quotes leave the affected transaction unchanged and produce a model result explaining it.
4. Extend the route UI with ordered unload/load configuration and explicit processing feedback for a carrier legally at the stop. Zero stock/full holds are finite no-ops; player-visible results distinguish these from rejection. Reordering changes priority, not actual stock until processing. EN/CS and keyboard paths reuse existing controls. En-route edits and automatic route traversal remain R-0142/R-0141.
