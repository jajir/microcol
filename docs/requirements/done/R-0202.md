## 1. Summary

1. The fleet report tells the player where each owned ship is headed and what it carries, while showing only permitted occupancy for visible foreign ships.
2. This requirement owns the fleet report and consumes R-0205's shared model disclosure query for foreign holds.

## 2. Behavior

1. Show every own ship with current location (map, port, Atlantic or repair), destination/ETA where known, passengers, goods and occupied/free holds based on real saved state. Current damage/repair status is labeled when applicable.
2. A visible foreign ship reveals only occupied-hold count, not exact cargo/passenger identities or hidden route/destination. An unknown foreign ship is absent. Transfer, reversal, battle/repair and Continue refresh values without making a move or duplicating cargo.
3. UC-114 checks six ship families, full/partial holds, Atlantic/reversed/repair state, visible foreign occupancy, hidden contents and owner switch. The report is read-only and localized; closing or navigation spends nothing. Map/Europe navigation revalidates ownership, current visibility and the current game, with unavailable feedback for stale targets; Atlantic/repair entries offer only navigation supported by their actual place.

4. Consume the accepted 2026-10-20 rules from [R-0171](../../gap-analysis.md#r-0171-refinement), [R-0175](../../gap-analysis.md#r-0175-refinement); preserve this requirement’s own outcome and existing delivered behavior. These decisions do not establish this consumer’s implementation or acceptance.

## 3. Implementation steps

1. Model supplies viewpoint-filtered ship summaries and bounded foreign occupancy from cargo/visibility owners; GUI renders through R-0016. Reuse R-0205's local disclosure semantics.
2. Proposed model/UI UC-114 checks cover source counts, all location modes, denial of hidden cargo and reload under the [functional contract](../../functional-tests.md).
3. Selected and refined on 2026-10-23 after targeted acceptance of R-0205. Reuse Player.getObservedOccupiedHolds for foreign occupancy and existing cargo, voyage and repair owners for own-ship details. Model returns a viewer-filtered snapshot; GUI never reconstructs gameplay rules.
4. Verify all six ship families and own placement modes, reserved/passenger holds, partial/full cargo, reversal, damage/repair, stale model and viewpoint isolation with pure-read model tests and disk reload. TC171 exercises actual cargo changes, report refresh, navigation and Continue, with English/Czech readable labels and keyboard access. Run all JUnit plus approximately five affected UI classes and full local acceptance at the batch boundary; remote CI is outside this task.
5. Implementation, written 2026-10-23 and not verified: `model.FleetReport` reads own ships through `LaborLocation`, `PlaceHighSea`, `PlaceShipRepair` and `CargoSlot`, skips Crown-seized ships as the labor report does, and lists visible foreign ships with only ID, type, tile and the count from `Player.getObservedOccupiedHolds`. `Model.getFleetReport` checks the owner's identity. The statistics tab `fleetTab` (`FleetPanel`) shows the list, and `FleetNavigator` revalidates the live report by ID before it opens a tile or Europe. Evidence and the untested parts are in [functional tests](../../functional-tests.md#r-0202-fleet-report-written-not-verified-2026-10-23).
