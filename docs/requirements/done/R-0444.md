# R-0444 — Consistent full-screen Save and Load

1. Status: done
2. Updated: 2026-11-10
3. Related: UC-119 SUPPORT-001; [save/load navigation](../../save-load-navigation.md).
4. Dependencies: existing saved-game browser, screen-origin navigation and shared game frame.
5. Primary area: [A03](../areas.md#a03).
6. Related areas: none; presentation and navigation only.
7. Origin: user screenshots and implementation request, 2026-11-10.

## 1. Summary

1. Players need consistent Save game and Load game screens with a header and footer.
2. Source inspection on 2026-11-10 found Save in a modal window and in-game Load with a darker outer background.
3. Reuse the shared browser and standard cream paper; remove “Please” from browser text. File formats and save rules remain unchanged.

## 2. Behavior

1. Opening Save during a game replaces the visible game with a full screen titled Save game, a Back to game action and the shared live gold/date footer.
2. In-game Load uses the same cream background as its header/footer, including the space outside the saved-game panels. Menu-origin Load retains its existing menu frame and return destination.
3. Back, Escape or closing Save cancels and returns to the originating screen without changing the game or files. Save-before-leaving proceeds only after a successful save; cancellation and failures preserve the running game.
4. Existing selection, previews, names, overwrite confirmation, deletion and import/export remain available. Smaller windows scroll the body while keeping the frame visible. Browser messages do not say “Please”.

## 3. Implementation steps

1. Reuse InGamePage for the Save host in gui.dialog and register it with existing screen-origin navigation; retain synchronous decisions needed by save-before-leaving without blocking FX interaction.
2. Scope background styling to Save/Load. Retain shared saved-game operations and test fixtures.
3. Verify TC_191 session/save journeys, TC_192/08 small-window layout and PageVerificationContractTest, plus required model/JUnit and smoke phases. Run shared formatter and documentation checks/strict MkDocs.
4. Implemented and locally accepted on 2026-11-10: 5,117 model/JUnit, 15 distinct targeted UI/source-contract and 21 smoke/support tests passed without failures, errors or skips. See [dated evidence](../../functional-tests.md#r-0444-saveload-screen-consistency-2026-11-10).
