## 2. Behavior

1. With developer mode enabled, the opening menu shows Map editor beside Settings; disabled mode hides the entry and rejects entry through another route. The editor is a separate screen with the familiar map viewport and right-hand editing panel. It displays the whole authored world without advancing turns or changing an existing game.
2. New map in the top menu requests width and height in tiles. Confirming valid dimensions creates an ocean-only world with no settlements or units. Cancel and rejected dimensions preserve the current draft. Reject nonintegers, nonpositive dimensions and dimensions beyond supported resource limits before allocating the world; show the supported bounds in the dialog.
3. Tools allow selecting/changing terrain, forests/fields, mountains, rivers and bonuses supported by the existing model. Clicking edits the intended tile; painting terrain by dragging applies the selected tool. Selecting a tile exposes its attributes and removal controls. Coordinates start at [1, 1] in the top left. Reuse current geography rules; invalid combinations have a concrete explanation and do not partially mutate data.
4. Choose the player's European nation and initial unit types, place/remove units and assign passengers to a ship. Reopening preserves nation, positions and cargo membership. Playback must use this authored expedition without silently substituting a generated expedition. Capacity and placement checks use the game's rules.
5. Place, inspect, edit and remove native settlements, choosing the tribe and currently supported settlement properties. Enforce current identity, name and placement contracts; use existing defaults for required properties not exposed by the form. Do not add European-colony authoring in this version.
6. Top-menu Save writes an authored scenario to a chosen file, and Open map restores it for further editing. A structurally valid unfinished draft can be saved and reopened, including an ocean-only world without an expedition. A failed write must not report success or destroy the previous file. Canceling file selection or a failed read preserves the draft.
7. Play validates the draft before creating a fresh game. Invalid/unplayable drafts remain in the editor with specific errors and implicated positions where available. A valid scenario starts with the exact authored geography, nation, units and settlements. Playing does not overwrite the source scenario; ordinary game saves remain separate.
8. New, Open, leaving the editor and closing the application protect unsaved changes with Save / Discard / Cancel. Cancel or unsuccessful saving leaves the draft accessible. Controls and feedback are localized in English and Czech, support keyboard use and follow shared UX and graphics rules.
