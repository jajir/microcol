## 1. Summary

1. Players need one editor for keyboard commands and movement, with platform defaults and persistent personal overrides.
2. Current source f29bf15e has keyboard handling and displayed shortcuts distributed across GUI components.
3. Preserve existing default combinations where compatible and add missing command bindings without conflicts. Mouse modifiers remain fixed and outside the editor. Standard form navigation and confirmation remain fixed.

## 2. Behavior

1. Settings offers Keyboard shortcuts, with localized action labels grouped by context and current combinations. Multiple combinations per action can be added, changed or removed, including an explicit unbound action.
2. Windows, Linux and macOS each have editable packaged default properties. The running platform selects its defaults; only player deviations are saved in user configuration, separately from saved games. Existing alternatives remain available.
3. Editing captures a combination without executing its old command. Overlapping active contexts cannot share conflicting bindings; show the conflicting action and block save. Disjoint contexts may reuse combinations. Typing, dialogs and unavailable commands must retain their existing protections.
4. Restore defaults updates the draft for the current platform. Save and back validates and persists before applying changes everywhere, including existing labels and handlers, without restart. Cancel discards the whole draft, including a reset. Persistence failure retains the draft and shows a useful error.
5. Tab, Enter and Escape retain ordinary focused-control/form behavior; gameplay uses of these keys remain context-sensitive. Mouse modifier gestures, including quick-buy, do not change. Held movement keys and release events must remain correct after remapping.
6. User-approved choices: preserve and complete current defaults; allow multiple bindings; include commands and movement, exclude mouse modifiers. Default files can be changed in source without Java edits. Unmodified actions follow changed packaged defaults; explicit empty overrides remain unbound.

## 3. Implementation steps

1. Implemented 67 contextual actions with stable IDs, three complete platform properties resources, an injected `ShortcutController` and `KeyboardShortcuts` interface. User overrides are stored per platform through existing settings persistence. See the authoritative [shortcut inventory and contract](../../keyboard-shortcuts.md).
2. The transactional editor supports multiple bindings, capture, conflict detection, unbound actions, reset, cancel, persistence failure and immediate configuration updates. Existing command controls retain availability and confirmation rules. Held-key and release-gesture handling protects typing and repeated key events.
3. Accepted locally on 2026-11-08: 5,091 model/JUnit tests, 65 targeted Docker/Xvfb UI/support tests and 21 smoke/support tests, all zero failures/errors/skips. Smoke completed in 231.066 seconds within 420 seconds. Shared Java formatting and visual review completed; 14 documentation consistency checks, name audit and strict MkDocs passed on the integrated sources.
