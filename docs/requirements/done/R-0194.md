## 1. Summary

1. A player can leave without scoring, or retire and record the current scored result.
2. This requirement owns the choice/action path, while dates and score arithmetic remain separate.

## 2. Behavior

1. Exit ends/leaves the current play session without calculating or recording a new score. Retire previews and confirms one score/result, then may place it in the Hall of Fame; cancellation of either leaves the live game unchanged.
2. At the 1800 nonrevolutionary boundary, Continue resumes unscored play; it cannot replace the already recorded result. Retiring during that unscored continuation does not create a second score. End/reload does not repeat a result write.
3. UC-111 checks Exit versus Retire, both cancellations, score/no-score, later unscored Continue and one result identity across Save/Continue.

## 3. Implementation steps

1. Reuse the existing safe Exit flow without computing a new result. Add a discoverable Retire choice with EN/CS consequences, model-derived preview and explicit confirmation/cancel. The shared model owns eligibility, preview validation and the terminal transition; UI and AI do not duplicate score arithmetic.
2. Confirmed scored retirement freezes one GameResult and uses the existing completed-result/Hall-of-Fame path. Repeated confirmation is rejected before mutation. During an unscored continuation retain the original frozen identity and components; retirement ends play without a replacement result. Mission-specific behavior remains separate from scored free play.
3. Save/load validates retirement reason against scored/continued state. Cancel and Exit preserve result history, while successful confirmation shows the frozen breakdown and ranking through R-0197. Reuse the existing persistence failure handling and avoid overlapping confirmation/outcome dialogs.
4. Model tests cover preview/confirmation consistency, stale or duplicate requests, cancellation purity, unscored retirement and reload. Add TC164 for actual Exit/cancel versus Retire/cancel/confirm and no duplicate entry after continuation, using explicit page verification methods and the functional contract.
