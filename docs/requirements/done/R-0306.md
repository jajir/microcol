## 1. Summary

1. Question marks should be easier to read on the unexplored map and share the black pen appearance of the approved waves.
2. Source inspection at `a28f774f` found the selected shape A drawn with a 1.6-logical-pixel dark-gray stroke. Increase it moderately to 2 pixels and use black; do not repeat the rejected overly heavy wave proposals.
3. This changes only the question mark's ink and stroke width, including its dot. Other map markers retain their appearance.

## 2. Behavior

1. Opening or continuing a game shows the same hand-drawn question marks with a stronger black line, without a new setting or confirmation.
2. The existing path geometry, position and approximate 4% frequency remain. Panning, resizing, repainting and Continue do not move or animate the marks.
3. Exploring a marked square removes its question mark permanently, including after it leaves current sight or the game is continued. Marks do not reveal terrain, resources or units beneath the unexplored map.
4. The change is automatic; the usual navigation and exit paths apply. No gameplay or save data changes.

## 3. Implementation steps

1. Change only `PaintService.paintUnknownMark` to `Color.BLACK` and a 2-pixel stroke. Keep the shared `MARKER_INK` unchanged for other callers and preserve the existing path and graphics-state save/restore.
2. Update the independent drawing in `FogPage.verifyUnknownMark` and the evidence filename in the existing `TC_26_F18_fog_of_war_test.TC_10_unknown_question_marks_remain_fixed_until_explored`. Preserve all visibility, persistence and pixel assertions.
3. Apply the shared Java formatter when Java changes, review the diff and drawing, and run the required model/JUnit, targeted UI, smoke and documentation checks. The original task explicitly omitted tests; the later acceptance is recorded separately below.
4. Current result: the existing black 2-pixel question marks passed fresh model/JUnit, targeted Docker/Xvfb and fixed smoke acceptance on 2026-10-27. See the [closure evidence](../../functional-tests.md#requirement-closure-2026-10-27). The earlier test omission remains recorded in the original evidence; this later acceptance does not rewrite that history or verify remote publication.
