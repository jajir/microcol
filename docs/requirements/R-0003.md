# R-0003 — Distinguish waiting from skipping a unit's turn

6. Related areas: A04 activation/reset; A03 shared controls and action feedback.

## 1. Summary

Give the player two distinct choices: return to this unit after others, or finish
its opportunity for this turn. Keep this separate from persistent orders.

Static source inspection on 2026-10-12 at
[`4b3a1b56`](https://github.com/jajir/microcol/commit/4b3a1b567bd9e8c8ad8af1587d9849ecee02bead);
no new gameplay test was run while preparing this draft.
[ScreenGamePresenter](../../microcol-game/src/main/java/org/microcol/gui/screen/game/ScreenGamePresenter.java)
binds Tab to next-unit selection.
[SelectedUnitManager](../../microcol-game/src/main/java/org/microcol/gui/screen/game/gamepanel/SelectedUnitManager.java)
and [UnitStorage](../../microcol-game/src/main/java/org/microcol/model/UnitStorage.java)
cycle eligible own units and wrap around. This is useful wait-like behavior;
a separate skip command is missing. The existing TC11 name includes “skip” but
its assertions cover selection cycling.

Scope excludes sentry, fortification, persistent travel and cancelling pioneer work.

## 2. Behavior

Expose distinguishable Wait and Skip actions for an eligible selected unit using
shared controls and keyboard access. Waiting preserves its remaining movement.
Skipping ends its current-turn opportunity; next own turn restores ordinary
availability. The model owns the effect and validation.

Acceptance examples:

1. Own active A/B/C → wait on A → B is selected; after the others, A is available
   again with unchanged movement.
2. Skip A → selection moves on and A cannot move or reappear in the eligible cycle
   this turn; after the next own turn starts, it is available normally.
3. Repeat waits → no unit is lost or duplicated. One or zero eligible units does
   not create an endless selection loop.
4. Save after skipping, reload in the same turn → the skip remains effective;
   save/load does not restore spent opportunity.
5. Foreign, removed or no-longer-active selected unit → the action is unavailable
   or safely rejected without affecting another unit.

These commands have no modal confirmation to cancel and do not create a lasting
order. Manually selecting a skipped unit may show its details but cannot bypass
the model's current-turn restriction.

## 3. Implementation steps

1. Review selection callers, `AbstractUnit` turn reset and persisted unit state.
   Reuse the existing cycle; add only the model operation/state required to
   distinguish a current-turn skip.
2. Connect shared buttons/keys to that operation and refresh selection/feedback
   from the model. Do not implement skip solely as a GUI selection flag.
3. Extend [TC_11_F11_skip_to_next_unit_test](../../microcol-test/src/test/java/org/microcol/test/TC_11_F11_skip_to_next_unit_test.java)
   while retaining its 0 → 1 → 2 → 0 regression and F11 fixture consumers.
   Add named methods for skip, reload and next-turn reactivation.
4. Extend `UnitStorageTest` and appropriate unit/model tests for eligibility,
   rejected commands and reset. Test model rejection without partial effects.
5. Run those tests, TC11 and the full functional suite because selection is
   shared; use the [standard verification environment](../functional-tests.md#spousteni-a-ochrana-publikace).
   Update MOVE-005/UC-014 evidence without closing other orders.

Verification: planned, not executed for this requirement.

## 4. Open questions

1. **Nonblocking presentation choice:** keep Tab as Wait/next selection and choose
   a distinct Skip control/shortcut consistent with existing controls. Proposed,
   not a requirement to reproduce historical keyboard bindings.
2. **Refinement detail:** confirm behavior for units already performing a
   persistent action. Recommended first slice: enable Wait/Skip only for units
   eligible for manual movement; do not silently cancel work.
3. No unresolved numeric rule is required for ordinary movable units. Decide
   whether remaining movement alone is sufficient persisted state after reviewing
   every current-turn activation path.
