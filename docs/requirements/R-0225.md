# R-0225 — Reproduce the source-to-runtime graphics export

1. Status: ready for development
2. Updated: 2026-11-01
3. Related: P29; [SVG export and atlas rules](../graphics.md#export-svg-do-rastrovych-souboru), [graphics verification](../graphics.md#rozsah-overeni).
4. Dependencies: existing SVG/PNG resources and image-loading contract; visible coverage [R-0224](canceled/R-0224.md) consumes the result. The [accepted manual](../graphics.md#minimalisticky-graficky-manual) governs new or changed exports; this does not require a wholesale art redesign.
5. Primary area: [A03](areas.md#a03).
6. Related areas: A05 tile atlas, A07 building atlas, A01 menu imagery.
7. Origin: documented nonreproducible/partly manual export risk, not a claim that every existing PNG is incorrect.

## 1. Summary

1. A contributor can regenerate the selected runtime images from their editable sources with a recorded recipe and check that the result maps to the intended game asset.
2. This requirement owns the export/manifest path; R-0224 owns what the final game shows.

## 2. Behavior

1. Each maintained source image has a clear output filename, dimensions, crop/layer choice, atlas cell/alias and consumer, plus final logical display size and stroke role under the [shared stroke contract](../graphics.md#stejna-tloustka-car-na-obrazovce). Running the documented export produces the expected assets in a temporary location without silently including helper layers or replacing unrelated resources.
2. Validate transparency, orientation, format and cropped variants against the runtime loader contract. A changed source and its generated runtime asset enter the same change; exact pixel identity is required only for unchanged reference inputs where the chosen renderer supports it.
3. A new contributor can repeat the export and understand any deliberate hand-authored exception from the manifest. No mass replacement of unrelated historical art is implied.

4. Maintained exports preserve the [2026-10-24 shared visual contract](../graphics.md#minimalisticky-graficky-manual): reference-palette solid fills without internal effects, approximately uniform final-size strokes and the agreed typography wherever text is part of the asset.
5. Fog-related sources and exports must support the [R-0261 map presentation](done/R-0261.md): solid gray unknown territory without baked-in grid or texture effects. The procedural explored-area grid remains a GUI rendering responsibility.

6. Terrain appearance follows [R-0277](done/R-0277.md) and its [shared graphics contract](../graphics.md#ridsi-znacky-terenu-a-ziva-voda-25-rijna-2026): one flat colour and sparse transparent drawing, meaningful-overlay priority, stable land and staggered water. This focused change does not close the broader audit.

7. Technical design (implemented candidate, 2026-11-01): [export-manifest.json](../../akropia-game/src/graphics/export-manifest.json) is the single recipe list, grouped by family (`buildings`, `goods`, `units`, `terrain-fog`, `colonies`, `controls`, `menu`, `harbor`, `legacy-raster`). [export-graphics.py](../../scripts/graphics/export-graphics.py) uses only the Python standard library, `rsvg-convert` and `with-fonts.py`. Render kinds `native`, `size`, `zoom`, `viewbox`, `crop` and `atlas` encode the documented R-0265, R-0266, R-0278, R-0384 and per-asset commands. `preserved` entries are only checked for format and size. `export-buildings.py` becomes a shortcut for the `buildings` group with its previous commands. The default output is a fresh temporary directory. `--output` must be new or empty and outside the source/runtime trees, `--check` never writes, and only `--install` replaces runtime files, after every selected export has passed. Helper SVGs stay in a separate temporary directory.
8. Inventory classification and the 39 runtime files outside the manifest are recorded in the [graphics manifest section](../graphics.md#manifest-exportu-r-0225). Remaining uncertain recipe: the `sunset*` viewBox, whose exact 2026-10-25 numbers were not recorded.
9. Verification on 2026-11-01: all 13 graphics tooling tests passed, and all 62 maintained exports matched runtime bytes with librsvg 2.61.4. The full model run had 4,861 tests and only the explicitly permitted pre-existing FRIGATE failure. No Java, vector source or runtime image changed. [Exact evidence and limitations](../functional-tests.md#r-0225-reproducible-graphics-export-2026-11-01). Status remains ready for development until the user's single final batch smoke check.
