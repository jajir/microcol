# R-0240 — Verify Steam install, offline play and update recovery

1. Status: new
2. Updated: 2026-10-17
3. Related: P32; [installed-build test scope](../implementation-estimate.md#missing-publishing-and-delivery-work), [Steam platform findings](../implementation-estimate.md#platform-requirements-and-project-findings).
4. Dependencies: private Steam depots [R-0239](R-0239.md), stable candidate [R-0236](R-0236.md), Mac/Linux acceptance [R-0234](R-0234.md)/[R-0235](R-0235.md), saved-state contract [R-0068](done/R-0068.md).
5. Primary area: [A01](areas.md#a01).
6. Related areas: A04 save preservation, A03 launch/feedback; P31 journey regression.
7. Origin: customer-style Steam installation acceptance, separate from uploading a build and from ordinary package tests.

## 1. Summary

1. A Steam-installed build survives clean install, offline play, update, verification/reinstall and rollback on supported Linux and Mac targets.
2. Existing user saves and settings remain available according to an explicit release update policy.

## 2. Behavior

1. From clean accounts/environments, install and launch each supported depot, play a representative journey offline, save/Continue, return online, update to the next candidate, verify/reinstall and switch back to a known-good branch. Record the exact build, OS/runtime, steps and state before/after.
2. Validate install location versus external user-data location. Updating/rolling back does not silently delete or relocate save files; whether a version can load a different schema follows an explicit stable-compatibility policy, with recovery guidance for rejected saves. Do not assert historical-save migration merely from this test.
3. Test failure cases such as missing permissions or native library with actionable diagnostics. A passed upload or platform build alone does not satisfy this installed-client gate.

## 3. Implementation steps

1. Prepare clean Steam-client matrices and controlled saved-state fixtures, run representative player paths on each chosen target, and route actual defects to package, persistence or feature owners.
2. Current result: captured installed-build acceptance; no Steam-client run has been verified by this document.

## 4. Open questions

1. What backward-compatibility and rollback policy applies to saves created by a public stable version? The development no-migration rule does not decide post-release updates.
