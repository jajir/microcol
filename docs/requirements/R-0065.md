## 1. Summary

1. The player needs a new map choice that produces a valid, playable world and can be reproduced for verification.

2. Current situation: The current setup selects bundled maps, including R-0027’s RivalExpedition; it does not generate a New World from climate/landmass choices.

3. Scope: the outcome and examples below. This is captured work awaiting individual refinement; it does not reopen the delivered origin scope or close a whole UC.

## 2. Behavior

Proposed acceptance for refinement; inherited resolved decisions remain agreed.

1. Select the generated-world option and its supported climate/landmass choices → preview the choices and start a valid world.

2. The generated world has legal sea access, arrival lanes and usable starting positions for its participants; it must support the existing outward-voyage rule.

3. Back or failed generation leaves the active game and Continue unchanged and explains the failure.

4. Identical agreed generation inputs and seed reproduce the same starting terrain. Saving/continuing preserves the actual generated world.

## 3. Implementation steps

1. Preparation awaits selection. Inspect setup/scenario assembly, model profile validation and persistence; reuse existing setup controls under the [package responsibility map](../architecture.md). Keep rule validation before mutation and use current-schema fixtures.

2. Observation basis: the 2026-10-14 [migration baseline](migration-2026-10-14.md#verification-baseline). Source inspection and catalogue findings are not fresh acceptance of these examples; recheck the selected paths before choosing a design.

3. Verification to prepare: Add generator invariants and a setup/start/save journey; retain all bundled-map choices and their stable scenarios. Allocate any new scenario IDs during refinement; old unimplemented proposals do not reserve TC numbers. Follow the [functional test contract](../functional-tests.md).

4. Current result: not implemented or accepted by this migration. Retain already working portions described above; record actual changes and checks only when this requirement is selected and delivered.
