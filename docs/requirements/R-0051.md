## 1. Summary

1. The player needs one calendar for the displayed date, saved position and historical statistics, advancing once per complete round.
2. Source findings on 2026-10-15: `Calendar.getCurrentYear` uses 1600 as the seasonal base even for a later scenario start, so a 1630 start with one elapsed round calculates 1600. `getYearForTurnNo`, used by statistics, adds every round as a year. The late-start test checks only zero elapsed rounds. These are source findings, not executed regression results.
3. Free-play and the first two bundled campaign starts already use 1490; `thrive` still starts in 1630. Apply the [agreed calendar](../gap-analysis.md#calendar-and-starting-expeditions) to all newly created bundled games. Preserve campaign objectives and current-schema saved positions; the manual's 1500 start remains an intentional departure.

## 2. Behavior

Agreed calendar and acceptance, refined on 2026-10-15; implementation is pending.

1. Every new available free-play map and bundled campaign mission starts at 1490 with no displayed season and zero completed rounds. Loading a position preserves its stored start and elapsed rounds, including later-date test scenarios; opening it never rewrites the file or resets its date.
2. For a 1490 start, completed-round indexes 109, 110, 111, 112, 113 and 114 display 1599 without a season, spring 1600, summer 1600, autumn 1600, winter 1600 and spring 1601. No nation within the same round advances that date separately.
3. A stored scenario beginning in 1630 advances spring → summer → autumn → winter 1630 → spring 1631. It never jumps back to the global 1600 boundary. Save/Continue at every boundary retains the same year, season and round index.
4. Historical statistics convert their stored round indexes with the same calendar rule. Four seasonal points can share a calendar year; none is relabeled as a later year merely because another season passed. Calendar queries do not mutate the current date.
5. Reject negative elapsed-round data and negative historical round queries. Preserve existing valid earlier/later scenario starts and the configured end-year boundary: once the end year is reached, another round is rejected without changing it. Global scoring/end-date changes remain with their own requirements.
6. Use [national turn processing](../gap-analysis.md#national-turn-processing) for one advance after all present actors, including Crowns. Opening colony/Europe/report screens, saving or Continue adds no round. This calendar change does not introduce an independence date exception: [R-0105](R-0105.md) owns replacing the existing obsolete 1700/three-colony gates with national support, including the updated `thrive` scenario.
