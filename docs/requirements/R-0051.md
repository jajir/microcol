## 1. Summary

1. The player needs the displayed year and seasons to follow the agreed game profile, with one calendar advance after a complete round.

2. Migration observation (2026-10-14): The reference calendar still starts in 1490 and changes season frequency in 1600; the manual-based catalogue specifies a 1500 start. The accepted calendar below retains 1490 and the existing season schedule; tests still need the complete acceptance matrix.

3. Scope: the outcome and examples below. This is captured work awaiting individual refinement; it does not reopen the delivered origin scope or close a whole UC.

## 2. Behavior

Proposed acceptance for refinement; inherited resolved decisions remain agreed.

1. Start the reference game → show its agreed initial year and season; loading an existing current-schema game preserves its stored date.

2. Complete all participating nations’ turns → advance the calendar exactly once. Opening a screen or continuing a save never advances it.

3. At each agreed season-frequency boundary, the last turn before and first turn after it show the expected dates; no year or season is duplicated or skipped.

4. The user-selected start is 1490 for newly created games, including bundled campaign starts when their fixtures are updated. Existing saves retain their stored date; later-date test fixtures remain valid boundary setups. The manual’s 1500 date stays documented as a deliberate departure.

5. Accepted behavior (2026-10-15; [calendar and starting expeditions](../gap-analysis.md#calendar-and-starting-expeditions)): Use the fixed 1490 start and the retained year/season schedule; save/load preserves the date.
