# R-0037 — Safe Guava dependency update

## 1. Summary

1. Authorized 2026-10-14: replace the Guava 32.0.0 proposal in PR #46 with
   stable `32.1.3-jre`. Keep Log4j PR #47 separate.
2. Primary area: [A03](areas.md#a03), shared development support. Cross-area
   dependency: preference persistence tests supporting A04. No gameplay change.
3. Status: locally verified on Linux/JDK 17; platform CI pending.

## 2. Behavior

1. Guice remains `4.2.2:no_aop`. Existing production Guava APIs must compile;
   injection, singleton scopes and EventBus delivery must work together.
2. Preference tests use JUnit `@TempDir`, backed by Java NIO and automatic
   cleanup, instead of deprecated Guava `Files.createTempDir`. The inherited
   setting file becomes per-test rather than a shared static file.
3. [Guava 32.0.1](https://github.com/google/guava/releases/tag/v32.0.1)
   fixes the Windows regression. Chosen
   [32.1.3](https://github.com/google/guava/releases/tag/v32.1.3) also fixes
   Windows-service temporary-file behavior on Java 9+. This is a conservative
   update within the proposed major version, not a claim of latest-version status.

## 3. Implementation steps

1. Update the direct Maven dependency. Inspect the verbose dependency tree for
   the older Guava requested by Guice and presence of `failureaccess`.
2. Replace all three temporary-directory call sites, retain persistence
   assertions, and add a production-stage Guice/EventBus compatibility test.
3. Run game `clean verify`, dependency-tree inspection, shared Java formatter,
   documentation checks and strict MkDocs. Check game assembly and Java module
   packaging. Full player regression and native packaging remain in existing CI.
4. Add game verification on Linux/Windows, Java 11/17, with retained Surefire
   reports. A configured workflow alone does not establish a Windows pass.

## 4. Open questions

1. Verified 2026-10-14 on Linux/Temurin 17.0.20.1: game and Java module
   `mvn -B -ntp -pl microcol-game,microcol-module -am verify` passed, including
   1,115 tests, zero failures/errors/skips. Full-JDK setup and the system TLS
   truststore corrected environment-only failures (missing javadoc and proxy CA).
2. Verbose dependency tree resolves only `32.1.3-jre`; Guice requests
   `25.1-android`, omitted for conflict. Resolved Guava support artifacts:
   `failureaccess:1.0.1`, empty `listenablefuture:9999.0-empty-to-avoid-conflict-with-guava`,
   `checker-qual:3.37.0`, `error_prone_annotations:2.21.1`,
   `j2objc-annotations:2.8`. The assembled game JAR includes
   `InternalFutureFailureAccess` and the chosen Guava metadata.
3. Shared Eclipse XML formatter applied with JDT Core 3.43.0 and Java 11
   source level to all changed Java files. Nine documentation checks and
   strict MkDocs passed. No local Docker or Windows runtime is available.
4. Full player regression/native publication and Windows/Java 11 verification
   remain CI checks; configuration alone is not a passing platform result.

5. First Windows CI attempt on Java 11 and 17 ran all 1,115 tests and
   exposed two cleanup errors in SettingDaoTest: its debug reader was never
   closed, preventing Windows deletion. The reader now uses try-with-resources.
   Linux Java 11/17 passed the first platform run. Windows recheck pending.
