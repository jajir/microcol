# R-0389 — Úplné přejmenování MicroCol na Akropia

1. Status: new
2. Updated: 2026-11-01
3. Related: P27–P29 v [implementačním plánu](../implementation-plan.md#seznam-pracovnich-baliku); UC-001 (Nastavení), UC-119 (Regrese) v [katalogu use cases](../use-cases.md); [moduly a výstupy](../modules.md), [distribuce](../distribution.md), [vývojové doručování](../development-builds.md) a [publikování dokumentace](../publishing.md).
4. Dependencies: současný Maven reactor, spouštěče, distribuční a dokumentační postupy. Pozdější přejmenování GitHub repozitáře provede uživatel samostatně a neblokuje tento požadavek.
5. Primary area: [A03](areas.md#a03), jednotný název produktu a jeho prezentace.
6. Related areas: A01 spuštění, nabídky a navigace; A04 názvy úložišť, nastavení a uložených her. Technický přesah do všech modulů nemění vlastnictví herních pravidel podle [mapy odpovědností](../architecture.md).
7. Origin: požadavek uživatele z 1. listopadu 2026 na nahrazení všech názvů MicroCol, včetně Maven modulů, s jedinou výjimkou dosavadního GitHub projektu. Uživatel následně výslovně potvrdil zápis **Akropia / akropia**; varianta s písmenem c není cílovým názvem. Nyní je objednáno zachycení požadavku, nikoli realizace přejmenování.

## 1. Shrnutí

1. Hra i její technický projekt mají používat jediný nový název **Akropia**. Vývojář musí být schopen prohledat aktuální verzované soubory i jejich cesty bez nalezení starého názvu mimo přesně vymezené vazby na dosavadní GitHub repozitář. Změna zahrnuje značku, nikoli jen nadpis hlavního okna.
2. Kontrola zdrojů 1. listopadu 2026 na revizi `fc3c4090619f289cb35b05bafc36e602b32275b3` ukazuje název v UI, dokumentaci, Maven souřadnicích a adresářích, Java balíčcích a třídách, Java modulu, spouštěčích, distribučních souborech, CI a testovacím vybavení. Tyto nálezy jsou inventář zdrojů, nikoli ověření budoucí změny.
3. Požadavek vlastní úplné sjednocení názvu při zachování fungujícího sestavení, spuštění, testů a dokumentačních odkazů. Nezavádí řecká herní pravidla ani novou grafickou koncepci; nepřejmenovává vzdálený GitHub repozitář a neobjednává registraci názvu či vydání na Steamu.

## 2. Chování

1. Hráč i čtenář aktuální dokumentace vidí **Akropia** v nadpisech, názvech oken a aplikace v operačním systému, menu, nápovědě, popiscích, metadatech a současných značkových obrázcích. Pro technické identifikátory se použije `akropia`, pro názvy tříd odpovídající `Akropia` a pro velká písmena `AKROPIA`. Všechny jazykové varianty používají stejný název značky.
2. Vývojář sestaví a spustí projekt pod novými názvy. Přejmenují se všechny vlastní Maven moduly a jejich adresáře, rodičovské a závislostní souřadnice, Java balíčky, třídy a soubory obsahující starý název, Java module name, vlastnosti, proměnné, identifikátory nástrojů, zdroje a odkazy mezi nimi. Nezůstanou vlastní staré aliasy kvůli zpětné kompatibilitě názvu.
3. Distribuce, instalátory, spouštěče, archivy a nově vytvářené pracovní či uživatelské adresáře používají nový název. Sestavení a obsluha chyb zůstávají funkční; přejmenování nesmí potichu odstranit nebo přepsat existující uživatelské pozice a nastavení. Zpětná kompatibilita uložených her není požadována podle [společného kontraktu](../architecture.md); potřebné změny přibalených dat a fixture patří do stejné implementace.
4. Rozsah zahrnuje veškerý projektový obsah pod správou Gitu: zdroje, testy, scénáře, dokumentaci včetně archivních požadavků, komentáře, kořenové instrukce, skrytou konfiguraci IDE/agentů, skripty, Docker, CI, sestavení a publikování. Přesné historické výsledky, data, revize a stabilní R/UC/TC identifikátory se zachovají; úprava názvosloví nesmí vydávat staré ověření za test nové revize. Původní obsah zůstane dostupný v historii Gitu, kterou tento požadavek nepřepisuje.
5. Jedinou věcnou výjimkou jsou vazby na dosud nepřejmenovaný GitHub projekt `jajir/microcol`: jeho skutečný identifikátor a funkční adresy repozitáře, API, raw souborů, issues, commitů, release objektů a odvozená adresa Pages `https://jajir.github.io/microcol/`. Zobrazovaný název webu a projektu už je Akropia. Výjimka neopravňuje ponechat staré lokální moduly, nové artefakty ani jiné výskyty na témže řádku. Nevymýšlejí se dosud neexistující adresy GitHub projektu s novým názvem.
6. Po dokončení implementace kontrola bez rozlišení velikosti písmen nad obsahem i relativními cestami všech verzovaných souborů nenajde `microcol` mimo jednotlivě doložené výskyty podle bodu 5. Kontrola zahrnuje i tento požadavek, backlog a instrukce pro agenty; jejich popis se při dokončení sjednotí s novým názvem. Vyhledávání nesmí záviset na výchozích výlukách IDE či ignorování skrytých souborů. Výskyty se nesmějí skrýt rozdělením slova, kódováním nebo plošným vyřazením souborů z kontroly. Opraví se i nalezené chybné varianty značky, například `MocroCol` v rodičovském POM.
7. Akceptace pracuje s čistým checkoutem a čerstvě vytvořenými výstupy. Staré lokální buildy, historie a interní metadata `.git`, externí Maven cache, již publikované historické binární soubory či adresáře mimo verzovaný projekt nejsou aktuálním zdrojovým stromem; nepřepisují se jako součást textové náhrady. Návody pro nové checkouty uvedou cílový lokální adresář `akropia` i při použití dosavadní GitHub adresy. Nově sestavené výstupy a aktuální značkové obrázky se kontrolují samostatně, protože textové hledání neověří jejich zobrazení.
8. Přejmenování nemění herní výsledky, ovládání, datové identity ani rozsah existujících scénářů. Při zjištění nevyřešené vazby, nefunkčního odkazu nebo neúplných povinných kontrol se změna nepovažuje za dokončenou. Samotný push nepotvrzuje vydání nové herní distribuce.

## 3. Kroky implementace

1. Před výběrem k vývoji doplnit podrobný inventář všech obsahových a cestových výskytů včetně skrytých souborů. Připravit konkrétní seznam nezbytných vazeb na GitHub podle kapitoly 2, bodu 5; automatická kontrola má vyhodnocovat jednotlivé výskyty a odmítat nezdůvodněné zbytky. Znovu prověřit aktuální [mapu odpovědností](../architecture.md), [moduly](../modules.md), [distribuce](../distribution.md) a [doručování](../development-builds.md), neprovádět slepou globální náhradu URL nebo cizích identit.
2. Koordinovaně přejmenovat reactor `microcol-root` a všechny jeho běžné i profilové moduly na prefix `akropia-`, Maven groupId a balíčky `org.microcol` na `org.akropia`, Java modul `microcol.game` na `akropia.game` a odvozené vlastní třídy. Opravit importy, reflexi, FXML, resources, service/DI registrace, serializační odkazy, vstupní body a jlink/jpackage konfiguraci. Sdílené vlastnictví modelu, UI a AI zůstane zachováno; Java změny musí projít [společným formatterem](../code-formatting.md).
3. Současně upravit testy a fixture, konfiguraci IDE/agentů, Docker a shell/Python nástroje, názvy proměnných a locků, launcherové manifesty a očekávání publikovaných artefaktů. Existující běžící cizí úlohy a jejich data nezasahovat. Zastaralé externí metadata, například původní SourceForge adresu, nahradit platným kanonickým odkazem nebo odstranit; pouhá výměna názvu hostitele není ověření adresy. Zachovat funkční GitHub a Pages vazby do samostatné změny uživatele.
4. Sjednotit aktuální i archivní projektové texty, názvy dokumentačních souborů a odkazy. Aktualizovat zejména `docs/modules.md`, architektonické odkazy, návody, README, `AGENTS.md` a konfiguraci MkDocs. Referenční modul `microcol-site` zachovat obsahově jako přejmenovaný `akropia-site`; nerozšiřovat jeho publikaci a nezaměnit jej za web z `docs/`. Současná grafika nesoucí starý název se upraví podle [grafického zdrojového kontraktu](../graphics.md#zdrojovy-format-herni-grafiky); nové rasterové obrázky nesmějí nahradit požadovaný skutečný SVG zdroj.
5. Při refinementu stanovit konečný seznam cílených kontrol nad tehdy aktuálním kódem. Výchozí kandidáti jsou `TC_12_F11_start_free_game`, `TC_21_F15_free_play_screen_navigation_test`, `TC_84_F75_framed_settings_test`, `TC_191_F224_session_menu_test` a `TC_42_F34_load_recovery_test`; zachovat jejich stabilní ID a herní aserce. Zahrnout relevantní nástrojové a distribuční kontroly, zejména `LauncherTest`, `LauncherPackageIT`, `NativeDistributionIT` a `PublicationTest`, audit názvů čerstvých výstupů a vizuální kontrolu značky. Povinné model/JUnit, cílené Docker/Xvfb UI a smoke kontroly i dokumentační konzistence a striktní MkDocs zůstávají podle [lokální akceptační politiky](../publishing.md#local-acceptance-policy). Jde o plán, nikoli již provedené testy přejmenování.
6. Aktuální výsledek: zachycen požadavek ve stavu `new`; změna názvu není implementována ani ověřena. Technický refinement a výběr realizace teprve následují. Ověření samotného dokumentačního zachycení patří do [publikační evidence](../publishing.md), ne do důkazů herní regrese.

## 4. Otevřené otázky

1. Žádné k potvrzenému názvu a požadovanému rozsahu. Konkrétní inventář vazeb a konečný výběr testů se doplní při technickém refinementu; nejde o důvod znovu otevírat volbu názvu.
