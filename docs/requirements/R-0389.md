## 1. Shrnutí

1. Hra i její technický projekt používají jediný název **Akropia**. Vývojář prohledá aktuální verzované soubory i jejich cesty a původní název najde jen v přesně vymezených vazbách na dosud nepřejmenovaný GitHub repozitář. Změna zahrnuje značku, nikoli jen nadpis hlavního okna.
2. Kontrola zdrojů 1. listopadu 2026 na revizi `fc3c4090619f289cb35b05bafc36e602b32275b3` našla původní název v UI, dokumentaci, Maven souřadnicích a adresářích, Java balíčcích a třídách, Java modulu, spouštěčích, distribučních souborech, CI a testovacím vybavení. Tyto nálezy jsou inventář zdrojů, nikoli ověření změny.
3. Požadavek vlastní úplné sjednocení názvu při zachování fungujícího sestavení, spuštění, testů a dokumentačních odkazů. Nezavádí řecká herní pravidla ani novou grafickou koncepci; nepřejmenovává vzdálený GitHub repozitář a neobjednává registraci názvu či vydání na Steamu.

## 2. Chování

1. Hráč i čtenář aktuální dokumentace vidí **Akropia** v nadpisech, názvech oken a aplikace v operačním systému, menu, nápovědě, popiscích, metadatech a současných značkových obrázcích. Technické identifikátory používají `akropia`, názvy tříd `Akropia` a velká písmena `AKROPIA`. Všechny jazykové varianty používají stejný název značky.
2. Vývojář sestaví a spustí projekt pod novými názvy. Všechny vlastní Maven moduly a jejich adresáře, rodičovské a závislostní souřadnice, Java balíčky, třídy a soubory, Java module name, vlastnosti, proměnné, identifikátory nástrojů, zdroje a odkazy mezi nimi používají nový název. Nezůstávají vlastní staré aliasy kvůli zpětné kompatibilitě názvu.
3. Distribuce, instalátory, spouštěče, archivy a nově vytvářené pracovní či uživatelské adresáře používají nový název. Sestavení a obsluha chyb zůstávají funkční; přejmenování nesmí potichu odstranit, přesunout nebo přepsat existující uživatelské pozice a nastavení pod původním názvem. Hra je nečte ani nemigruje. Zpětná kompatibilita uložených her není požadována podle [společného kontraktu](../architecture.md); přibalená data a fixture používají nové názvy.
4. Rozsah zahrnuje veškerý projektový obsah pod správou Gitu: zdroje, testy, scénáře, dokumentaci včetně archivních požadavků, komentáře, kořenové instrukce, skrytou konfiguraci IDE/agentů, skripty, Docker, CI, sestavení a publikování. Přesné historické výsledky, data, revize a stabilní R/UC/TC identifikátory se zachovávají; úprava názvosloví nevydává staré ověření za test nové revize. Původní obsah zůstává dostupný v historii Gitu, kterou tento požadavek nepřepisuje.
5. Jedinou věcnou výjimkou jsou vazby na dosud nepřejmenovaný GitHub projekt `jajir/microcol`: jeho skutečný identifikátor a funkční adresy repozitáře, API, raw souborů, issues, commitů, release objektů a odvozená adresa Pages `https://jajir.github.io/microcol/`. Zobrazovaný název webu a projektu je Akropia. Výjimka neopravňuje ponechat staré lokální moduly, nové artefakty ani jiné výskyty na témže řádku. Nevymýšlejí se dosud neexistující adresy GitHub projektu s novým názvem.
6. Kontrola [`scripts/docs/name_audit.py`](../../scripts/docs/name_audit.py) prochází bez rozlišení velikosti písmen obsah i relativní cesty všech verzovaných a nově přidaných neignorovaných souborů a vyhodnocuje každý výskyt původního názvu zvlášť. Přijme jen segmenty podle bodu 5, odkazy na soubory v pevné historické revizi a historicky publikované release assety; jinak skončí chybou. Nezávisí na výlukách IDE, nevyřazuje celé soubory ani řádky a hledá i chybnou variantu značky z rodičovského POM. Výskyty se nesmějí skrýt rozdělením slova nebo kódováním. Kontrola běží v dokumentačním workflow.
7. Akceptace pracuje s čistým checkoutem a čerstvě vytvořenými výstupy. Staré lokální buildy, historie a interní metadata `.git`, externí Maven cache, již publikované historické binární soubory či adresáře mimo verzovaný projekt nejsou aktuálním zdrojovým stromem a nepřepisují se. Návody pro nové checkouty uvádějí cílový lokální adresář `akropia` i při použití dosavadní GitHub adresy. Nově sestavené výstupy a aktuální značkové obrázky se kontrolují samostatně, protože textové hledání neověří jejich zobrazení.
8. Přejmenování nemění herní výsledky, ovládání, datové identity ani rozsah existujících scénářů. Při zjištění nevyřešené vazby, nefunkčního odkazu nebo neúplných povinných kontrol se změna nepovažuje za dokončenou. Samotný push nepotvrzuje vydání nové herní distribuce.

## 3. Kroky implementace

1. Inventář všech obsahových a cestových výskytů včetně skrytých souborů se obnovuje z aktuálního main. Nezbytné vazby na GitHub podle kapitoly 2, bodu 5 vyhodnocuje [auditní skript](../../scripts/docs/name_audit.py) po jednotlivých výskytech; jeho pravidla pokrývá `scripts/docs/test_name_audit.py`. Před změnou se znovu prověřují [mapa odpovědností](../architecture.md), [moduly](../modules.md), [distribuce](../distribution.md) a [doručování](../development-builds.md); URL a cizí identity se nenahrazují slepě.
2. Reactor `akropia-root` a všechny jeho běžné i profilové moduly používají prefix `akropia-`, Maven groupId a balíčky `org.akropia`, Java modul `akropia.game` a odvozené vlastní třídy. Importy, reflexe, FXML, resources, service/DI registrace, serializační odkazy, vstupní body a jlink/jpackage konfigurace se mění společně. Sdílené vlastnictví modelu, UI a AI zůstává zachováno; Java změny procházejí [společným formatterem](../code-formatting.md).
3. Testy a fixture, konfigurace IDE/agentů, Docker a shell/Python nástroje, názvy proměnných a locků, launcherové manifesty a očekávání publikovaných artefaktů se upravují současně. Existující běžící cizí úlohy a jejich data se nezasahují; nový lock a nové Docker identity se před prvním použitím ověřují proti běžícím úlohám. Zastaralá externí metadata, například původní SourceForge a Travis adresy, jsou nahrazena skutečným GitHub projektem, jeho releases a Actions, případně odstraněna. Funkční GitHub a Pages vazby zůstávají do samostatné změny uživatele.
4. Aktuální i archivní projektové texty, názvy dokumentačních souborů a odkazy jsou sjednocené, zejména `docs/modules.md`, architektonické odkazy, návody, README, `AGENTS.md` a konfigurace MkDocs. Referenční modul `akropia-site` zachovává obsah a referenční roli; jeho publikace se nerozšiřuje a nezaměňuje s webem z `docs/`. Značkový text v `logo.svg` a `icon.svg` je upravený přímo ve vektorovém zdroji podle [grafického zdrojového kontraktu](../graphics.md#zdrojovy-format-herni-grafiky); vložené podmnožiny fontu a odvozené PNG/ICNS se obnovují opakovatelným exportem, nikoli novými rastrovými zdroji.
5. Cílené kontroly vycházejí z tabulky v bodě 10. Stabilní ID scénářů a herní aserce se zachovávají. Povinné model/JUnit, cílené Docker/Xvfb UI a smoke kontroly i dokumentační konzistence a striktní MkDocs zůstávají podle [lokální akceptační politiky](../publishing.md#local-acceptance-policy).
6. Aktuální výsledek: přejmenování je implementováno; 48 cílených UI testů a 36 testů spouštěče prošlo. Modelová kontrola má pouze výslovně povolenou výjimku FRIGATE. Závěrečná společná přejímka dávky a nativní distribuční profily zůstávají otevřené. Podrobnosti včetně historických selhání vede [funkční evidence](../functional-tests.md#r-0389-akropia-project-rename-2026-11-02); nejde o potvrzení publikace.
7. Inventář zdrojů z 1. listopadu 2026 na `949a4fab`: průchod všemi 3 309 soubory z `git ls-files` (včetně skrytých) našel původní název nebo jeho chybnou variantu bez rozlišení velikosti písmen v textovém obsahu 2 155 souborů a v 2 456 cestách. Počty se překrývají; cesta uvnitř modulu neznamená značku uvnitř obrázku. Obnovený inventář 2. listopadu 2026 na `4cf07149` zahrnul 3 368 souborů, z toho 2 196 s výskytem v textu, dva binární archivy legacy webu a 2 498 cest.
