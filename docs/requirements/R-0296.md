## 1. Summary

1. Make unknown-map question marks look like the surrounding hand-drawn map artwork.
2. At source revision `0a85fe547218dd4e23107ef91acbe30e3486fdf7`, the current mark is a small, light-brown Playpen Sans 14 glyph. The supplied screenshot shows weaker visual weight than the map contours.
3. Prepare comparable alternatives before selecting a game change. The [comparison](../graphics-assets/question-marks-2026-10-26/comparison.png) shows the current glyph, enlarged details and schematic map samples with actual terrain drawings.

## 2. Behavior

1. Proposed A, B and C replace the text glyph with a drawn symbol: A has a compact rounded hook, B a wider leaning hook, C a slightly angular sketch-like hook. A is the recommendation, not a selected design.
2. All three proposals use rounded 1.6-pixel strokes in the terrain contour color `#292824`, with an approximately 20–22-pixel ink height inside a 45-pixel map square. These are proposed artwork measurements, not a change to the Playpen Sans 14 typography rule.
3. A later implementation must retain the existing approximately 4% frequency, saved-seed placement, fixed map position and permanent disappearance after exploration. Shape, position and tilt must not animate or change during repainting, panning, resizing or Continue.
4. The decoration appears automatically and has no action or cancellation path. It must remain legible without revealing hidden terrain or adding a control.

## 3. Implementation steps

1. Store the three editable vector alternatives and their comparison as documentation assets; keep runtime code and atlases unchanged during this proposal request.
2. After the user selects a design and development, reuse the existing unknown-mark drawing in `gui.util.PaintService` and the stable selection in `gui.image.ImageRandomProvider`; do not add a font weight, dependency, save field or package responsibility.
3. Preserve `TC_26_F18_fog_of_war_test.TC_10_unknown_question_marks_remain_fixed_until_explored`, update its rendered-pixel reference for the selected symbol, and retain the density, fog/privacy and resource checks. Runtime acceptance then requires the shared formatter, affected player scenarios and the complete model/JUnit plus fixed Docker/Xvfb smoke gate.
4. This document and the proposals require documentation consistency checks, strict MkDocs and visual review only. Record their results in the [documentation evidence](../publishing.md#r-0296-question-mark-proposals-2026-10-26).
