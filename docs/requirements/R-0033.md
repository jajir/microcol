# R-0033 — Run routine UI tests in Docker

1. Status: Implemented and locally verified
2. Updated: 2026-10-13
3. Related: [P31](../implementation-plan.md#seznam-pracovnich-baliku), [functional test contract](../functional-tests.md); regression infrastructure, no gameplay rule change.
4. Dependencies: Docker Engine/Compose, existing Maven/JDK 17 and TestFX suite.
5. Primary area: [A03](areas.md#a03), reliable verification of player-facing controls.
6. Related areas: existing TC scenarios cover multiple areas; their acceptance and ownership remain unchanged.

## 1. Summary

1. The user agreed on 2026-10-13 that routine UI tests should primarily run in
   Docker, avoiding dependence on an unlocked macOS desktop.
2. At `595038b3`, CI already uses Linux/Xvfb/Openbox but no reusable local
   container configuration exists. Native macOS tests fail to interact with
   the locked desktop; Monocle cannot cover all drag-and-drop paths.
3. Provide one Docker test command for local work and CI. Keep platform-specific
   manual inspection separate from ordinary automated acceptance.

## 2. Behavior

1. The default command runs the complete existing game and functional suites
   with JavaFX Glass in a private Xvfb/Openbox session, without host display
   access, exposed desktop ports or an unlock request.
2. A read-only checkout is copied into a disposable, space-free container
   workspace. Personal saves, source fixtures and host Maven settings are not
   modified. A dedicated Docker volume caches Maven dependencies.
3. Each invocation preserves a separate result directory under
   `target/docker-ui/`, including Maven/Xvfb/Openbox logs, available Surefire
   reports, warehouse screenshots and the exit status, also after test failure.
4. A failing test or setup step fails the command and the CI publication gate.
   No assertions, stable TC IDs, expected outcomes or test counts are weakened.
5. Docker unavailability is a runtime problem to diagnose. Do not fall back to
   native macOS interaction or request unlocking for routine tests. CI remains
   an available independent Linux execution route.

## 3. Implementation steps

1. Add a Maven/JDK 17 Linux image with JavaFX libraries, Xvfb and Openbox, a
   Compose service and a small test entrypoint. Use Linux amd64 consistently
   with CI, including on Apple Silicon through Docker's emulation.
2. Delegate the bounded entrypoint to local Qwen. The caller owns environment
   configuration, review, integration and verification. No Java/package
   responsibilities or player behavior change.
3. Run the full baseline selection (683 game and 64 functional-suite checks),
   check failure propagation and retained reports, and verify source fixtures
   remain unchanged. Existing TC05/TC06 and TC23 cover drag/drop paths that
   Monocle cannot reliably execute. No new gameplay scenario is appropriate.
4. Use the same container command for the required CI functional job, retain
   artifacts on failure, update the shared instructions and module-output map,
   run documentation checks/strict MkDocs, and verify publication on `main`.

Verification, 2026-10-13: Docker Desktop started through its CLI
without an unlock request. Runner checks passed success, Maven exit 7,
export failure, clean snapshot and quoted argument cases. The first full run
passed 683 game tests but exposed a 1 GiB JVM heap limit in TC19 and window
interaction failures in TC22. Set the test JVM heap explicitly to 2 GiB within
the 4 GiB container, keeping Maven at 768 MiB. Targeted TC19/TC22 then passed
all 22 checks with no failures/errors/skips (`run-i4TsZE`); TC22's earlier
interaction failures did not recur, without Java changes. All 22 source fixture
checksums remained unchanged, warehouse screenshots were exported, and the
limited-transfer dialog screenshot was inspected.

The full default Compose command then passed **683 game tests and 64
functional-suite checks, zero failures/errors/skips**, in 10 minutes 27 seconds
on the Apple Silicon host using Linux amd64 emulation. Result `run-6BVsG8`
retained exit code 0, both modules' Surefire XML and screenshots. All 22 source
fixture checksums still matched. TC05, TC06 and TC23 passed without any Java or
assertion changes. Bash syntax, Compose validation, nine documentation unit
tests and strict MkDocs also passed. Evidence, including the first failed run,
is retained under `~/Library/Logs/Microcol/docker-ui/2026-10-13/`.

The required CI job repeats runner checks and the full suite for each pushed
revision; its artifacts and publication result remain attached to that
[development workflow run](https://github.com/jajir/microcol/actions/workflows/dev-builds.yml).
Worker attempts and caller takeover are recorded in the
[local Qwen evidence](../ai/local-qwen.md#docker-ui-runner-2026-10-13).
