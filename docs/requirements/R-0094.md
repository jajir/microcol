## 1. Summary

1. The player needs battle odds to respond to the same strengths the game explains before an attack.

2. Migration observation (2026-10-14): The inspected combat path uses a fixed win probability; R-0028 deliberately left outcome arithmetic unchanged.

3. Scope: the outcome and examples below. Selected for linked refinement on 2026-10-16; it does not reopen the delivered origin scope or close a whole UC.

## 2. Behavior

Agreed acceptance, refined from the shared combat rules on 2026-10-16.

1. For the agreed ordinary attacker/defender pairs, compute the outcome chance from the displayed final strengths using one documented formula.

2. Use one combat draw only after successful confirmation/revalidation; canceled or stale commands draw nothing and cause no battle.

3. Controlled low/high draws exercise both outcomes with the agreed movement exhaustion and existing ownership/selection cleanup.

4. An ordinary defeated dragoon loses its horses and survives as a soldier; a defeated soldier loses its muskets and survives unarmed. Preserve identity, specialty, owner and location; both units remain on their original tiles while the loser survives. Equipment is lost, not transferred. Clear an invalidated fortification order without restoring movement. Save/continue preserves the resolved equipment and random state without replay. Veterans, artillery, naval outcomes and civilian capture use their own linked scope.

5. Accepted behavior (2026-10-15; [combat and naval outcomes](../gap-analysis.md#combat-and-naval-outcomes)): Resolve battles from the agreed strength ratio and persisted random state, including zero/equal-strength boundaries.

## 3. Implementation steps

1. Use R-0093's exact immutable strength calculation for both displayed terms and ordinary land resolution. Revalidate the selected defender and complete strength snapshot before mutation. Draw one uniform value in [0,1) and compare strictly with A/(A+D); positive A against zero D succeeds, zero A cannot initiate and both-zero is rejected. Exhaust both participants. For ordinary armed colonists apply the agreed equipment loss, preserving location and identity instead of destroying the loser or advancing onto its occupied tile. Promotions remain R-0111, civilian capture R-0096, naval damage R-0097. The battle event must distinguish the defeated unit from an actually destroyed unit so GUI animation does not depict a surviving unit as killed.

2. Source inspection (2026-10-16, main `92c5b806`): `AbstractUnit.random` is private per-unit `java.util.Random`, currently not saved. Add model-owned persisted combat RNG state with deterministic advancement; previews/cancel/rejected stale commands must not advance it. Initialize state explicitly when creating a new game and update bundled current-schema maps/test fixtures; reject missing or invalid required state on load without migrations. Keep weather and Congress random paths outside this bounded change.

3. Test exact probability boundaries (below/equal/above 3/7 and 1/2), valid zero defense, forbidden zero attack, no draw on canceled/rejected quotes, one draw per accepted battle, identical continuation from saved RNG state, and no replay after a resolved result. Existing controlled-outcome tests must control the new model source rather than rely on reflected per-unit random fields. Retain TC35 player checks and add ordinary strength-based confirmation/Continue evidence.

4. Deliver together with [R-0093](R-0093.md), after its shared calculation and R-0106 effective state are available. Use one model-owned SplitMix64 state step per ordinary battle, stored as a required `Long combatRandomState` in `ModelPo`; all long values are valid, absence is invalid. Convert the high 53 output bits to a uniform double. Initialize authored new games explicitly and update actual model-root fixtures, leaving voyage weather RNG unchanged. Model tests control persisted state rather than adding a public testing-only setter. R-0106 is integrated; the bounded worker owns model and fixture changes, main owns GUI/TC35. No new battle acceptance is claimed yet.

5. Implemented and locally verified on 2026-10-16 in `codex/r93-combat`: full model suite 1681 passed, subsequent fortified-loss tests 5 passed, and repaired TC35 plus page-contract selection 15 passed.
