# R-0318 — Match unexplored tile previews to map fog

1. Status: new
2. Updated: 2026-10-27
3. Related: UC-006/114/119 in [use cases](../use-cases.md), MAP-007/008 in the [rule catalogue](../gap-analysis.md), P04 in the [implementation plan](../implementation-plan.md).
4. Dependencies: existing exploration/current-sight policy from [R-0069](done/R-0069.md) and [R-0070](done/R-0070.md); fog edges from [R-0268](done/R-0268.md); stationary unknown marks from [R-0282](done/R-0282.md).
5. Primary area: [A03 — screens and shared UI language](areas.md#a03).
6. Related areas: A05 supplies exploration and permitted observations; no change to its rules.
7. Origin: user's screenshot and request on 2026-10-27 to explain the dark right-panel preview of a gray unexplored square and propose a correction. Analysis only; implementation has not been selected.

## 1. Summary

1. A player selects a map square to inspect it. An unexplored square should have the same recognizable fog appearance in the right panel as on the map, without disclosing its terrain or occupants.
2. The supplied screenshot shows gray-beige fog on the map and a nearly black square beside “Unknown” in the panel. Source inspection on 2026-10-27 at `c9d172e18375dc891edf2bb8fdf3e8414f3bda84` confirms separate rendering paths; this is not a newly reproduced runtime test.
3. Proposed scope: correct unexplored previews and preserve existing exploration, information filtering and discovered previews. Full equivalence of every discovered-map layer is a broader outcome, described as a limitation in chapter 3 rather than silently included here.

## 2. Behavior

1. Proposed main path: on the main game screen, clicking any unexplored square shows the same gray-beige fog in the right-panel preview. If that particular square has a question mark on the map, the preview has the same mark; an unmarked square remains unmarked. The localized “Unknown” label remains.
2. Selecting an unexplored square after a known square with a colony or unit removes the previous preview completely. The preview reveals no terrain, resource, river, unit, colony or native settlement hidden by exploration. Selection changes neither exploration nor game state and needs no confirmation or cancellation dialog.
3. Panning, resizing and Save/Continue preserve the appearance associated with the same square. Once the square is explored, selecting it shows its existing discovered preview; leaving present sight does not make explored terrain unknown again. Current-sight and remembered-colony rules remain authoritative.
4. Check marked and unmarked unknown squares, map borders and the exploration frontier. Existing rounded fog edges on discovered squares remain intact. Selection outlines, movement indicators and transient animation are not terrain content; this proposal does not add them to the preview. Existing static terrain illustrations remain governed by the [visual brief](../graphics.md#soucasne-zadani-vzhledu) and [UX guidelines](../ux.md).

## 3. Implementation steps

1. Confirmed cause at the inspected revision: [GamePaintService](../../microcol-game/src/main/java/org/microcol/gui/screen/game/gamepanel/GamePaintService.java) fills unknown tiles with `#9B9486` in `paintHiddenTile`; its final `paintFog` pass also calls `PaintService.paintUnknownMark` with the selected location. [RightPanelView](../../microcol-game/src/main/java/org/microcol/gui/screen/game/components/RightPanelView.java), in the unexplored branch of `refreshView`, instead requests `ImageLoaderTerrain.IMG_TILE_HIDDEN`. [ImageLoaderTerrain](../../microcol-game/src/main/java/org/microcol/gui/image/ImageLoaderTerrain.java) maps that key to the dark `type_10_3` cell of `background.png`. [TilePainter](../../microcol-game/src/main/java/org/microcol/gui/screen/game/components/TilePainter.java) draws that image directly. The atlas was visually inspected; no UI screenshot was generated in this analysis.
2. Smallest proposed correction: move the existing fog-fill operation into [PaintService](../../microcol-game/src/main/java/org/microcol/gui/util/PaintService.java), use it from both current map passes and the panel, and reuse `paintUnknownMark` with the actual location in the panel. Preserve the final map fog pass and its ordering. Clear the whole preview canvas before composing a newly selected unknown tile, including the margins used by colony artwork. Remove the panel's now-unused image-provider dependency only after checking its callers. Do not recolor the atlas as the fix: that would leave the two rendering paths and location-dependent marks inconsistent.
3. Ownership stays in existing `gui.screen.game.components`, `gui.screen.game.gamepanel` and `gui.util` under the [package map](../architecture.md). No model, AI, save schema, localization, runtime artwork, configuration or exported API change is expected. Reuse the existing fog fixture and named scenarios; preserve the colony-field callers of `PaintService.paintTerrainOnTile`.
4. Broader limitation: the panel currently composes terrain, a known European colony and the first observed unit separately. The map also has a separate river pass and native-settlement drawing; those are absent from the panel composition. The panel's static terrain decoration intentionally differs from animated map frames. Therefore this correction cannot claim literal equivalence of all known map content. If that broader outcome is selected, reuse the map's content-layer painters and permitted player observations in a common composition path; avoid a screenshot crop tied to scrolling, selection outlines or transient effects.
5. Proposed verification: add `TC_11_unknown_preview_matches_map_tile` to `TC_26_F18_fog_of_war_test`, with comparisons of the actual map content and panel canvas for marked/unmarked locations and transitions from an occupied known tile. Put assertions in dedicated `FogPage.verify...` methods and exclude the selection outline from comparisons. Reuse TC26/01 for nondisclosure, TC26/02 for exploration/Continue, TC26/03 for animation covering, TC26/09 for frontier/grid edges and TC26/10 for stable marks. Correct `FogPage.verifyRevealedPixels`, which still compares the map against the obsolete dark atlas cell and thus does not reliably distinguish current gray fog from revealed terrain. Preserve the existing gameplay assertions and `PageVerificationContractTest`.
6. Before implementation acceptance, apply the shared Java formatter, run all model/JUnit tests, the targeted Docker/Xvfb selection above with visual inspection at 1×/2× scale, then the fixed smoke selection within 420 seconds. Follow the [local acceptance policy](../publishing.md#local-acceptance-policy), including documentation checks and strict MkDocs. This is a future verification plan, not passing game evidence.
7. Current result: source analysis and proposed correction only. No executable code, test, asset or game behavior changed. Documentation validation is recorded in the [publishing evidence](../publishing.md#r-0318-unknown-preview-analysis-2026-10-27); remote CI and publication remain independently verified only when requested.
