6. Related areas: A02 start/profile decisions; A03 shared labels and controls; A04 save/continue.

## 1. Summary

Let a new player start an ordinary game directly from the main menu. This is the
first small part of the [ordinary-game goal](../implementation-plan.md#cil-bezne-nove-hry),
not completion of the whole expedition or setup system.

Static source inspection on 2026-10-12 at
[`4b3a1b56`](https://github.com/jajir/microcol/commit/4b3a1b567bd9e8c8ad8af1587d9849ecee02bead);
no new gameplay test was run while preparing this draft.
[ButtonsPanelPresenter.refresh](../../microcol-game/src/main/java/org/microcol/gui/screen/menu/ButtonsPanelPresenter.java)
requires a completed campaign before enabling free play.
[ApplicationController.startNewFreeGame](../../microcol-game/src/main/java/org/microcol/gui/dialog/ApplicationController.java)
already starts the free-play campaign; its
[mission factory](../../microcol-game/src/main/java/org/microcol/model/campaign/FreePlay_0_missionFactory.java)
uses empty mission goals.

Scope is availability of ordinary free play and its continuation through the
agreed menu path. The existing scenario is a proposed first baseline. Full map
generation, nation/difficulty selection and scenario rebalancing remain outside
this slice. The A01 foundation must settle how campaign and free-play entries
fit into the menu before this requirement is ready.

## 2. Behavior

From a fresh profile, the player can discover and activate the free-game entry.
It leads to the ordinary free-play map without completing or selecting a campaign
mission. The menu path, campaign placement and any setup/confirmation boundary
come from A01/A02. The current direct launch is an implementation option, not
an agreed final structure. Specify the exact player steps after that foundation
is settled; this requirement does not silently choose a setup wizard either.

Acceptance examples:

1. Fresh profile with no campaign progress → start free play → playable map,
   free-play mode and no campaign goals; ending one turn remains possible.
2. Profile with completed campaign → the same action → the same game mode.
3. Open the menu and leave without starting → no new game or progress is created.
4. Start, save and continue → the same world, player, date and stocks return;
   continuation does not require a campaign completion flag.

Reusing the default scenario is proposed, pending question 2. Passing this entry
check does not accept all national profiles, the entire UC-115 journey or the
unresolved calendar.

## 3. Implementation steps

1. Apply the agreed A01/A02 entry contract and make the player steps concrete.
   Keep menu availability in `gui.screen.menu`; reuse the existing controller
   and `model.campaign` free-play path. Review all callers of the menu refresh
   and launch action before removing the campaign prerequisite.
2. Extend [TC_12_F11_start_free_game](../../microcol-test/src/test/java/org/microcol/test/TC_12_F11_start_free_game.java)
   with a fresh-profile path and explicit mode/state verifications. Its present
   setup uses `scenarios-finished`; preserve completed-profile regression coverage
   and the existing TC/F IDs.
3. Exercise launch and save/continue through page objects with dedicated
   `verify...` methods. Use isolated test homes; do not modify a player's profile.
4. Run TC12 and the page verification contract in the
   [documented JavaFX environment](../functional-tests.md#spousteni-a-ochrana-publikace).
   Run the full functional suite for the shared menu change; update UC-115 entry
   evidence and follow normal documentation/build publication.

Verification: planned, not executed for this requirement.

## 4. Open questions

1. **Nonblocking presentation choice:** retain the current free-game label or
   align it with “New Game”? Use the terminology chosen in A01/A03; current
   menu conventions alone do not settle the future design.
2. **Scope decision for refinement:** accept the existing free-play scenario as
   the initial world baseline, independently of the menu path? Recommended:
   yes, with profile/calendar corrections tracked separately. Q-01/Q-02 remain
   blockers for broader rule acceptance, not for this menu entry. The entry
   path itself is decided through question 3.
3. **Blocking — navigation foundation:** define the A01 menu structure and
   A02 handoff before implementation: entry destination, direct start versus
   setup, back/cancel behavior and replacement of an active game. This is the
   prerequisite identified on 2026-10-13; the existing launch path is not
   evidence of an agreed final design. Preserve question numbers 1 and 2
   when recording the resulting decisions.
