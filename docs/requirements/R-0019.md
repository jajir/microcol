# R-0019 — Separate explored terrain from current unit visibility

1. Status: Draft
2. Updated: 2026-10-13
3. Related: P04; MAP-007/008, Q-11; UC-006 (Hra). See the [rule catalogue](../gap-analysis.md),
   [use cases](../use-cases.md) and [work packages](../implementation-plan.md#seznam-pracovnich-baliku).
4. Dependencies: [R-0014](R-0014.md) initial expedition; existing Visibility state.
5. Primary area: [A05](areas.md#a05).
6. Related areas: A03 map/report disclosure; A08 opponent knowledge.

## 1. Summary

1. Exploration must preserve known terrain while preventing the player from learning the current state of unseen rivals.

2. The catalogue marks permanent terrain discovery as implemented, but initial radius is derived from movement speed and enemy-unit visibility is not established by that match.

3. Initial sight and current visibility for on-map units, with persistent explored terrain. Lost cities, native intelligence and full terrain-table completion remain separate.

## 2. Behavior

Proposed acceptance for individual refinement; capture does not approve implementation.

1. A new reference game reveals only the agreed surroundings of the expedition. Distant rival units and undiscovered colonies do not leak through map labels, tooltips or reports.

2. Moving a unit reveals terrain within the accepted Q-11 radius. Leaving that region preserves terrain knowledge but no longer exposes live enemy movement outside current sight.

3. Own unit visibility and currently observable enemy information are queried from the model by both GUI and AI; movement speed alone does not define an accepted sight rule.

4. Save/load preserves explored terrain and reconstructs or restores current sight consistently without revealing extra cells.

5. Changing or removing a sight source updates visible information immediately; opening another screen or cancelling a movement preview reveals nothing new.

## 3. Implementation steps

1. Inspect `model.Visibility`, `AbstractUnit.getVisibleLocations`, map rendering and AI target discovery. Define separate model queries for explored and currently observable information.

2. Resolve Q-11 sight values for supported units and integrate updates on movement, ownership and removal. Persist only the agreed knowledge state and avoid GUI dependencies.

3. Proposed `TC_free_play_visibility_test`: fresh start, explore/leave, unseen rival movement, removed scout and round-trip. Model tests compare both players and map edges; UI tests inspect labels/reports as well as tiles.
