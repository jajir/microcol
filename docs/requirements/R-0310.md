## 1. Summary

1. A player starting Free game → Original world should be able to move the initially focused galleon immediately.
2. Confirmed on 2026-10-27 at `afc916327ea4e7f6a4b5d02bce4c1c66044e6ece`: `M` followed by a destination click and mouse dragging both leave the galleon at its starting tile. Both control scenarios pass after clicking an adjacent empty tile and then the ship; see the linked evidence.
3. This request authorizes reproduction and regression tests, without repairing gameplay code. Results belong in the [functional evidence](../functional-tests.md#r-0310-initial-free-play-movement-2026-10-27).

## 2. Behavior

1. Start a fresh Original world from the real Free game menu using default setup. Initial focus is on the galleon at `(45, 15)`.
2. Without reselecting a tile or unit, press `M` and click adjacent sea tile `(44, 15)`. The same galleon arrives there and leaves its original tile empty.
3. In a separate fresh game, drag the initially focused galleon from `(45, 15)` to `(44, 15)`. Movement succeeds without an earlier click elsewhere.
4. Control scenarios repeat each action after clicking empty tile `(45, 14)` and then the ship. Preserve the world, destination and command.
5. No turn advance, model mutation, loaded replacement world or direct selection injection may prepare these scenarios. Save compatibility and other maps are outside this reproduction.

## 3. Implementation steps

1. Reuse `WelcomePage`, `FreePlaySetupPage`, `GamePage` and `FreePlayAuditPage`, the F15 fixture and `@Start` convention. Enter the actual bundled world through the menu. Expose the existing `GamePage.dragToLocation` action so new mouse scenarios check the ship's resulting location without first asserting hover/status feedback; preserve all existing helper assertions.
2. Add `TC_193_F15_initial_ship_movement_test`: `TC_01` covers `M`, `TC_02` covers dragging, and `TC_03`/`TC_04` are reselection controls. Require successful movement; do not invert assertions to accept the defect or disable failing cases.
3. Apply the shared formatter, run the model phase, then the four Docker/Xvfb scenarios and `PageVerificationContractTest`. Record actual outcomes and unchanged production revision in the linked evidence.
4. Preserve reproduction in an isolated worktree. Expected regression failures block integration of the test or gameplay changes. The user authorized documentation-only publication on 2026-10-27; the tests remain isolated and uncommitted. Gameplay repair and complete acceptance remain a separate user-selected step.
