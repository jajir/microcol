# R-0021 — Depart through sea lanes and return to the recorded coast

1. Status: Refining
2. Updated: 2026-10-13
3. Related: P09; CARGO-011/013/015, Q-11; UC-027 (Hra). See the [rule catalogue](../gap-analysis.md),
   [use cases](../use-cases.md) and [work packages](../implementation-plan.md#seznam-pracovnich-baliku).
4. Dependencies: [R-0002](R-0002.md) turn boundary; existing voyage duration and carrier persistence.
5. Primary area: [A06](areas.md#a06).
6. Related areas: A05 map movement; A04 transit continuation; A03 voyage status.

## 1. Summary

1. Make the Atlantic departure trigger and return location predictable on both sides of the map.

2. The catalogue records immediate transit on entering HIGH_SEA, and random eastern return rather than the original departure square. Existing carrier cargo is preserved during transit.

3. Outward departure, stored origin and safe return. Variable weather/speed durations (CARGO-012), reversal (CARGO-014) and Magellan remain separate; retain current timing visibly as provisional until Q-11 settles it.

## 2. Behavior

Target behavior for later implementation. The audit below separates existing
capability from missing steps; it does not accept these complete targets.

1. Entering or moving along a sea-lane cell keeps the ship on the map. Moving outward at the corresponding east/west edge starts exactly one voyage.

2. Record the departure sea-lane square and direction. The Europe screen displays transit state and remaining turns without allowing simultaneous map actions.

3. A return from Europe uses that recorded coast and square, subject to the agreed occupied-arrival policy. Never silently send a western departure to a random eastern location.

4. Goods and passengers keep their identity and quantities. Each turn reduces remaining time once; loading mid-voyage does not restart the crossing.

5. Invalid outward movement or cancelled departure leaves location, cargo and action points unchanged. First departure from Europe with no recorded origin follows an explicit profile rule.

## 3. Implementation steps

1. Adjust shared movement/transit operations in `AbstractUnit`, `PlaceHighSea`, `HighSea` and `unit.Ship`; save the origin through `model.store`.

2. Update Europe/map callers and current fixtures, then integrate phase timing from R-0002. Preserve existing cargo handling instead of rebuilding it.

3. Proposed `TC_atlantic_departure_return_test`: east/west entry, travel along lane, outward departure, mixed cargo, blocked arrival and mid-voyage round-trip. Model checks ensure a ship has only one place.

4. TC23/TC_01 now exercises a real departure, mid-voyage Continue, Europe arrival, return drag and preserved cargo/passenger identity. Local Monocle hit a clipboard error before the full journey completed; native Linux verification is required before calling the round-trip verified. ## 4. Open questions

1. What happens when the recorded arrival square is blocked? Blocking: yes; resolve under Q-11. Proposed answer: wait in transit with a reason until a legal arrival is possible, rather than teleporting. Decision: unresolved.

2. Where does a newly purchased ship with no departure history first appear? Blocking: yes. Proposed answer: use an explicit legal arrival location from the reference profile. Decision: unresolved.
