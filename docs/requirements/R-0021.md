## 1. Summary

1. Make the Atlantic departure trigger and return location predictable on both sides of the map.

2. Baseline before R-0021: TC23/TC_01 sailed to Europe in three turns, resumed a saved voyage with two turns remaining, and returned in three turns with 7 ore and the same passenger carrying 80 tools. It observed immediate transit on entering HIGH_SEA and random eastern arrival. The current implementation changes those trigger/origin rules; acceptance evidence must establish the full replacement behavior.

3. Outward departure, stored origin and safe return. Variable weather/speed durations (CARGO-012), reversal (CARGO-014) and Magellan remain separate; retain current timing visibly as provisional until Q-11 settles it.

## 2. Behavior

Implementation is authorized by the active R-0019-and-later goal. The decisions
below use the original manual. Local and publication acceptance passed; see the delivery evidence in chapter 3.

1. Entering or moving along a sea-lane cell keeps the ship on the map. A subsequent eastward move from an eastern lane or westward move from a western lane starts exactly one voyage, recording the source lane square. The manual requires movement toward the edge, not reaching the outermost map column first. A north/south or inward move stays on the map.

2. Record the departure sea-lane square and direction. The Europe screen displays transit state and remaining turns without allowing simultaneous map actions.

3. A return from Europe uses that recorded coast and square, subject to the occupied-arrival policy in 4.1. Never silently send a western departure to a random eastern location.

4. Goods and passengers keep their identity and quantities. Each turn reduces remaining time once; loading mid-voyage does not restart the crossing.

5. Invalid outward movement or cancelled departure leaves location, cargo and action points unchanged. First departure from Europe with no recorded origin follows an explicit profile rule.

## 4. Open questions

1. Resolved on 2026-10-13 after consulting the [original manual](../Sid_Meiers_Colonization_manual.pdf), printed page 60 (PDF page 66): return uses the sea-lane square of departure. The passage does not specify blocked arrivals. Explicit MicroCol policy: an enemy occupant blocks arrival; friendly stacking follows current model movement rules. Keep the ship, passengers and goods in transit with zero remaining turns and a visible waiting reason, then retry once on its next owner turn. Do not relocate to another square or decrement below zero.

2. Resolved implementation policy on 2026-10-13: a ship without prior departure uses the default eastern arrival for the selected reference map. Choose an eastern sea-lane square adjacent to ordinary ocean, nearest the vertical map centre; break ties by row and then column. Fix and persist this choice when beginning the first return voyage so a later load or occupant cannot select a different coast. An occupied destination follows 4.1. A map with no such legal terrain must reject departure before mutation and explain why. The consulted passage does not specify where newly purchased ships first arrive; this deterministic rule is MicroCol policy, not a historical claim. No new user setting is required.

3. Resolved trigger wording from printed pages 17 and 60 (PDF pages 23 and 66): entering a lane and then moving toward its corresponding map edge are separate actions. The source lane square, rather than the outward target square, is the recorded origin. Retain current provisional voyage timing; the manual describes variable one-to-four-turn crossings but does not supply an exact weather/navigation formula for Q-11.
