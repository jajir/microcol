## 1. Summary

1. Refine the spacing of the two voyage groups in Europe after R-0380. Move them slightly downward so their headings sit clearly below the horizon, and bring each ship row closer to its heading.
2. Use the selected [variant C](../graphics-assets/europe-voyage-spacing-2026-10-31/variant-c.png), the most compact of the three proposals. It is an ImageGen design reference, not a pixel-exact specification or a screenshot of implemented behavior.

## 2. Behavior

1. Apply the same vertical placement and compact heading-to-row spacing to both “Sailing to Europe” and “Sailing to New World”, including when either list is empty. The groups sit a little lower than the current R-0380 layout; avoid a large relocation within the harbor.
2. Leave a small, clearly visible gap between the heading and the ship selection frame, matching variant C. Text, ship artwork and selection/focus frames must not touch or overlap. Use the same layout in English and Czech.
3. Keep the headings' existing shared font and size, plain appearance without ribbons, and centered alignment. Preserve the ships' 45-pixel image size, horizontal scrolling, selection, voyage identity and remaining-turn information.
4. Keep the hand-drawn routes visually connected to the voyage rows when adjusting their upper portions. Their dock endpoints, the departure button, harbor palette, town, quay, cargo, goods and toolbar retain the R-0380 design. Red review rectangles are not UI.
5. This is a layout refinement only. Boarding, button/drag departure, travel orders, timing, cargo and other player actions retain their existing prerequisites and outcomes. No new action or confirmation is introduced.

## 3. Implementation steps

1. When selected for implementation, adjust the shared voyage layout in `EuropePanel` and `PanelHighSeas`, reusing the existing styles and controls. Tune the downward offset and row spacing against the saved reference at supported window sizes; exact pixel values are routine implementation calibration, not an unresolved gameplay decision.
2. Adjust route positioning only as needed for alignment, preserving genuine SVG sources and derived exports if artwork changes. Ownership stays in the existing GUI components under the [architecture contract](../architecture.md).
3. Retain `TC_194_F226_europe_harbor_test` gameplay and scrolling assertions. Extend its layout verification for the smaller gap, matching group placement and no heading/frame overlap in both languages and narrow/wide windows. Future implementation follows the normal [local acceptance policy](../publishing.md#local-acceptance-policy); this capture's no-tests exception does not waive those future checks.
4. Current scope is documentation and a saved design reference only. No executable files or runtime assets changed. All tests, documentation consistency checks and strict MkDocs are omitted at the user's explicit request for this push; see the [capture record](../publishing.md#r-0381-voyage-spacing-reference-2026-10-31).
