## 1. Summary

1. Introduce a shared bilateral relation state so peace and war have actual consequences for human and computer decisions.

2. The catalogue records no diplomatic relationships in `PlayerPo`; `UnitStorage` treats nonowners as enemies and AI lacks a treaty gate.

3. European peace/war state, legal transitions and shared queries. Negotiation dialogue, alliances, privateer exceptions and native attitudes require separate refinement.

## 2. Behavior

Proposed acceptance for individual refinement; capture does not approve implementation.

1. Each distinct pair of European colonizing players has one consistent relation based on stable identity, not display name. Initial relations are explicit scenario data.

2. Display the relation only where the player may know it. Renaming a player never changes war state, unit ownership or another pair’s relationship.

3. A declared hostilities operation changes only the intended pair; an accepted peace transition ends that pair’s war. Invalid/self transitions reject without changes.

4. Routine AI target selection respects peace. A human treaty-breaking attack must use an explicit confirmed transition; R-0028 owns the attack execution integration.

5. Save/load retains each relation. Replaying or opening a relation report does not declare war again.

## 3. Implementation steps

1. Add model-owned pair state and transition/query operations through existing player/store structures, with no AI/GUI dependency.

2. Update callers that equate every nonowner with a hostile target. Provide a minimal relation readout; reserve negotiation offers and privateer behavior for later analyses.

3. Proposed `TC_european_relations_test`: two rivals, confirmed hostilities, relation readout and reload. Model tests cover symmetry, three-player isolation, identity rename and invalid transition; AI tests reject peacetime routine attacks.
