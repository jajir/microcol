## 1. Summary

Make the first turn-sequence slice explicit: Europe, colony processing and unit
actions, with one calendar update after the last player. This carries forward
Z03; it does not introduce all nations, native AI or a complete economy rewrite.
The [turn-rule catalogue](../gap-analysis.md#setup-and-turn-sequence) cites
the manual's printed page 10 / PDF 16 for phases and national order; internal
colony calculation details remain in Q-10.

Static source inspection on 2026-10-12 at
[`4b3a1b56`](https://github.com/jajir/microcol/commit/4b3a1b567bd9e8c8ad8af1587d9849ecee02bead);
no new gameplay test was run while preparing this draft.
[Player.startTurn](../../microcol-game/src/main/java/org/microcol/model/Player.java)
currently processes units, colonies and then periodic immigration.
[GameManager](../../microcol-game/src/main/java/org/microcol/model/GameManager.java)
iterates the stored player list and already advances the calendar after the last
player. Its `continueGame` sends lifecycle events without calling `Player.startTurn`;
there is no observed claim here that loading currently duplicates production.
[Calendar](../../microcol-game/src/main/java/org/microcol/model/Calendar.java)
switches from yearly advances to four seasons at 1600.

## 2. Behavior

On an agreed small available-player fixture, a new player's turn processes the
available Europe effects, colony effects and unit activation in that order.
Each effect runs once. The player uses the ordinary end-turn control and sees
the resulting date, stocks and reports in free play.

Acceptance examples:

1. End a nonfinal player's turn → next player becomes active; date is unchanged.
2. End the final player's turn → one agreed calendar step, one new round and one
   start-of-turn processing for the next player.
3. Record phase events → Europe precedes colony processing, which precedes unit
   activation; exact internal colony production order is a separate Q-10 issue.
4. Save during manual unit actions, reload and continue → same active player,
   date, stocks and units; neither production nor immigration is replayed.
5. Invalid end-turn request by an inactive player → rejection without changing
   player, date or inventories. An already completed transition cannot run twice.

Use the current available players for this slice. Complete national ordering
still depends on P02/P18; this file does not close TURN-001 in full.
No cancellation is invented for already committed automatic turn effects.

## 3. Implementation steps

1. Resolve Q-02 for the test baseline and define the persisted continuation
   boundary before changing behavior. Inspect `GameManager`, `Player`, `Calendar`,
   their UI/AI callers and `model.store` together.
2. Keep phase ordering in the model. Reuse existing operations and lifecycle
   events; adapt consumers only where ordering changes. Save/load must preserve
   the chosen boundary without running gameplay effects during file opening.
3. Add focused `GameManagerTest` and `PlayerTurnTest` cases (proposed names);
   retain `CalendarTest`, `CalendarStoreTest`, `CalendarSeasonTest` and
   `CalendarSeasonsTest`.
4. Add proposed `TC_21_F15_turn_sequence_test` with a dedicated F15 fixture:
   normal end turn, date transition and save/continue through the real controls.
   Verify date, active player, stocks and one-time reports explicitly.
5. Run the model tests and full native functional suite using the
   [test contract](../functional-tests.md#spousteni-a-ochrana-publikace).
   Update the affected UC slices and recorded phase/continuation evidence.
