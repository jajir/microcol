## 1. Summary

1. Prevent an unarmed colonist or stale attack command from initiating a battle while making intentional treaty-breaking explicit.

2. COMBAT-001 already has adjacency/terrain checks. COMBAT-003 records that colonist type eligibility ignores muskets, allowing an unarmed foot colonist to attack.

3. Eligibility for currently supported roles and European hostility transition. Strength calculation belongs to R-0029; new unit types, capture and privateer exceptions remain separate.

## 2. Behavior

Proposed acceptance for individual refinement; capture does not approve implementation.

1. Show an attack only when role/equipment, owner, distance, terrain, remaining movement and target permit it. Unarmed foot colonists and cargo-only carriers cannot initiate attacks.

2. For a peaceful European target, show that the proposed attack declares war; cancelling changes neither relation nor movement nor units.

3. On confirmation, revalidate all preconditions before changing the relation or consuming movement. A moved target or removed weapon rejects with no partial declaration.

4. A successful valid initiation invokes existing combat resolution and exhausts the surviving attacker’s movement. No second attack or movement is available that turn.

5. AI uses the same legality checks and explicit relation policy. Save/load preserves resulting relations and movement, without repeating combat.

## 3. Implementation steps

1. Refine shared attack queries/commands in `model.AbstractUnit` and role data; connect the R-0026 relation transition as part of one validated operation.

2. Update game controller/dialog and AI callers without embedding separate permission formulas. Keep current outcome algorithm until independently changed.

3. Proposed `TC_attack_eligibility_test`: armed/unarmed, peace-confirm/cancel, stale target, no movement and reload. Model tests assert every rejected command preserves all involved state; retain existing combat scenarios.
