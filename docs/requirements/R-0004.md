# R-0004 — Restrict ship entry to valid coastal colonies

1. Status: Draft
2. Updated: 2026-10-13
3. Related: P06; MOVE-001/002;
   [UC-011, Hra](../use-cases.md#pohyb-a-rozkazy), ship terrain/port variants.
4. Dependencies: agreed coastal eligibility definition; existing movement operation.

## 1. Summary

Allow a ship into an owned coastal settlement but prevent it from sailing through
colonies into inland land tiles. Keep legal movement and passenger handling intact.

Static source inspection on 2026-10-12 at
[`4b3a1b56`](https://github.com/jajir/microcol/commit/4b3a1b567bd9e8c8ad8af1587d9849ecee02bead);
no new gameplay test was run while preparing this draft.
[AbstractUnit.isPossibleToGoToPort](../../microcol-game/src/main/java/org/microcol/model/AbstractUnit.java)
accepts any owned colony. It does not check whether it is coastal.
[GamePanelPresenter](../../microcol-game/src/main/java/org/microcol/gui/screen/game/gamepanel/GamePanelPresenter.java)
also uses that predicate. A loaded/scripted adjacent-colony world can expose the
hole; normal founding currently prevents adjacent colonies.

Terrain movement prices, Atlantic connectivity rules beyond the agreed coastal
definition, colony spacing and a general save-file audit are outside this slice.

## 2. Behavior

Movement preview and execution use the same model definition of a valid port.
The player can move from water to an eligible own coastal colony and back.
An inland colony does not make an otherwise illegal land step legal.

Acceptance examples:

1. Water → own valid coastal colony → movement succeeds, with normal current
   movement charge and unchanged cargo/passenger identities.
2. Coastal colony → adjacent inland colony in a dedicated regression fixture →
   rejected; ship position, remaining movement and cargo are unchanged.
3. Empty ship, or an explicit ship-movement command, from water → land without
   an eligible port → rejected with no mutation. A loaded ship's existing
   passenger-disembark action remains available; it is not a ship land move.
4. Legal adjacent/diagonal water moves and map-edge rejection remain correct.
5. Save/reload around legal port entry preserves location and passengers;
   an invalid requested move never rewrites a save or relocates the ship.

The UI excludes forbidden ship moves and handles a destination becoming invalid
before execution, while preserving legal passenger landing. Combat against
foreign settlements remains outside this rule.

## 3. Implementation steps

1. Specify coast examples, then inspect callers of the shared port predicate,
   `Model.moveUnit`, pathfinding, range display and AI movement.
2. Fix eligibility in the model and reuse it from GUI/AI. Preserve pre-mutation
   movement validation and existing legal movement costs.
3. Add focused ship model tests for coastal/inland/boundary conditions. Retain
   [TC_01_F01_embark_disembark_test](../../microcol-test/src/test/java/org/microcol/test/TC_01_F01_embark_disembark_test.java),
   [TC_13_F12_arriving_to_colony_test](../../microcol-test/src/test/java/org/microcol/test/TC_13_F12_arriving_to_colony_test.java)
   and [TC_16_F12_arriving_to_colony_test](../../microcol-test/src/test/java/org/microcol/test/TC_16_F12_arriving_to_colony_test.java).
4. Add proposed `TC_22_F16_coastal_port_entry_test` and an explicit F16
   loaded-world regression fixture. Do not weaken or rewrite F12's valid arrival
   and passenger expectations.
5. Run model movement tests, those TC scenarios and the full functional suite
   for shared movement using the [test contract](../functional-tests.md#spousteni-a-ochrana-publikace).
   Record the narrow MOVE-002/UC-011 evidence.

Verification: planned, not executed for this requirement.

## 4. Open questions

1. **Blocking:** what makes a colony coastal: orthogonal or eight-direction water
   adjacency, and does an isolated lake qualify? Write exact map examples before
   implementing. The catalogue does not settle these details; do not silently
   require an ocean path or invent a new connectivity subsystem.
2. **Nonblocking scope limit:** existing loaded worlds may contain adjacent
   colonies. Use one for regression without changing ordinary founding spacing.
   General validation of those worlds is a separate requirement.
