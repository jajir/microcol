# R-0231 — Preserve local diagnostics for recoverable failures

1. Status: new
2. Updated: 2026-10-17
3. Related: P32/P31; [diagnostics estimate](../implementation-estimate.md#release-engineering-and-upkeep), [save recovery](../gap-analysis.md#recovery-and-presentation).
4. Dependencies: existing logging and save rejection [R-0067](done/R-0067.md), turn-preparation recovery [R-0052](done/R-0052.md), package identity [R-0233](R-0233.md).
5. Primary area: [A04](areas.md#a04).
6. Related areas: A01 startup/exit, A03 actionable feedback, P32 distribution.
7. Origin: release diagnostics residual beyond delivered validation and recovery; no cloud telemetry is requested.

## 1. Summary

1. When startup, local I/O or an unexpected operation fails, a player gets a usable next step and a local diagnostic record that supports reproduction.
2. Existing save rejection and turn-preparation recovery stay with R-0067/R-0052; this requirement owns shared release diagnostic capture and exposure.

## 2. Behavior

1. A failure report identifies game/build version, platform/runtime, time, operation and safe error context in a bounded persistent local log. The player can locate that log and learn whether retry, Continue, backup restore or reporting is appropriate; ordinary saved games remain unchanged merely by opening them.
2. Missing/unwritable log location or a logging failure does not overwrite a valid save or hide the original error. Sensitive local paths and player-entered content are handled deliberately in any shareable summary.
3. Test startup and selected recoverable save/resource failures, log rotation/retention and reportability on packaged runtimes. Current source logging and existing expected-error dialogs are credited; only observed residual gaps are repaired.

## 3. Implementation steps

1. Recheck current logging/error paths on the release candidate, then add only missing file sink, version context and player guidance through application/GUI owners. Preserve model validation and expected rejection semantics.
2. Current result: captured diagnostic acceptance; historical console-only evidence in the estimate is not a verified current defect.

## 4. Open questions

1. What default retention/size and redaction policy should apply to player-shareable local diagnostics? The release estimate does not fix these values.
