# R-0376 — Remove the separate Recovery points entry from the main menu

1. Status: new
2. Updated: 2026-10-31
3. Related: P28 navigation and P26 persistence in the [implementation plan](../implementation-plan.md#prurezova-prace-pro-kazdou-etapu); SUPPORT-001 and UC-113 (Hra) in the [use cases](../use-cases.md).
4. Dependencies: [R-0298](done/R-0298.md) shared saved-game browser; [R-0068](done/R-0068.md) existing recovery checkpoints.
5. Primary area: [A01](areas.md#a01).
6. Related areas: A04 retains checkpoint creation and restoration; A03 retains localized labels and keyboard navigation.
7. Origin: user request on 2026-10-31 to capture removal after confirming that Recovery points duplicates Load game with a preset filter; implementation was not requested.

## 1. Summary

1. Players should have one main-menu entry for choosing a saved game, without a separate Recovery points shortcut to the same browser.
2. Source inspection on 2026-10-31 at `97f8463e` found that Load game and Recovery points open the shared saved-game browser with different initial filters. See the [current navigation contract](../save-load-navigation.md).
3. Remove only the separate main-menu entry. Keep the recovery saves, their automatic creation, the autosave setting, the browser's Recovery points filter and Continue behavior.

## 2. Behavior

1. Opening the main menu in English or Czech shows Load game / Načíst hru and no separate Recovery points / Body obnovy button. The remaining actions retain their relative order and remain reachable by keyboard.
2. Choosing Load game opens the existing saved-game browser with all save types available. Selecting its Recovery points filter shows the existing latest-position, latest-turn and previous-decade saves, including their actual saved metadata.
3. Choosing a recovery save restores it through the existing validation and leave-confirmation flow. Canceling returns without loading or changing files; an invalid save preserves the active game. An empty recovery filter retains the existing empty-state explanation.
4. Removing the shortcut does not delete or rewrite any saved game. Checkpoint timing, autosave on/off, manual and quick saves, and Continue retain their existing behavior.

During refinement, map the behavior to named scenarios in `TC_43_F34_recovery_points_test` and `TC_191_F224_session_menu_test`, including both languages, keyboard access, empty results and cancellation.
