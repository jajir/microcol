# R-0234 — Distribute a signed and notarized macOS release

1. Status: new
2. Updated: 2026-10-17
3. Related: P32; [distribution limits](../distribution.md#distribution-scope-and-remaining-release-work), [macOS release estimate](../implementation-estimate.md#platform-requirements-and-project-findings).
4. Dependencies: release runtime [R-0233](R-0233.md) and existing Mac development packages/launcher. The player guide [R-0232](R-0232.md) describes verified installation; stable promotion [R-0236](R-0236.md) consumes this gate.
5. Primary area: [A01](areas.md#a01).
6. Related areas: A03 JavaFX/audio launch, A04 save location; P32 release.
7. Origin: public Mac acceptance beyond the delivered ARM/Intel development artifacts; no second architecture is automatically mandated beyond the chosen support matrix.

## 1. Summary

1. A downloaded Mac release opens under the supported macOS security flow with its bundled runtime and declared architecture.
2. This requirement owns signing, notarization, packaging and clean-machine acceptance, not the existing development CI pipeline.

## 2. Behavior

1. Sign the app and nested runtime components with the correct identity/entitlements, notarize and staple the distributed artifact, and retain a verifiable build/signing record. A fresh downloaded copy launches through ordinary Finder/installer behavior on each chosen supported architecture.
2. Verify install, first start, graphics/audio, Save/Continue, exit/uninstall and upgrade from a previous stable candidate without deleting player save files. Whether an older schema loads is a separate stable-compatibility decision; a failed signature/notarization or Gatekeeper check blocks release even if local unsigned launch passed.
3. The package/version shown to players matches the promoted commit and guide. Keep credentials protected; no certificate material enters the repository.

## 3. Implementation steps

1. Choose supported Mac architecture/OS minima, configure signing/notarization for the existing packaging path, and run fresh download/launch checks plus representative functional scenarios.
2. Current result: captured public-release gate. The current [development package](../distribution.md) is not claimed to be a notarized public build.

## 4. Open questions

1. Which Mac architectures and OS versions will the first stable release support, and which publisher identity/certificate will sign it? The existing development ARM/Intel artifacts do not settle the public support claim.
