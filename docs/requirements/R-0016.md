# R-0016 — Define the free-play screen and information structure

1. Status: Draft
2. Updated: 2026-10-13
3. Related: P27, P28; SUPPORT-002/003/004; UC-114/UC-115 (Hra). See the [rule catalogue](../gap-analysis.md),
   [use cases](../use-cases.md) and [work packages](../implementation-plan.md#seznam-pracovnich-baliku).
4. Dependencies: [R-0012](R-0012.md) navigation; existing map, colony, Europe and turn-report screens.
5. Primary area: [A03](areas.md#a03).
6. Related areas: A05 map knowledge; A07 colony data; A06 Europe; A04 turn reports.

## 1. Summary

1. Give players a consistent route between the map, their colony, Europe and information needed to continue the economic loop.

2. `Screen` already includes GAME, COLONY, EUROPE, STATISTICS and TURN_REPORT. Their existence is not evidence that every manual advisor or the full ordinary-game journey is available.

3. Agree and implement a small information structure for these existing screens; leave new advisor systems, final artwork and detailed styling outside this slice.

## 2. Behavior

Proposed acceptance for individual refinement; capture does not approve implementation.

1. From the game map, expose the owned colony and Europe through recognizable controls; each destination shows its subject and a clear return action.

2. Returning from colony/Europe/report restores the relevant map context and valid selection. If the selected object no longer exists, use an agreed safe fallback rather than a stale reference.

3. Keep turn/year, treasury and active player unambiguous. Distinguish actual stock, projected production and a transaction preview using common terms.

4. A turn-report entry about an owned colony can navigate to that colony when it still exists; a historical entry never opens a different colony with the same name.

5. Reports and tooltips respect model visibility. Keyboard users can reach and leave each included screen, and closing a report does not repeat its gameplay effects.

## 3. Implementation steps

1. Map the included journeys in `gui.screen` and reuse the UX guidelines, stable colony IDs and existing model/turn-event data. Do not compute rule effects in presenters.

2. Define screen responsibilities and implement only missing navigation/context preservation for the agreed four-screen loop. Link shared wording and error behavior to R-0017.

3. Proposed `TC_free_play_screen_loop_test`: map→colony→map→Europe→map→report→colony, deleted report target and keyboard return. Inspect actual rendered screens and translated text at supported window sizes.
