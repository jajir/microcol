# R-0280 — Colony markers at the actual map scale

1. Status: new
2. Updated: 2026-10-25
3. Related: P05/P12/P28 in the [implementation plan](../implementation-plan.md), UC-006/UC-031/UC-047/UC-077 in [use cases](../use-cases.md), [visual brief](../graphics.md#soucasne-zadani-vzhledu).
4. Dependencies: existing colony population, owner and construction state; [R-0260](done/R-0260.md) visual agreement and [R-0277](done/R-0277.md) map treatment.
5. Primary area: [A03 — screens and shared UI language](areas.md#a03).
6. Related areas: A05 supplies map visibility and remembered observations; A07 supplies colony residents and construction state; A09 owns defense effects. This visual exploration changes none of those rules.
7. Origin: on 2026-10-25 the user requested ten colony-marker proposals with three population sizes, national flags, unboxed names and all fortification levels. They rejected large village illustrations and required comparison inside the supplied game screenshot at its actual tile size. They subsequently approved the compact direction, requested further experiments with one, two and three houses, and explicitly allowed slight overhang beyond the tile.

## 1. Summary

1. Replace the current bright square town picture with a compact pen-drawn colony marker that matches the shared map style.
2. Show size, ownership and fortification with a few readable strokes anchored to one map square, with slight visual overhang permitted. A large illustration reduced until its lines disappear does not meet this need.
3. This request authorizes visual exploration and analysis. The [proposal gallery](../graphics-colony-proposals.md) contains the original ten alternatives and three subsequent house arrangements A–C; no family or population thresholds have yet been selected for gameplay implementation.

## 2. Behavior

1. The colony name appears directly below the map marker without a plaque or box. A small national flag identifies its owner.
2. At least three population-size silhouettes are available. The proposals use one, two and three roofs; their numeric population thresholds remain undecided.
3. Each size supports four independent defense states: none, stockade, fort and fortress. Fortification must not be inferred from population alone, including after forced population loss.
4. The marker remains anchored to the existing 45 × 45 logical-pixel tile with a consistent visible pen stroke. The user's subsequent decision permits slight overhang of houses or fortification; the current proposal tries up to 4 px on either side without covering the colony name. This proposed numeric margin is not an agreed runtime limit. Names and adjacent important map markers must remain readable.
5. The comparison uses the supplied screenshot without changing its camera or map geometry. Haarlem is a labeled fictional placement used only to display the fourth defense state. Nothing is added to a saved game.
6. Eventual implementation must preserve selection, opening a colony, labels, visibility and remembered-colony information. Hidden growth or fortification changes must not leak through an old observation.

## 3. Implementation steps

1. The current [PaintService](../../microcol-game/src/main/java/org/microcol/gui/util/PaintService.java) uses one town image; the observed-colony overload accepts owner and name. Inspect both live and remembered drawing paths before implementation. `gui.image` owns artwork selection, while model owners retain population, construction and visibility rules.
2. Ten documentation-only vector families and their screenshot compositions are available in the [gallery](../graphics-colony-proposals.md). The original 120 size/defense combinations stay as historical alternatives. Follow-up A–C adds 36 combinations of one, two or three larger houses with all defense states, retaining the 1.35 px stroke while allowing modest horizontal overhang. These are proposals, not runtime assets or evidence that gameplay rendering changed.
3. After selection, refine population thresholds, visual treatment of remembered colonies, actual font placement and the affected player scenarios. Map tests to stable `TC_...` cases before implementation; preserve shared model operations and the functional-test contract.
4. For this analysis and its illustrations, run documentation consistency tests, strict MkDocs and visual/geometry checks. Implementation and gameplay acceptance remain unstarted.

## 4. Open questions

1. Which compact family and house arrangement should be developed further? Blocking for artwork implementation; the current request is the comparison. The permission for slight overhang is already agreed and does not need to be reopened.
2. At which resident counts should the small, medium and large silhouettes change? Blocking for runtime selection; construction minimum populations are not automatically these thresholds.
