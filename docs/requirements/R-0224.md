6. Related areas: A05 world/unit artwork, A07 buildings, A10 political views.

## 1. Summary

1. Each visible terrain, role, building, command and political state in the documented game has a suitable runtime visual or a deliberate readable fallback.
2. The accepted style is the [shared visual manual updated on 2026-10-24](../graphics.md#minimalisticky-graficky-manual); runtime coverage applies it to selected assets without a wholesale replacement of unrelated art.

## 2. Behavior

1. Build a coverage ledger for actually used states, including atlas aliases, variants and fallback. Verify missing or duplicated symbols in the current build instead of treating the 2026-10-11 inventory as current proof. Correct absent or misleading visuals while preserving the related action/result.
2. Inspect map and UI at actual sizes, small commodity icons, coast rotations, transparent overlays, relevant window sizes and localized text. States are distinguishable against their backgrounds and without color alone where meaning is critical. Compare nominal stroke widths by role at final UI sizes and basic/HiDPI scales; small variants must not lose strokes or merge essential details.
3. Each changed visual retains its source, export, resource and consumer trace; relevant functional `TC_...` outcomes still pass. Unused historical assets do not become mandatory new art merely because they exist in the catalogue.

This focused change does not close the broader audit.

## 3. Implementation steps

1. Reconcile the [graphics inventory](../graphics.md) against current source/consumers, inspect rendered screens, then update only missing/incorrect assets and mappings. Use the shared [export-to-screen checks](../graphics.md#export-a-kontrola-vysledne-velikosti) and run affected [visual and gameplay checks](../functional-tests.md).
2. Current result: captured coverage scope; old source counts and suspected alias gaps require revalidation before implementation.
3. Align the existing checks and shared model/AI/UI integration with the linked 2026-10-20 decisions; retain unresolved questions only with their rule owners and run UI regression in CI under the current user instruction.
4. Compare selected runtime assets with the [stored palette reference](../graphics.md#vychozi-paleta) and calibrate their final-size strokes beside the default text. Record remaining old-style coverage accurately; this agreement alone neither replaces assets nor verifies a game-wide redesign.
5. Include the [map-grid reference and boundary rules](../graphics.md#mrizka-a-neprozkoumana-cast-mapy) when inspecting map coverage. Consume R-0261 rendering and visual evidence without treating a captured requirement as an implemented map redesign.
6. Coordinate selected main-screen asset corrections with R-0262 layout and final-size comparison; keep the broader inventory and unrelated screen redesign outside that focused delivery.

7. Reuse the three-row terrain atlas, seeded decoration and recoloured coast masks from [R-0277](done/R-0277.md); check their documented export and visible-size evidence instead of restoring the former repeated tile artwork.
